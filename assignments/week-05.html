CSC 500 — Practice Assignments

Week 5: Arrays and Strings

There are 50 assignments, with exactly 10 assignments at each difficulty level.

Unless an assignment says otherwise:

  • use Java;
  • write methods for computational tasks rather than putting all logic in main;
  • do not use concepts substantially beyond Week 5 to replace the requested algorithm;
  • consider empty sequences and boundary cases where relevant;
  • test your solution with multiple inputs, not just one example.

Assignment 50 — Sequence Analysis Toolkit Difficulty 5/5integrated arrays and stringsmethodsreferencessearchingaggregationnullStringBuilderboundary cases

Create a small Java sequence-analysis toolkit.

The program receives two parallel arrays:

String[] labels;
int[] values;

Each index represents one labeled measurement.

Some labels may be null.

Implement separate methods that:

  1. return an independent copy of the numeric array;
  2. calculate the total of all numeric values;
  3. return the index of the smallest numeric value;
  4. count how many values are above a caller-supplied threshold;
  5. return the first index whose non-null label matches a target ignoring case;
  6. count neighboring numeric pairs whose difference exceeds a supplied amount;
  7. create a new String[] containing only non-null labels;
  8. build a multi-line report with StringBuilder, showing each valid label beside its corresponding value.

Requirements:

  • computation should be separated from display where practical;
  • do not accidentally alias the numeric array when an independent copy is required;
  • safely handle null labels;
  • use .equals() or .equalsIgnoreCase() rather than == for string contents;
  • use correct index boundaries for every traversal;
  • document what each method does with empty arrays;
  • assume the two parallel input arrays have equal lengths.

Finally, answer these design questions in comments:

  1. Which methods require indices, and which could use enhanced for loops?
  2. Which methods use the accumulator, counting, searching, filtering, or neighboring-element patterns?
  3. Which returned arrays are new objects?
  4. Where could aliasing cause a bug?
  5. Which boundary cases did you explicitly test?
  6. How does processing the String[] resemble processing the int[] even though element access and comparison differ?
