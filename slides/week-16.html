Polymorphism: an Interface

Suppose we define:


public interface Shape {
    double area();
}

Two classes implement the interface.

The interface says what: every Shape can report an area. It says nothing about how any particular shape computes it.
The complete Shape example

Suppose we define an interface Shape with a single method, double area. Two classes implement the interface.

The interface is a contract with no implementation in it at all. It fixes what a Shape can be asked to do, and leaves entirely open how each shape does it.

Two Implementations


public class Circle implements Shape {

    private double radius;

    public Circle(double radius) {
        this.radius = radius;
    }

    @Override
    public double area() {
        return Math.PI * radius * radius;
    }
}


public class Rectangle implements Shape {

    private double width;
    private double height;

    public Rectangle(double width, double height) {
        this.width = width;
        this.height = height;
    }

    @Override
    public double area() {
        return width * height;
    }
}
What the two classes actually share

Circle stores one field and uses Math.PI; Rectangle stores two fields and multiplies them. They share no field, no constructor shape and no formula.

What they share is the interface: both are declared implements Shape and both provide public double area(). That single shared promise is the whole basis on which the loop on the next slide can treat them identically.

Circle stores a radius and computes pi times radius squared. Rectangle stores a width and a height and computes their product.

The two classes share no fields, no formula and no internal representation. What they share is the promise made by the interface: ask either of them for an area and you will get a double.

Linked List

Why that one difference changes everything

An array's speed at indexing comes from consecutive memory: element i is a fixed distance from element zero. A linked list gives that up, so it cannot jump to position i — it must walk.

In exchange, inserting in the middle costs no shifting: you rewire two references. That is the trade the two structures make, and it is why "which one is better" is never answerable without knowing the operations.

A linked list stores elements in nodes: Alice points to Bob, Bob points to Carlos, and Carlos points to null. Each node contains data and a reference to the next node.

Approach 2: Use a HashSet


public static boolean containsDuplicate(int[] values) {

    HashSet<Integer> seen = new HashSet<>();

    for (int value : values) {

        if (seen.contains(value)) {
            return true;
        }

        seen.add(value);
    }

    return false;
}

Key Takeaways

  • Programming is not primarily about memorizing syntax.
  • Ask what problem you are solving, and what information must be represented.
  • Choose the abstraction and the data structure from the operations, not from habit.
  • Data-structure choices influence algorithm performance.
  • Correctness first, then clarity, then efficiency.
  • Read, trace and debug unfamiliar code systematically rather than by guessing.
  • Programming techniques exist to divide complexity into manageable pieces.
  • The specific technologies may change; the reasoning skills will not.
