Searching an Array

Suppose we want to determine whether the number 42 occurs in an array.


int[] values = {15, 7, 42, 19, 8};

boolean found = false;

for (int i = 0; i < values.length; i++) {
    if (values[i] == 42) {
        found = true;
    }
}

This is a simple form of linear search. We examine elements one at a time.

A better version stops after the value is found:


boolean found = false;

for (int i = 0; i < values.length && !found; i++) {
    if (values[i] == 42) {
        found = true;
    }
}

Or:


for (int i = 0; i < values.length; i++) {
    if (values[i] == 42) {
        found = true;
        break;
    }
}
Linear search — all three versions

To determine whether 42 occurs in an array, set a boolean to false and loop, setting it to true when the value is seen. This is a simple form of linear search: we examine elements one at a time.

The first version keeps looking even after it has found what it wants. Two better versions stop early — one folds !found into the loop condition, the other uses break. We will formally study searching algorithms later in the course.

For now, notice an important idea: once data is stored in a collection, we can develop algorithms for processing that collection.

Java provides another loop for processing array elements. Read for (int score : scores) as "for each integer score in scores". This is often called an enhanced for loop or a for-each loop.

It is convenient when we need the values but do not need their indexes. The accumulator example is the clearest case: summing the scores never needs to know where a score sits.

Regular for vs. Enhanced for

Use a regular for loop when:

  • you need the index
  • you need to modify array positions
  • you need to compare neighboring elements
  • you need to process only part of an array

Example:


for (int i = 0; i < scores.length; i++) {
    scores[i] += 5;
}

Use an enhanced for loop when you simply want each value:


for (int score : scores) {
    System.out.println(score);
}

A common mistake is:

Does nothing 

for (int score : scores) {
    score += 5;
}
Common errorThis does not modify the array.
Why the enhanced loop cannot modify the array

The variable score receives a copy of each integer value. The original array remains unchanged. score is a new int variable created for each iteration and initialised from the array element; assigning to it changes the copy, not the storage location inside the array. To change the array you must name a position — and naming a position requires an index, which is why the regular for is the fix.

Note the contrast with Part VII: an array passed to a method can be modified by that method, because the array itself is not copied. Here it is an individual int element that is copied, not the array.

"Compare neighboring elements" is exactly what the isSorted challenge in Part XII needs — and it is why that method uses a regular for.

Use a regular for loop when you need the index, when you need to modify array positions, when you need to compare neighboring elements, or when you need to process only part of an array.

Use an enhanced for loop when you simply want each value. The four bullets are a checklist students can apply directly: if none of them is true, the enhanced loop is shorter and clearer.

A common mistake is writing score += 5; inside an enhanced for loop and expecting the array to change. This does not modify the array. The variable score receives a copy of each integer value, so if you want to modify array positions you need the index, and therefore the regular for loop.

Part VI

Arrays and Methods

Arrays make it possible for many methods to operate on the same collection of data.

Arrays as Method Parameters

Arrays can be passed to methods. Example:


public static int sum(int[] values) {
    int total = 0;

    for (int value : values) {
        total += value;
    }

    return total;
}

We can call:


int[] numbers = {5, 10, 15};

int result = sum(numbers);

System.out.println(result);

Output:


30

The parameter type is:


int[]

because the method expects an array of integers.

Arrays in and out of methods

Arrays can be passed to methods. The sum method declares a parameter of type int[] because the method expects an array of integers, and uses an enhanced for loop because it only needs the values.

Calling sum(numbers) on the array 5, 10, 15 returns 30. This is Week 4's decomposition idea meeting Week 5's collections: the method knows nothing about where its array came from or how long it is, because values.length answers that at run time.

Example: Average Method


public static double average(double[] values) {
    double total = 0;

    for (double value : values) {
        total += value;
    }

    return total / values.length;
}

Usage:


double[] grades = {87.5, 90.0, 76.5, 93.0};

NoteNo cast is needed here: total is already a double, so total / values.length is floating-point division.

Key Takeaways

  • Arrays represent collections — one name plus an index instead of score1, score2, score3.
  • Loops and arrays naturally work together; the standard traversal runs from 0 to length - 1.
  • Many algorithms follow recurring patterns: traversal, accumulation, counting, searching, minimum/maximum, comparison.
  • Arrays are reference types — assignment can create aliases rather than copying the array.
  • Strings are sequences; text.charAt(i) plays the role of array[i].
  • Strings are objects and are immutable — operations return new strings.
  • Use .equals() to compare strings; == compares references.
  • These ideas prepare us for object-oriented programming.
