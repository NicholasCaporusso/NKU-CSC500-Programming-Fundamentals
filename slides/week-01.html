Part I

Problems, Algorithms, and Programs

A computer executes instructions according to precisely defined rules — and nothing else.

Programs as Precise Instructions

A computer does not understand:

  • what you intended,
  • what you probably meant,
  • whether your result makes sense,
  • or whether a particular instruction is a good idea.

It executes instructions according to precisely defined rules.

Calculate the average of three exam scores.

A human may immediately understand what to do. A computer needs a much more explicit procedure.

Key ideaThat explicit procedure is an example of an algorithm.
Programming: the process of expressing a solution to a problem in a form that a computer can execute.
The procedure a computer needs, spelled out
  1. Obtain the first score.
  2. Obtain the second score.
  3. Obtain the third score.
  4. Add the three scores.
  5. Divide the sum by 3.
  6. Display the result.

This sequence of steps is an example of an algorithm. Notice what the English sentence left implicit and the six steps supply: order, granularity, and the commitment that nothing is assumed.

A computer is extremely fast, but it is not intelligent in the way humans normally use that word. It does not understand what you intended, what you probably meant, whether your result makes sense, or whether a particular instruction is a good idea.

It executes instructions according to precisely defined rules. Programming is therefore the process of expressing a solution to a problem in a form that a computer can execute.

Consider the instruction: calculate the average of three exam scores. A human may immediately understand what to do. A computer needs a much more explicit procedure — six numbered steps, each of which does exactly one thing. This sequence of steps is an example of an algorithm.

Algorithms

Algorithm: a finite sequence of well-defined steps for solving a problem or performing a computation.

Area of a rectangle

  1. Obtain the width.
  2. Obtain the height.
  3. Multiply width by height.
  4. Report the result.
A = w × h

Algorithms exist independently of programming languages. We could implement the same algorithm in Java, Python, C++, or another language.

Algorithm: the method used to solve the problem.
Program: an implementation of that method in a programming language.

Problem→ Algorithm→ Program→ Execution→ Result
Algorithm vs. program, in full

An algorithm is a finite sequence of well-defined steps for solving a problem or performing a computation. Algorithms exist independently of programming languages.

For example, an algorithm for computing the area of a rectangle could be: obtain the width, obtain the height, multiply width by height, report the result. We might express the algorithm mathematically as A = w times h. We could implement the same algorithm in Java, Python, C++, or another language.

This distinction is important. The algorithm is the method used to solve the problem; the program is an implementation of that method in a programming language. Throughout CSC500 we will repeatedly move through the process problem, algorithm, program, execution, result.

Portability

One of Java's historical design goals is portability. The idea is approximately:

Compile Java source into a standard bytecode format, then run that bytecode using an appropriate JVM on each platform.

Therefore, Java bytecode can often run across operating systems without recompiling the source for each CPU architecture. This idea is sometimes summarized by the phrase:

Write once, run anywhere.
Is "write once, run anywhere" literally true?

In reality, platform differences still matter in some situations, but the JVM provides a useful level of abstraction between the Java program and the underlying machine.
