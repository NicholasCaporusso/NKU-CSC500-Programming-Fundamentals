Part I

Decisions, Boolean Values, and Comparison

A program evaluates a condition and chooses which code to execute.

Programs Need to Make Decisions

So far, the programs we have written execute statements sequentially. For example:


int x = 10;
int y = 20;
int sum = x + y;
System.out.println(sum);

Every statement executes in order.

Real programs are usually more interesting because they behave differently depending on the situation. For example:

  • If a student's grade is at least 60, display "Pass".
  • If the temperature is below freezing, display a warning.
  • If a password is incorrect, deny access.
  • If a bank account does not contain enough money, reject a withdrawal.
  • If a user is 18 or older, allow access to an adult-only feature.
Selection: the ability of a program to evaluate a condition and choose which code to execute. Also called branching or decision-making.

The if Statement and Its Alternatives

One branch, two branches, many branches — and why the order of the branches decides the answer.

The Basic if Statement

The syntax of an if statement is:


if (condition) {
    statements;
}

For example:


int temperature = 30;

if (temperature < 32) {
    System.out.println("Warning: freezing temperature.");
}

The program asks:


Is temperature < 32?
  • If the answer is true, the body executes.
  • If the answer is false, the body is skipped.
NoteThere is no semicolon after the closing parenthesis of the condition. The block that follows is the statement.

The syntax of an if statement is the keyword if, a condition in parentheses, and a block of statements in braces.

In the example, temperature is 30, so the program asks: is temperature less than 32? If the answer is true, the body executes; if the answer is false, the body is skipped. Here it is true, so the warning prints.

Notice there is only one branch. Nothing happens when the condition is false — the program simply carries on with whatever follows the closing brace.

Incorrect

Java uses short-circuit evaluation for && and ||. This means Java may not evaluate the second part of a Boolean expression if the result is already known.

Consider AND. If A is false, the entire expression must be false — look back at the truth table in Section 15: both rows with A false give false regardless of B. Java therefore does not need to evaluate B, and it does not.

This is not merely an optimisation. As the next slide shows, it is a guarantee programs are written to depend on.
