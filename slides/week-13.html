Abstract Data Type (ADT): a specification of what kind of data is stored, what operations are supported, and what those operations mean.

A stack is a collection in which elements are removed in the reverse order from which they were added. This behavior is called Last In, First Out, or LIFO.

The call stack, frame by frame

The call stack evolves approximately as follows. First main. Then main calls methodA, so methodA sits above main. Then methodA calls methodB, so methodB sits above both.

When methodB finishes we are back to methodA above main. Then methodA finishes, leaving main. Finally main finishes.

Using a Stack in Java

Java provides several ways of implementing stack behavior. An older Java class called Stack exists:


Stack<Integer> stack = new Stack<>();

However, modern Java generally prefers using the Deque interface.

NoteBoth work. Deque is the one to write in new code and the one used everywhere in these notes.
Reading StackDemo

Three pushes put 10, 20, and 30 on the stack, with 30 on top. The first println pops, so it prints 30 and removes it. The second peeks, so it prints 20 and leaves the stack alone.

Note that both statements are printing the results of stack operations — the stack itself is never printed.


import java.util.ArrayDeque;
import java.util.Deque;

public class StackDemo {
    public static void main(String[] args) {

        Deque<Integer> stack = new ArrayDeque<>();

        stack.push(10);
        stack.push(20);
        stack.push(30);

        System.out.println(stack.pop());
        System.out.println(stack.peek());
    }
}

ReverseString, in Java

The two loops are the whole algorithm — push everything, then pop everything:


Deque<Character> stack = new ArrayDeque<>();

for (char c : text.toCharArray()) {
    stack.push(c);
}

StringBuilder result = new StringBuilder();

while (!stack.isEmpty()) {
    result.append(stack.pop());
}

return result.toString();

Output:


retupmoc
Note!stack.isEmpty() is the loop guard. Without it, the last pop() would run on an empty stack.
The complete ReverseString program

The Java implementation declares a Deque of Character, pushes every character of the text onto it, then builds a StringBuilder by popping until the stack is empty and returns the result as a String.

Example: Matching Parentheses

Stacks are useful for determining whether brackets are correctly nested.

Valid

Not valid

To check the expression

  1. When we encounter an opening symbol, push it.
  2. When we encounter a closing symbol, pop the corresponding opening symbol.
  3. If the symbols do not match, the expression is invalid.
  4. At the end, the stack should be empty.

Part IV

Queues

First In, First Out — the fairness structure.

The Queue ADT

Queue: a collection that stores elements in the order in which they arrive.

A queue follows:

First In, First Out (FIFO)

Think about people waiting in line. Suppose:


Alice arrives
Bob arrives
Carol arrives

The queue is:


Front                      Back
Alice   Bob   Carol

Alice is served first. Then:


Front                Back
Bob   Carol
What the two ends are for

Arrivals join at the back; service happens at the front. Alice arrived first, so Alice is served first, and removing her leaves Bob at the front with Carol behind him — the people who remain keep their relative order.

That is the difference from a stack in one sentence: a queue adds at one end and removes at the other.

A queue stores elements in the order in which they arrive. A queue follows First In, First Out, or FIFO.

Think about people waiting in line. Suppose Alice arrives, then Bob, then Carol. The queue reads Alice, Bob, Carol from front to back. Alice is served first, leaving Bob and Carol.

Contrast this with the plates from Part II. A queue has two ends that do different jobs; a stack has one end that does both.

Queue Applications

Queues appear whenever tasks should generally be handled in arrival order.

  • printer jobs,
  • customer-service requests,
  • web-server requests,
  • event processing,
  • operating-system scheduling,
  • breadth-first search,
  • simulations,
  • message systems.
Key ideaThe word underneath most of this list is fairness. A queue is what you use when arriving earlier should mean being served earlier.
Breadth-first search is the outlier

Suppose tasks generate additional tasks. A queue allows us to process them in discovery order. This idea is the foundation of breadth-first search, an algorithm you will encounter again in data structures and algorithms courses.

Here the queue is not being fair to anybody — it is controlling the shape of a search. We return to this in Part IX.

        for (int value : numbers) {

            if (seen.contains(value)) {
                return true;
            }

            seen.add(value);
        }

        return false;
    }
}
The shapeAsk before adding. If the value is already in seen, we are done; otherwise record it and continue.
Why the order of the two statements matters

The contains check comes before the add. If we added first, every value would already be in the set by the time we asked, and the method would report a duplicate on the first element.

Returning false after the loop is the "we never found one" case: the loop ran to completion without ever seeing a repeat.

The DuplicateDetector class declares a Set of Integer called seen. For each value in the array, if seen already contains the value we return true; otherwise we add the value and continue. If the loop finishes, we return false.

Note that we never store the array twice and we never compare pairs of elements. The set does the remembering.

A map can be thought of as an index. Suppose we have a Student class with an id and a name. If students are stored in a List of Student, finding student 12345 might require scanning the list.

Instead we could maintain a Map of Integer to Student called studentsById. Then studentsById.get of 12345 directly expresses what we want.

This is a powerful general programming technique: organize data according to how you need to retrieve it. It is also the idea behind the inverted index in this week's lab.

Mistake: Confusing containsKey() and containsValue()

Suppose:


Map<String, Integer> ages = new HashMap<>();

ages.put("Alice", 30);

Then:

is:


true

is also:


true
Common errorThese answer completely different questions. Both happen to be true here, which is exactly what makes the confusion survive testing.
They do not even cost the same

containsKey is a hash lookup — expected O(1), as the complexity table in Part VIII records.

containsValue has no index to work from, so it must examine the values one by one. Reaching for it inside a loop is a common way to turn a linear algorithm into a quadratic one.

Suppose a Map of String to Integer called ages, with Alice mapped to 30. Then ages.containsKey of Alice is true, while ages.containsValue of 30 is also true.

These answer completely different questions. Ask the class which one answers "is Alice in the map" and which answers "does anybody here happen to be 30".

Mistake: Forgetting That get() May Return null

Consider:

Therefore you may need:

or:

Common errorDoing arithmetic on the result of get() without checking. That is where a NullPointerException comes from.
Which one to choose

Use containsKey() when a missing key means something different from a present one — a lookup failure you must report.

Use getOrDefault() when a missing key has a sensible stand-in value, as in the word-counting loop from Part VI where the stand-in is 0.

Key Takeaways

  • An ADT specifies what is stored, what operations exist, and what they mean — not how they are implemented.
  • A stack is LIFO: push, pop, peek, isEmpty. The call stack is one you have used all semester.
  • A queue is FIFO: offer, poll, peek. Stacks and queues differ only in removal order.
  • A set holds unique elements and answers "have I seen this?" in expected O(1).
  • A map associates each key with at most one value and answers "what is stored under this key?".
  • Hashing computes a position from the key itself; collisions are normal and must be handled.
  • Hash-based operations are expected constant time — an average, not a guarantee.
  • The real skill is selection: identify the behavior the problem needs, then pick the structure.

These eight points are the week in miniature. The first is the framing idea, the next four are the four ADTs, and the last three are the machinery and the judgement.

If a student remembers only one line, make it the last one: identify the behavior the problem needs, then pick the structure.

Key ideaIt demonstrates a fundamental idea used in search systems: an inverted index.
Why a Set of line numbers rather than a list

A word can occur twice on the same line. If the value were a list, line 2 would be recorded twice for that word; because it is a Set, the duplicate is absorbed and the value stays a clean list of which lines contain the word.

Note also the nested generics: Map<String, Set<Integer>> is a map whose values are themselves collections. This is the first time this semester a type parameter has contained another one.
