What Is an Algorithm?

Algorithm: a precise sequence of steps for solving a problem.

Consider the problem:

Find the largest number in an array.

One algorithm is:

  1. Assume the first element is the largest.
  2. Examine every remaining element.
  3. Whenever a larger element is found, remember it.
  4. After all elements have been examined, return the remembered value.
NoteNothing in those four steps mentions Java. That is deliberate — the algorithm exists before any language does.

The Algorithm and Its Implementation

    for (int i = 1; i < values.length; i++) {
        if (values[i] > max) {
            max = values[i];
        }
    }

    return max;

The mechanical rule, in two steps

To classify an operation count:

  1. Drop every term except the fastest-growing one.
  2. Drop the constant multiplier on the term that is left.

Applied to 4n² + 7n + 12: step one leaves 4n², step two leaves n², so the class is O(n²). Applied to the constant 7: there is no n at all, so the class is O(1).

Suppose the number of operations is 4n squared plus 7n plus 12. For very large n, the n squared term dominates. So we classify the algorithm as O of n squared.

Similarly: n plus 10 is O of n; 3n squared plus n is O of n squared; a bare 7 is O of 1; and n cubed plus n squared plus n is O of n cubed.

Work through each of those four out loud. Students who can do this mechanically will find the rest of the week much easier, because analysing code reduces to producing one of these expressions and then simplifying it.

Linear Search: The Idea

The simplest searching algorithm is linear search. The idea:

  1. Start with the first element.
  2. Compare it to the target.
  3. If it matches, return its index.
  4. Otherwise examine the next element.
  5. Continue until the target is found or the array ends.

Note the two ways this loop can end. One is success. The other is running off the end of the array, and that second exit is the one beginners forget to handle.

Linear Search in Java


public static int linearSearch(int[] values, int target) {
    for (int i = 0; i < values.length; i++) {
        if (values[i] == target) {
            return i;
        }
    }

    return -1;
}

45

Binary Search Procedure

Given a sorted array:

  1. Identify the middle element.
  2. Compare the middle element with the target.
  3. If they are equal, we are done.
  4. If the target is smaller, search only the left half.

Binary Search in Java


public static int binarySearch(int[] values, int target) {
    int low = 0;
    int high = values.length - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;

        if (values[mid] == target) {
            return mid;
        } else if (target < values[mid]) {
            high = mid - 1;
        } else {
            low = mid + 1;
        }
    }

    return -1;
}

Nineteen lines. Walk the clicks: low and high bracket the region we still have to consider; the while condition says "the region is non-empty"; mid is its middle; then three cases — found, go left, go right.

The two assignments high = mid - 1 and low = mid + 1 are where the halving actually happens, and the minus-one and plus-one matter: they exclude the element we just compared, which is what guarantees the loop terminates.

As with linear search, return -1 lives after the loop. Reaching it means low passed high — the region became empty and the target was never there.

Selection Sort in Java


public static void selectionSort(int[] values) {
    for (int i = 0; i < values.length - 1; i++) {

        int minIndex = i;

        for (int j = i + 1; j < values.length; j++) {
            if (values[j] < values[minIndex]) {
                minIndex = j;
            }
        }

        int temp = values[i];
        values[i] = values[minIndex];
        values[minIndex] = temp;
    }
}
The three-line swap, and why it needs temp 
int temp = values[i];
values[i] = values[minIndex];
values[minIndex] = temp;

The first line saves whatever is currently at position i. The second overwrites that slot with the smallest value. The third puts the saved value into the slot the smallest value came from.

Without temp, the second line destroys values[i] before the third line can read it, and one of the two values is lost.

Sixteen lines, and structurally it is two nested loops plus a three-line swap.

Click through: the outer loop chooses the position we are filling; minIndex starts as a guess that position i already holds the minimum; the inner loop scans the unsorted region for anything smaller; then the three-line swap puts the winner into place.

The three-line swap with a temporary variable is the standard Java idiom. Students who try values[i] = values[minIndex]; values[minIndex] = values[i]; lose the original value — walk that failure through if anyone proposes it.

Insertion Sort in Java


public static void insertionSort(int[] values) {
    for (int i = 1; i < values.length; i++) {

        int current = values[i];
        int j = i - 1;

        while (j >= 0 && values[j] > current) {
            values[j + 1] = values[j];
            j--;
        }

        values[j + 1] = current;
    }
}
The two-part while condition 
while (j >= 0 && values[j] > current) {

The first test, j >= 0, stops the walk at the front of the array. The second, values[j] > current, stops it as soon as we reach a value that current belongs after.

The order matters. Because && short-circuits, Java never evaluates values[j] once j has gone negative — swap the two tests and the loop throws an ArrayIndexOutOfBoundsException whenever a value travels all the way to the front.

Fourteen lines. Click through: the outer loop starts at 1 because element 0 is already a sorted region of one; current saves the value being inserted before we start overwriting slots; j walks backwards from the element just left of it.

The while condition has two parts joined by and. The first, j >= 0, stops us walking off the front of the array. The second, values[j] > current, stops us once we find something that current belongs after. Short-circuit evaluation matters here: if j goes negative, Java never evaluates values[j].

Finally values[j + 1] = current drops the saved value into the gap the shifts opened up.

Theory and Experiment

Big-O gives us a theoretical model. We can also measure algorithms experimentally. For example:

  1. Generate arrays of different sizes.
  2. Run the algorithm several times.

Notice what happens when n doubles from one thousand to two thousand: runtime increases by approximately four times. Why? Because two n, all squared, is four n squared. Doubling the input quadruples the work.

This behavior is consistent with an O of n squared algorithm. This is the standard experimental signature of a quadratic algorithm, and students can check it on their own lab data.

An O(n²) algorithm with a tiny constant can beat an O(n) algorithm with a large one, right up until n passes some crossover point. Above that point the quadratic loses, and keeps losing by more.
