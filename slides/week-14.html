Binary Search Trees

One extra ordering rule, and suddenly whole subtrees can be eliminated without looking at them.

The BST Ordering Property

Binary search tree (BST): a binary tree with an additional ordering property.

For every node:


values in left subtree < node value
values in right subtree > node value

For example:


           50
         /    \
       30      70
      /  \    /  \
    20   40  60   80

This is a binary search tree.

A binary search tree, or BST, is a binary tree with an additional ordering property. For every node, the values in the left subtree are less than the node value and the values in the right subtree are greater than the node value.

Emphasise "for every node". Checking the root is not enough — the property is recursive, and a tree that satisfies it at the root but violates it three levels down is not a BST.

Checking the Property


           50
         /    \
       30      70
      /  \    /  \
    20   40  60   80

For the root 50:


20, 30, 40 < 50

and:


60, 70, 80 > 50
Key ideaThe same property is true recursively for every node.
Check it at 30 and at 70 too

At node 30: its left subtree holds 20, and 20 is less than 30. Its right subtree holds 40, and 40 is greater than 30.

At node 70: its left subtree holds 60, less than 70; its right subtree holds 80, greater than 70.

Every node passes, so the tree is a BST. That is what "the same property is true recursively for every node" means in practice — you check it node by node, not once at the top.

For the root 50, the values 20, 30 and 40 are all less than 50, and the values 60, 70 and 80 are all greater than 50. The same property is true recursively for every node.

Searching a Binary Search Tree

A recursive search method can be written as:


public static boolean contains(TreeNode node, int target) {

    if (node == null) {
        return false;
    }

    if (target == node.value) {
        return true;
    }

    if (target < node.value) {
        return contains(node.left, target);
    } else {
        return contains(node.right, target);
    }
}

There are three main cases.

Why the last comparison needs no third branch

By the time execution reaches the final if, we already know the target is not equal to the node value — Case 2 would have returned. So only two possibilities remain: less than, or greater than.

That is why else is enough. The method searches only one subtree, and every path through it either returns a value or recurses exactly once.

A recursive search method can be written in about a dozen lines. There are three main cases, and the next slide names them.

Walk the line-number clicks: the signature takes the node to search and the target; the null test is the base case; the equality test is the success case; and the final comparison decides which single subtree to recurse into.

Iterative Search

Search can also be implemented without recursion.


public static boolean contains(TreeNode root, int target) {

    TreeNode current = root;

    while (current != null) {

        if (target == current.value) {
            return true;
        }

        if (target < current.value) {
            current = current.left;
        } else {
            current = current.right;
        }
    }

    return false;
}

Both recursive and iterative implementations are reasonable.

Key ideaTree algorithms are frequently written recursively because the recursive structure of the code matches the recursive structure of the tree.
Why the loop works here but not for traversals

Search follows a single path down the tree — at each node it discards one side entirely and never comes back. A single moving reference, current, is enough to remember where you are.

A traversal has to visit both subtrees, so it must remember where to return to. That is what the call stack does for free in the recursive versions in Part VI.

Search can also be implemented without recursion, using a while loop and a moving current reference. When current becomes null the loop ends and we return false.

Both recursive and iterative implementations are reasonable. Tree algorithms are frequently written recursively because the recursive structure of the code matches the recursive structure of the tree — and for traversals, as we will see, the recursive version is dramatically shorter.

Recursive BST Insertion

One implementation is:


public static TreeNode insert(TreeNode node, int value) {

    if (node == null) {
        return new TreeNode(value);
    }

    if (value < node.value) {
        node.left = insert(node.left, value);
    } else if (value > node.value) {
        node.right = insert(node.right, value);
    }

    return node;
}

Notice the base case:


if (node == null)

We have found the location where the new value belongs.

Why the method returns a node

The pattern node.left = insert(node.left, value) lets the recursive call decide what the child reference should become. If the child was null, the call returns a brand-new node and the assignment attaches it. If the child already existed, the call returns that same node unchanged and the assignment is harmless.

That is why the method ends with return node; — every level hands its own node back up so the parent's link stays correct.

One implementation of recursive insertion is a method that returns a TreeNode. Notice the base case: if node is null, we have found the location where the new value belongs, so we return a new node.

If the value is less than the node value, insert into the left subtree and reassign node.left; if greater, do the same on the right. If the value equals the node value, neither branch runs and nothing is inserted — a basic BST like this one quietly ignores duplicates.

A More Complete BST Class

Instead of exposing raw TreeNode objects to users of our code, we can create a class representing the entire data structure.


public class BinarySearchTree {

    private TreeNode root;

    public BinarySearchTree() {
        root = null;
    }

    public void add(int value) {
        root = insert(root, value);
    }

    private TreeNode insert(TreeNode node, int value) {

        if (node == null) {
            return new TreeNode(value);
        }

        if (value < node.value) {
            node.left = insert(node.left, value);
        } else if (value > node.value) {
            node.right = insert(node.right, value);
        }

        return node;
    }


    public boolean contains(int value) {
        return contains(root, value);
    }

    private boolean contains(TreeNode node, int value) {

        if (node == null) {
            return false;
        }

        if (value == node.value) {
            return true;
        }

        if (value < node.value) {
            return contains(node.left, value);
        }

        return contains(node.right, value);
    }
}
The class in one piece

Instead of exposing raw TreeNode objects to users of our code, we can create a class representing the entire data structure. The class keeps a private root, and each public method is a one-line wrapper around a private recursive helper.

Note the pairs: public add calls private insert; public contains calls private contains. The public method takes only what the caller cares about — a value. The private one takes the node, which is the caller's business only inside the class.

Week 14 Programming Example

Below is a small complete BST implementation. The node class is now nested and private:


public class BinarySearchTree {

    private static class TreeNode {

        int value;
        TreeNode left;
        TreeNode right;

        TreeNode(int value) {
            this.value = value;
        }
    }

    private TreeNode root;


    public void add(int value) {
        root = add(root, value);
    }

    private TreeNode add(TreeNode node, int value) {

        if (node == null) {
            return new TreeNode(value);
        }

        if (value < node.value) {
            node.left = add(node.left, value);
        } else if (value > node.value) {
            node.right = add(node.right, value);
        }

        return node;
    }
NoteThe class also defines contains and printInOrder, each a public wrapper over a private recursive helper — open the modal for the whole file.
The complete program

This is the class the lab asks students to build. Note the difference from the version in Part VII: TreeNode is now a private static nested class, so the node type is invisible outside BinarySearchTree entirely.

Note too that its constructor sets only the value. The left and right fields are left at their default of null, which Java guarantees for reference fields — the earlier version set them explicitly, and both are correct.
