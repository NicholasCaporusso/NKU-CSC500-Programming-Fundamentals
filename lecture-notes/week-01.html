CSC 500 — Programming fundamentals

Week 1: Computational thinking and Java basics

Course index

1. Overview

Programming is not primarily about memorizing the syntax of a programming language. It is about learning how to describe a computational process precisely enough that a computer can carry it out.

During this first week, we will develop three foundations that the rest of the course will build upon:

  1. Computational thinking — how to break problems into precise computational steps.
  2. The Java programming model — how Java source code is written, compiled, and executed.
  3. Basic program construction — variables, data types, expressions, assignment, console input, and console output.

At this stage, our programs will be small and will generally execute one statement after another from top to bottom. That simplicity is intentional. Before learning how programs make decisions, repeat operations, define methods, or create objects, we need to understand how individual statements manipulate data.

A central goal for this week is to begin moving from:

“I ran the program and it worked.”

toward:

“I can explain why the program behaves the way it does.”

2. Learning objectives

By the end of Week 1, you should be able to:

  • explain what a computer program is;
  • explain what an algorithm is;
  • distinguish an algorithm from a program;
  • describe the basic ideas of computational thinking;
  • decompose a small computational problem into steps;
  • distinguish Java source code, bytecode, and program output;
  • explain the roles of the compiler and Java Virtual Machine;
  • distinguish the JDK, JVM, and traditional concept of the JRE;
  • write, compile, and run a basic Java program;
  • recognize the basic structure of a Java application;
  • produce console output using System.out.print and System.out.println;
  • declare and initialize variables;
  • explain the difference between declaration, initialization, and assignment;
  • use common primitive data types;
  • distinguish primitive types from String;
  • construct arithmetic expressions;
  • apply Java's arithmetic precedence rules;
  • explain integer division and the remainder operator;
  • recognize how types influence expression evaluation;
  • perform simple numeric conversions and casts;
  • use constants with final;
  • combine text and values in output;
  • read keyboard input using Scanner;
  • recognize the common nextInt() / nextLine() input issue;
  • trace the execution of a short Java program manually;
  • describe how assignment changes program state;
  • distinguish compile-time, runtime, and logic errors;
  • use systematic debugging techniques;
  • write readable Java code using meaningful names, indentation, and comments.

Part I — Programming and computational thinking

3. What is a computer program?

A computer program is a sequence of instructions that tells a computer how to perform some task.

Programs can:

  • perform calculations;
  • process text;
  • manipulate images;
  • read and write files;
  • search through information;
  • communicate over networks;
  • control hardware;
  • run simulations;
  • manage databases;
  • support websites and mobile applications;
  • implement entire software systems.

A very small program might perform only three steps:

  1. Ask the user for a temperature in Fahrenheit.
  2. Convert the temperature to Celsius.
  3. Display the result.

A much larger program may contain millions of instructions, but the same basic principle applies: the program specifies computations that the machine will perform.

3.1 Computers are literal

Computers are extraordinarily fast, but they do not infer intention in the way humans routinely do.

Suppose we tell another person:

Calculate the average of these three exam scores.

A person probably knows immediately what is meant.

A computer needs the procedure to be made explicit:

  1. Obtain the first score.
  2. Obtain the second score.
  3. Obtain the third score.
  4. Add the scores.
  5. Divide the total by the number of scores.
  6. Display the result.

The computer executes what we specify—not what we hoped or intended to specify.

That observation explains many programming bugs.

Consider:

double width = 5.0;
double height = 3.0;

double area = width + height;

Java can execute this perfectly.

The result is:

8.0

But the programmer probably intended:

double area = width * height;

The machine has not made a mistake. The instructions were wrong.

4. Algorithms

An algorithm is a finite, well-defined sequence of steps for solving a problem or performing a computation.

An algorithm exists independently of a particular programming language.

For example, an algorithm for calculating the area of a rectangle is:

  1. Obtain the width.
  2. Obtain the height.
  3. Multiply the width by the height.
  4. Report the result.

Mathematically:

A = w × h

The same algorithm could be implemented in Java:

double area = width * height;

or in some other programming language.

Therefore:

Algorithm

The procedure or method used to solve a problem.

Program

An implementation of that procedure in a programming language.

A useful model for this course is:

Problem
   ↓
Understand
   ↓
Algorithm
   ↓
Program
   ↓
Execution
   ↓
Result
   ↓
Evaluate correctness

Notice that writing code is only one part of the process.

5. Computational thinking

Computational thinking is a systematic way of approaching problems so that a solution can be described precisely and, when appropriate, implemented by a computer.

Four ideas are particularly useful.

5.1 Decomposition

Decomposition means breaking a large problem into smaller problems.

Instead of trying to think about:

Build a banking application.

we might identify smaller responsibilities:

  • represent an account;
  • accept deposits;
  • accept withdrawals;
  • update the balance;
  • display account information;
  • record transactions.

Each smaller problem is easier to reason about.

For a simple temperature conversion program, decomposition might look like:

1. Obtain Fahrenheit temperature
2. Convert Fahrenheit to Celsius
3. Display Celsius temperature

Later in the course, methods and classes will give us programming mechanisms for representing this decomposition.

5.2 Pattern recognition

Pattern recognition means noticing similarities among problems.

Suppose you already know how to calculate:

average of three exam scores

Then calculating:

average of five exam scores

is not an entirely new problem.

The general pattern is:

sum the values
divide by the number of values

Recognizing reusable patterns reduces the amount of reasoning required for each new problem.

5.3 Abstraction

Abstraction means focusing on the important features of a problem while temporarily ignoring details that are not currently relevant.

Suppose we want to calculate the cost of buying several identical items.

Important information might be:

  • unit price;
  • quantity;
  • tax rate.

The color of the store walls is irrelevant to that computation.

Abstraction means deciding which information matters for our current purpose.

Computer science relies heavily on abstraction.

For example, when we write:

int x = 5;

we reason about a variable storing the value 5.

We do not normally need to think about:

  • transistor states;
  • processor registers;
  • electrical signals;
  • physical memory cells;
  • machine instructions.

Java allows us to work at a more useful level of abstraction.

5.4 Algorithm design

Once a problem has been understood and decomposed, we need a precise procedure.

For example:

Problem

Calculate the total cost of purchasing several items.

Inputs

item price
quantity
tax rate

Algorithm

subtotal = price × quantity
tax = subtotal × tax rate
total = subtotal + tax
display total

Possible Java implementation

double price = 12.50;
int quantity = 3;
double taxRate = 0.08;

double subtotal = price * quantity;
double tax = subtotal * taxRate;
double total = subtotal + tax;

System.out.println("Total = " + total);

Programming begins with this ability to translate a problem into precise operations.

6. Programming versus computer science

Programming is an important component of computer science, but the two terms are not synonyms.

Programming focuses on constructing executable solutions.

Computer science studies computation more broadly, including topics such as:

  • algorithms;
  • data structures;
  • programming languages;
  • operating systems;
  • databases;
  • computer networks;
  • artificial intelligence;
  • computer architecture;
  • distributed systems;
  • cybersecurity;
  • theory of computation.

CSC 500 teaches programming because programming is one of the basic tools through which many other computer science ideas are explored.

Part II — Java and the Java execution model

7. What is Java?

Java is a general-purpose programming language.

For this course, several characteristics are especially important.

Java is:

  • statically typed;
  • strongly centered around classes and objects;
  • compiled into bytecode;
  • executed through a Java Virtual Machine;
  • supported by a large standard library.

We are using Java not merely to memorize Java syntax, but to develop programming concepts that transfer to many other languages.

Concepts such as:

  • variables;
  • types;
  • expressions;
  • decisions;
  • loops;
  • methods;
  • recursion;
  • objects;
  • data structures;
  • algorithms

are not unique to Java.

8. Installing Java: JDK, JVM, and JRE

Several similar abbreviations appear in Java discussions.

8.1 JVM — Java virtual machine

The Java Virtual Machine (JVM) executes Java bytecode.

Conceptually:

Java bytecode
      ↓
     JVM
      ↓
running program

Different platforms provide JVM implementations appropriate for their environment.

8.2 JDK — Java development kit

The Java Development Kit (JDK) contains tools required to develop Java software.

Important commands include:

javac

for compiling Java source code and:

java

for running Java applications.

For CSC 500, you need a JDK because you need to both compile and execute Java programs.

8.3 JRE — Java runtime environment

Historically, the term Java Runtime Environment (JRE) referred to the environment needed to run Java programs, including the JVM and supporting runtime libraries.

For our conceptual purposes:

JDK
├── development tools
├── compiler
└── runtime environment
    └── JVM

The exact packaging of Java runtimes has evolved over time, but these conceptual distinctions remain useful.

9. Source code, compilation, bytecode, and execution

Java programs usually begin as human-readable source code.

Suppose we write:

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}

and save it as:

Hello.java

This .java file contains source code.

9.1 Compilation

We can compile the program using:

javac Hello.java

The Java compiler checks the program and, if compilation succeeds, normally creates:

Hello.class

The .class file contains Java bytecode.

Conceptually:

Hello.java
    |
    | javac
    v
Hello.class

9.2 Execution

The bytecode is then executed by the JVM:

java Hello

Conceptually:

Java source code
      |
      v
   Compiler
      |
      v
   Bytecode
      |
      v
      JVM
      |
      v
 Program executes

More concretely:

Hello.java
    |
    | javac Hello.java
    v
Hello.class

    v

    v
Hello, world!

10. Why bytecode and the JVM?

One historical design goal of Java is portability.

Rather than producing only machine instructions for one particular CPU and operating system, Java source is generally compiled into a standardized bytecode representation.

A compatible JVM on a platform can then execute that bytecode.

Conceptually:

                Hello.class
                    |
        +-----------+-----------+
        |           |           |
        v           v           v
   Windows JVM   macOS JVM   Linux JVM

This idea is associated with the expression:

Write once, run anywhere.

Real systems involve additional platform details, but the JVM gives Java programs an important layer of portability.

11. IDEs and the command line

An IDE, or Integrated Development Environment, is software that assists programmers in writing and managing code.

Typical IDE features include:

  • source-code editing;
  • syntax highlighting;
  • automatic indentation;
  • code completion;
  • compilation;
  • execution;
  • debugging;
  • project organization.

Examples of environments commonly used for Java development include IntelliJ IDEA, Eclipse, and Visual Studio Code with Java support.

An IDE is not Java itself.

A useful analogy is:

English      → language
Text editor  → tool for writing English

Java         → programming language
IDE          → tool for developing Java programs

An IDE may allow you to press a Run button, but conceptually something like this still happens:

source code
    ↓
compiler
    ↓
bytecode
    ↓
JVM
    ↓
execution

Understanding these stages makes debugging much easier.

Part III — Your first Java program

12. Hello, World

Consider:

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}

Output:

Hello, world!

Several parts may look mysterious during Week 1. That is expected.

We will deliberately learn Java in layers.

For now, understand the basic structure without trying to completely explain object-oriented concepts that belong later in the course.

13. The class declaration

The first line is:

public class Hello {

Java programs are organized around constructs called classes.

Classes will become a major topic later.

For Week 1, use the following mental model:

A class is a named container in which we can place part of our Java program.

The class is named:

Hello

Because it is declared public, the source file should normally be named:

Hello.java

not:

hello.java

or:

MyProgram.java

for this particular class declaration.

14. Java is case-sensitive

Java distinguishes uppercase and lowercase letters.

These names are different:

Hello
hello
HELLO

Likewise:

int score = 90;

creates a variable named:

score

This is not the same identifier as:

Score

Therefore:

int score = 90;

System.out.println(Score);

produces a compile-time error because Score was not declared.

Case matters in Java.

15. The main method

The line:

public static void main(String[] args) {

defines the conventional entry point for the simple Java applications we write in this course.

Execution begins in main.

During Week 1, you do not need a full explanation of:

public
static
void
String[]
args

Those concepts depend on material we will study later.

For now, treat:

public static void main(String[] args)

as the standard pattern indicating:

Start executing this program here.

16. Blocks and curly braces

Curly braces:

{
}

surround a block of code.

In:

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}

the outer braces contain the class:

public class Hello {
    ...
}

and the inner braces contain the body of main:

public static void main(String[] args) {
    ...
}

As programs grow, correctly pairing braces becomes increasingly important.

17. Statements

Inside main:

System.out.println("Hello, world!");

is a statement.

A statement represents an action performed during program execution.

Many Java statements end with a semicolon:

;

For example:

int age = 25;
age = 26;
System.out.println(age);

Each of these is a statement.

Not every Java line ends with a semicolon. For example:

public class Hello {

does not.

Part IV — Console output

18. System.out.println

We can display information using:

System.out.println("Welcome to CSC 500");

Output:

Welcome to CSC 500

Multiple statements produce multiple lines:

System.out.println("CSC 500");
System.out.println("Programming Fundamentals");
System.out.println("Week 1");

Output:

CSC 500
Programming Fundamentals
Week 1

println approximately means:

Print this value, then move to the next output line.

19. print versus println

System.out.print does not automatically move to a new line.

System.out.print("Hello ");
System.out.print("world");

Output:

Hello world

Compare:

System.out.println("Hello");
System.out.println("world");

Output:

Hello
world

A common use of print is displaying an input prompt:

System.out.print("Enter your age: ");

The user then types on the same line.

20. String literals

Text written directly inside a Java program is usually enclosed in double quotes.

System.out.println("Hello");

Here:

"Hello"

is a string literal.

Without quotation marks:

System.out.println(Hello);

Java assumes Hello is an identifier such as a variable name.

Unless such an identifier exists, compilation fails.

21. Escape sequences

Some special characters are represented using escape sequences.

Common examples:

EscapeMeaning

\ttab
\"double quotation mark
\\backslash

Example:

System.out.println("Hello\nWorld");

Output:

Example:

System.out.println("Name:\tAda");

Output resembles:

To include quotation marks:

System.out.println("She said, \"Hello.\"");

Part V — Variables, values, and program state

22. Why programs need memory

Programs often need to remember information.

Suppose we are calculating the area of a rectangle.

We need to remember:

  • width;
  • height;
  • calculated area.

Java uses variables for this purpose.

double width = 5.0;
double height = 3.0;
double area = width * height;

23. What is a variable?

A useful introductory mental model is:

A variable is a named storage location that holds a value.

For example:

int age = 25;

We have:

type       variable name       value
int        age                 25

The name age allows later statements to use that value:

System.out.println(age);

Output:

25

24. Declaration

Before using a local variable, we normally declare it.

General form:

type variableName;

Example:

int count;

This declares an integer variable named count.

At this point, we have specified the variable's name and type.

25. Initialization

Giving a variable its first value is called initialization.

We can write:

int count;
count = 10;

or combine declaration and initialization:

int count = 10;

The combined version is usually preferable when the initial value is already known.

26. Assignment

After a variable has been declared, we can assign another value:

int score = 80;

score = 90;
score = 95;

The variable does not contain all three values.

Its state changes over time:

80 → 90 → 95

After the final assignment:

score = 95

The previous values have been replaced.

27. Assignment is not mathematical equality

This is one of the most important Week 1 concepts.

In mathematics:

x = 5

usually describes equality.

In Java:

x = 5;

means:

Evaluate the expression on the right side and store its value in the variable on the left side.

Consider:

x = x + 1;

As an algebraic equation:

x = x + 1

does not make sense.

As an assignment statement, however, it is perfectly valid.

Suppose:

x = 10

before execution.

For:

x = x + 1;

Java conceptually performs:

1. Read current x       → 10
2. Evaluate x + 1       → 11
3. Store result in x    → 11

Afterward:

x = 11

The general interpretation of assignment is:

leftSide = rightSide;

means:

evaluate rightSide
       ↓
obtain a value
       ↓
store that value in leftSide

28. Program state

At any moment, a running program has a state.

For our introductory programs, an important part of that state is the collection of current variable values.

Consider:

int balance = 100;

balance = balance - 25;
balance = balance + 50;

The state changes:

balance = 100
balance = 75
balance = 125

Programming is therefore not just about individual lines of code.

We must often reason about:

How does executing this statement transform the current state into the next state?

This mental model becomes increasingly important with loops, objects, arrays, and data structures.

Part VI — Data types

29. Why variables have types

Programs manipulate different kinds of information.

Examples include:

  • whole numbers;
  • decimal numbers;
  • individual characters;
  • text;
  • logical true/false values.

Java is a statically typed language.

A variable has a declared type, and the compiler checks whether values and operations are compatible with that type.

Example:

int age = 25;

The compiler knows that age is intended to hold an integer.

This is invalid:

age = "twenty-five";

because "twenty-five" is text rather than an integer.

Static typing allows Java to detect many mistakes before execution begins.

Part VII — Variable names and code style

37. Java identifiers

Names used for variables, classes, and other program elements are called identifiers.

Java identifiers may contain:

  • letters;
  • digits;
  • underscore _;
  • dollar sign $.

An identifier cannot begin with a digit.

Valid:

age
studentCount
exam2
total_score

Invalid:

2exam
student-count
student name

Java keywords also cannot be used as identifiers.

Invalid:

int class = 5;

because class is a reserved Java keyword.

38. Meaningful variable names

Compare:

double x;
double y;
double z;

with:

double width;
double height;
double area;

The second version communicates the program's meaning.

Likewise:

double totalPrice = unitPrice * quantity;

is usually clearer than:

double x = p * q;

Good names reduce the amount of information a programmer has to remember mentally.

39. camelCase

Java convention normally uses camelCase for variable names.

Examples:

studentCount
maximumScore
monthlyPayment
accountBalance
averageTemperature

The first word begins with lowercase.

Each subsequent word begins with uppercase.

Class names conventionally begin with uppercase:

Student
BankAccount
RectangleArea
CourseRegistration

40. Constants and final

Some named values should not change during execution.

Suppose:

double taxRate = 0.07;

If the tax rate is intended to remain unchanged, we can write:

final double TAX_RATE = 0.07;

The keyword:

final

prevents later reassignment.

This would therefore be invalid:

TAX_RATE = 0.08;

Constants conventionally use uppercase letters with underscores:

MAX_SCORE
TAX_RATE
SECONDS_PER_MINUTE
MILES_TO_KILOMETERS

41. Avoiding magic numbers

Consider:

double deduction = salary * 0.0765;

What is 0.0765?

Its meaning is not obvious.

A clearer version might be:

final double TAX_RATE = 0.0765;

double deduction = salary * TAX_RATE;

A numeric literal with an unexplained meaning is sometimes called a magic number.

Naming important values improves readability.

Part VIII — Expressions and arithmetic

42. What is an expression?

An expression is a piece of code that evaluates to a value.

Examples:

5 + 3

evaluates to:

8

Likewise:

price * quantity

produces a value based on the current values of price and quantity.

In:

double area = width * height;

the expression is:

width * height

Java evaluates that expression before assigning its result to area.

43. Arithmetic operators

Java provides familiar arithmetic operators.

OperationJava operator
addition+
subtraction-
multiplication*
division/
remainder%

Example:

int x = 10;
int y = 3;

int sum = x + y;
int difference = x - y;
int product = x * y;
int quotient = x / y;
int remainder = x % y;

The values are:

sum        = 13
difference = 7
product    = 30
quotient   = 3
remainder  = 1

44. Operator precedence

Java follows arithmetic precedence rules.

Consider:

int result = 5 + 2 * 3;

Multiplication occurs first:

2 * 3 = 6

then:

5 + 6 = 11

Therefore:

result = 11

If we write:

int result = (5 + 2) * 3;

the parentheses force addition first:

5 + 2 = 7
7 * 3 = 21

so:

result = 21

45. A practical precedence rule

For the arithmetic used this week:

  1. Parentheses
  2. Multiplication, division, remainder
  3. Addition and subtraction

Operations at the same level generally associate from left to right.

Example:

20 / 5 * 2

becomes:

20 / 5 = 4
4 * 2 = 8

When the intended calculation might be unclear, use parentheses.

46. Parentheses prevent bugs

Suppose we want the average of three values.

Incorrect:

double average = a + b + c / 3.0;

Java interprets this approximately as:

double average = a + b + (c / 3.0);

Correct:

double average = (a + b + c) / 3.0;

Parentheses are not merely decorative. They may change the result.

47. Integer division

One of the most important Java arithmetic rules is:

Dividing two integer operands performs integer division.

Consider:

System.out.println(5 / 2);

Many beginners expect:

2.5

Java produces:

2

because both operands are integers.

The fractional part is discarded.

Examples:

10 / 3 = 3
7 / 2  = 3
1 / 2  = 0

48. Floating-point division

If at least one operand is floating-point:

System.out.println(5.0 / 2);

the result is:

2.5

These all perform floating-point division:

5.0 / 2
5 / 2.0
5.0 / 2.0

49. Destination type does not fix integer division

Consider:

int a = 5;
int b = 8;

double average = (a + b) / 2;

It may appear that average should be 6.5 because its type is double.

But Java first evaluates:

(a + b) / 2

Using integers:

13 / 2 = 6

Then that integer result is converted to a double:

6.0

The destination variable does not change how the earlier expression was evaluated.

Correct:

double average = (a + b) / 2.0;

Now:

13 / 2.0 = 6.5

50. The remainder operator %

The % operator computes the remainder from integer division.

For example:

17 % 5

Because:

17 = 5(3) + 2

the remainder is:

2

Examples:

8 % 2  = 0
9 % 2  = 1
10 % 3 = 1
17 % 5 = 2

The remainder operator is useful for:

  • determining divisibility;
  • determining even and odd values;
  • extracting digits;
  • time conversion;
  • cyclic calculations.

For example:

int totalSeconds = 137;

int minutes = totalSeconds / 60;
int seconds = totalSeconds % 60;

produces:

minutes = 2
seconds = 17

51. String concatenation

The + operator has another use: combining strings.

String name = "Grace";

System.out.println("Hello, " + name);

Output:

Hello, Grace

Example:

int age = 27;

System.out.println("Age: " + age);

Output:

Age: 27

52. Numbers versus numeric-looking strings

Compare:

2 + 3

with:

"2" + "3"

The first performs numeric addition:

5

The second concatenates strings:

23

Quotation marks change the type and therefore the meaning.

53. Concatenation and evaluation order

Consider:

System.out.println("Result: " + 2 + 3);

Java evaluates from left to right once concatenation is occurring:

"Result: " + 2
→ "Result: 2"

"Result: 2" + 3
→ "Result: 23"

Output:

Result: 23

If we want arithmetic first:

System.out.println("Result: " + (2 + 3));

Output:

Result: 5

Parentheses communicate the intention clearly.

Part IX — Type conversion

54. Automatic numeric conversion

Java can automatically perform some conversions when doing so is considered safe.

Example:

int count = 5;
double value = count;

count contains the integer:

5

and value becomes approximately:

5.0

Converting an int to a double does not normally require an explicit cast.

55. Explicit casting

Some conversions can lose information and must be explicitly requested.

Example:

double value = 5.9;

int whole = (int) value;

The cast:

(int)

requests conversion to an integer.

The result is:

whole = 5

56. Casting does not round

Consider:

double value = 9.9;
int result = (int) value;

The result is:

9

not:

10

Casting a double to an int discards the fractional portion.

Similarly:

(int) 3.99

produces:

3

Casting should be used carefully because information may be lost.

57. Floating-point approximation

Decimal numbers represented by double are stored using binary floating-point representation.

Not every decimal fraction has an exact finite binary representation.

Therefore, some computations can produce results such as:

0.30000000000000004

where a human might expect exactly:

0.3

For introductory scientific and numerical exercises, double is usually appropriate.

However, the general lesson is:

Computer representations of numbers have limitations.

For production financial calculations, programmers often use representations designed for exact decimal arithmetic, such as integer cents or BigDecimal.

We do not need to master those alternatives during Week 1.

65. The nextInt() / nextLine() pitfall

A common beginner problem occurs when token-reading methods such as:

nextInt()

or:

nextDouble()

are followed by:

nextLine()

Consider:

System.out.print("Enter age: ");
int age = input.nextInt();

System.out.print("Enter name: ");
String name = input.nextLine();

Suppose the user enters:

25

and presses Enter.

nextInt() consumes the integer 25, but the newline generated by Enter may remain.

Then:

input.nextLine();

may consume that leftover newline immediately.

The name appears to have been “skipped.”

One common solution is:

System.out.print("Enter age: ");
int age = input.nextInt();

input.nextLine();  // consume the remaining newline

System.out.print("Enter name: ");
String name = input.nextLine();

That extra call consumes the remainder of the previous input line.

Part XII — Sequential execution and tracing

72. Statements execute in order

For the simple programs in Week 1, execution proceeds essentially from top to bottom.

Consider:

int x = 5;

x = x + 1;
x = x * 2;

System.out.println(x);

Trace:

x = 5
x = 6
x = 12
print 12

Output:

12

Java does not evaluate the program “all at once.”

Each statement operates using the program state that exists at that moment.

73. Why trace programs manually?

One of the most useful programming skills is predicting what code will do without relying exclusively on running it.

Before executing code, ask:

What do I expect to happen?

If the actual result differs, you have learned something important.

Tracing helps you understand:

  • sequence;
  • assignment;
  • expression evaluation;
  • variable state;
  • source of bugs.

74. Basic trace example

Consider:

int x = 4;
int y = 2;

x = x + y;
y = x * 2;

System.out.println(x);
System.out.println(y);

Initially:

x = 4
y = 2

Execute:

x = x + y;

Right side:

4 + 2 = 6

New state:

x = 6
y = 2

Now execute:

y = x * 2;

Right side:

6 * 2 = 12

New state:

x = 6
y = 12

Output:

6
12

75. Trace tables

A trace table gives us a systematic way to record changing values.

Program:

int a = 3;
int b = 4;

a = a + b;
b = a - b;
a = a - b;

Trace:

Statementab
int a = 3;3—
int b = 4;34
a = a + b;74

The two values have been swapped.

Initially:

Finally:

a = 4
b = 3

76. Assignment copies a value

Consider:

int a = 5;
int b = 8;

a = b;

After:

a = b;

the current value of b is copied into a.

State:

a = 8
b = 8

Now execute:

b = a + 2;

Then:

b = 10

Final state:

a = 8
b = 10

Changing b later does not retroactively change the earlier assignment to a.

Part XIII — Errors and debugging

77. Programming errors

Beginning programmers should distinguish at least three broad categories of errors:

  1. compile-time errors;
  2. runtime errors;
  3. logic errors.

Understanding which category you are dealing with immediately narrows the debugging problem.

78. Syntax errors

A syntax error violates Java's grammatical rules.

Example:

int x = 5

The semicolon is missing.

Another example:

System.out.println("Hello);

The quotation marks are not paired correctly.

The compiler detects such problems and refuses to successfully compile the program.

79. Compile-time errors

Not every compile-time error is simply punctuation.

Consider:

int age = "twenty";

The basic form resembles valid Java, but the type is wrong.

Another example:

System.out.println(score);

when no score variable has been declared.

Both problems are detected during compilation.

Therefore:

A syntax error is a kind of compile-time error, but compile-time errors also include violations of type and name rules.

80. Runtime errors

A runtime error occurs after successful compilation when something goes wrong during execution.

Example:

int x = 10;
int y = 0;

System.out.println(x / y);

This compiles.

During execution, integer division by zero causes an exception.

Conceptually:

compile
   ↓
success
   ↓
program begins
   ↓
problem occurs
   ↓
runtime failure

81. Logic errors

A logic error occurs when the program runs but computes the wrong result.

Example:

double length = 10;
double width = 5;

double perimeter = length * width;

The code compiles.

It runs.

But:

length * width

calculates area rather than perimeter.

Correct:

double perimeter = 2 * (length + width);

Logic errors are often difficult because the compiler cannot determine what result the programmer intended.

83. What is debugging?

Debugging is the process of locating, understanding, and correcting defects in a program.

A realistic development process is:

understand problem
      ↓
design solution
      ↓
write some code
      ↓
compile
      ↓
test
      ↓
compare actual result with expected result
      ↓
investigate differences
      ↓
revise
      ↓
test again

Debugging is not separate from programming.

It is part of programming.

84. A systematic debugging strategy

When something goes wrong:

Step 1 — Identify the category

Ask:

Did compilation fail?
Did execution crash?
Did execution finish with a wrong answer?

Step 2 — Read the error message

Do not ignore compiler output.

The first error is often especially important because later errors may be consequences of the first one.

Step 3 — Predict the expected behavior

Ask:

What did I expect?
What actually happened?

Step 4 — Trace values

Record the current value of each important variable.

Step 5 — Reduce the problem

Test a smaller example if possible.

Step 6 — Form a hypothesis

For example:

I think integer division is causing the average to lose .5.

Step 7 — Test the hypothesis

Change only what is relevant.

Avoid randomly editing multiple lines until the program happens to work.

85. Common beginner debugging checklist

When a program does not work, check:

  • Did I save the source file?
  • Does the public class name match the filename?
  • Is capitalization correct?
  • Are quotation marks paired?
  • Are parentheses paired?
  • Are braces paired?
  • Did I forget a semicolon?
  • Did I declare every variable before using it?
  • Am I using the correct variable name?
  • Am I assigning a compatible type?
  • Am I accidentally performing integer division?
  • Did I use parentheses to express the intended formula?
  • Did I quote text literals?
  • Did I import Scanner?
  • Did I create the Scanner?
  • Am I mixing nextInt()/nextDouble() with nextLine()?
  • Did I read the first compiler error carefully?
  • Have I manually traced the program?
  • Have I tested with simple values whose answer I already know?

Part XIV — Readability and style

86. Code is read by humans

These statements may perform the same computation:

int x=10;double y=20.5;System.out.println(x+y);

and:

int x = 10;
double y = 20.5;

System.out.println(x + y);

The second version is much easier for a human to read.

Correct software must be understandable as well as executable.

87. Indentation

Preferred:

public class Example {
    public static void main(String[] args) {
        int x = 5;

        System.out.println(x);
    }
}

Poorly formatted:

public class Example {
public static void main(String[] args) {
int x = 5;
System.out.println(x);
}
}

Java usually relies on braces rather than indentation to determine structure, so the second program may still compile.

Humans, however, rely strongly on indentation.

88. Comments

A single-line comment begins with:

//

Example:

// Calculate the rectangle area
double area = width * height;

Java ignores the comment during execution.

Multi-line comments use:

/*
This comment can span
several lines.
*/

Comments should communicate useful information.

Weak:

// Multiply width and height
double area = width * height;

The code already tells us that.

Potentially more useful:

// Dimensions are measured in meters, so the result is in square meters.
double area = width * height;

Use comments to explain intent, assumptions, or reasoning—not to translate every obvious statement into English.

Part XV — From problem to program

89. A reliable Week 1 problem-solving process

Suppose the problem says:

Write a program that reads a distance in miles and reports the equivalent distance in kilometers.

Do not immediately begin typing Java.

Use a sequence such as the following.

Step 1 — Understand the problem

Input:

distance in miles

Output:

distance in kilometers

Conversion:

1  mile = 1.60934  km

Step 2 — Design the algorithm

read miles
kilometers = miles × 1.60934
display kilometers

Step 3 — Choose representations

The distance may contain a fractional component.

Use:

double

Define a named conversion constant:

final double KM_PER_MILE = 1.60934;

Step 4 — Translate the algorithm into Java

import java.util.Scanner;

public class MilesToKilometers {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        final double KM_PER_MILE = 1.60934;

        System.out.print("Enter miles: ");
        double miles = input.nextDouble();

        double kilometers = miles * KM_PER_MILE;

        System.out.println("Kilometers = " + kilometers);
    }
}

Step 5 — Predict a result

Suppose:

miles = 1

Expected:

1.60934 km

Step 6 — Run and compare

If the output differs from the prediction, investigate why.

This pattern is far more reliable than typing code first and thinking later.

Part XVI — Worked example: Weighted course grade

90. Problem

Suppose a course uses:

Homework: 30%
Midterm:  30%
Final:    40%

Given the three scores, calculate the weighted course grade.

91. Decomposition

Inputs:

homework score
midterm score
final exam score

Processing:

weighted homework = homework × 0.30
weighted midterm  = midterm × 0.30
weighted final    = final × 0.40

course score = weighted homework
             + weighted midterm
             + weighted final

Output:

course score

92. Implementation

import java.util.Scanner;

public class WeightedGrade {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        final double HOMEWORK_WEIGHT = 0.30;
        final double MIDTERM_WEIGHT = 0.30;
        final double FINAL_WEIGHT = 0.40;

        System.out.print("Enter homework score: ");
        double homework = input.nextDouble();

        System.out.print("Enter midterm score: ");
        double midterm = input.nextDouble();

        System.out.print("Enter final exam score: ");
        double finalExam = input.nextDouble();

        double courseScore =
                homework * HOMEWORK_WEIGHT
                + midterm * MIDTERM_WEIGHT
                + finalExam * FINAL_WEIGHT;

        System.out.println("Course score = " + courseScore);
    }
}

If:

homework = 90
midterm = 80
final = 100

then:

homework contribution = 90 × .30 = 27
midterm contribution  = 80 × .30 = 24
final contribution    = 100 × .40 = 40

Therefore:

course score = 27 + 24 + 40
             = 91

94. Incorrect capitalization

Incorrect:

3.0

7 / 2
→ integer division
→ 3
→ converted to 3.0

Incorrect:

System.out.println(Hello);

System.out.println("Hello");

99. Wrong formula

Code can be valid Java and still be wrong.

Incorrect area formula:

Correct:

double area = width * height;

Always distinguish:

“Does it compile?”

from:

“Is it correct?”

100. Misunderstanding assignment

Suppose:

int b = 20;

a = b;

Some beginners imagine the variables are somehow permanently connected.

They are not.

After assignment:

a = 20
b = 20

Then:

b = 30;

produces:

a = 20
b = 30

The earlier assignment copied the value that b had at that moment.

131. The Week 1 mental model

For now, think of a Java program as a sequence of state transformations.

Example:

int x = 5;
x = x + 2;
x = x * 3;

Think:

statement                state

int x = 5;               x = 5

x = x + 2;               x = 7

x = x * 3;               x = 21

Every time you encounter a statement, ask:

  1. What values does this statement read?
  2. What expression is evaluated?
  3. What value does the expression produce?
  4. Does a variable change?
  5. What is the program state afterward?

This method of reasoning will remain useful long after Week 1.

132. Key ideas to remember

A program specifies computations that a computer performs.

An algorithm is a precise procedure for solving a problem.

Computational thinking includes:

Java source code follows the approximate pipeline:

       ↓

       ↓

       ↓

       ↓

Variables allow programs to represent changing state:

Expressions produce values:

Input can be obtained with Scanner.

Programming requires learning to reason precisely about how instructions transform data and program state.

133. Final advice for Week 1

During the first week, programming may feel difficult for reasons that have little to do with the complexity of the programs themselves.

You are simultaneously learning:

  • a formal programming language;
  • a development environment;
  • compiler behavior;
  • unfamiliar notation;
  • new problem-solving techniques;
  • new ways of representing data;
  • a new interpretation of assignment;
  • techniques for diagnosing errors.

Do not measure progress only by asking:

Can I write this whole program from memory?

More useful questions are:

Can I explain what each statement does?

Can I predict the value of every variable?

Can I explain why this expression produces this value?

Can I identify whether an error occurs during compilation, execution, or computation?

Can I break a small problem into explicit steps before writing code?

Develop one habit immediately:

Make predictions before running code.

Before pressing Run, ask:

What output do I expect?

Before changing a statement, ask:

What effect should this change have?

Before evaluating an expression experimentally, ask:

What value should this expression produce?

When your prediction and the computer's behavior differ, do not treat the difference as mysterious.

Investigate it.

That process—predict, execute, compare, explain—is one of the foundations of learning to program.

134. Looking ahead

The programs in Week 1 execute essentially from top to bottom.

For example:

double width = input.nextDouble();
double height = input.nextDouble();
double area = width * height;
System.out.println(area);

Every statement executes once.

But useful programs frequently need to choose among different actions.

For example:

if a score is high:
    display one message

otherwise:
    display another message

That requires decision-making and Boolean logic, which are the focus of Week 2.
