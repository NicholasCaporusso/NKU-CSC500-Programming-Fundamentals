CSC500 - Programming fundamentals

Week 1: Computational thinking and Java basics

1. Learning objectives

By the end of Week 1, students should be able to:

  • Explain what a computer program is.
  • Describe, at a high level, how Java source code becomes an executing program.
  • Distinguish between source code, compiled code, and program output.
  • Write, compile, and run a simple Java program.
  • Use variables to store information.
  • Work with basic Java primitive data types.
  • Construct arithmetic expressions.
  • Use assignment statements.
  • Produce console output.
  • Read simple input from the keyboard.
  • Trace the execution of a short Java program by hand.
  • Identify syntax errors, runtime errors, and logic errors.
  • Begin thinking about programming as the precise specification of a computational process.

Part I - What is programming?

2. Programs as precise instructions

A computer is extremely fast, but it is not intelligent in the way humans normally use that word.

A computer does not understand:

  • what you intended,
  • what you probably meant,
  • whether your result makes sense,
  • or whether a particular instruction is a good idea.

It executes instructions according to precisely defined rules.

Programming is therefore the process of expressing a solution to a problem in a form that a computer can execute.

Consider the instruction:

Calculate the average of three exam scores.

A human may immediately understand what to do.

A computer needs a much more explicit procedure:

  1. Obtain the first score.
  2. Obtain the second score.
  3. Obtain the third score.
  4. Add the three scores.
  5. Divide the sum by 3.
  6. Display the result.

This sequence of steps is an example of an algorithm.

3. Algorithms

An algorithm is a finite sequence of well-defined steps for solving a problem or performing a computation.

Algorithms exist independently of programming languages.

For example, an algorithm for computing the area of a rectangle could be:

  1. Obtain the width.
  2. Obtain the height.
  3. Multiply width by height.
  4. Report the result.

We might express the algorithm mathematically as:

A = w × h

We could implement the same algorithm in Java, Python, C++, or another language.

This distinction is important:

Algorithm: the method used to solve the problem.

Program: an implementation of that method in a programming language.

Throughout CSC500, we will repeatedly move through the following process:

Problem → Algorithm → Program → Execution → Result

Part II - A first Java program

4. Hello, World

A traditional first Java program is:

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}

When executed, the program displays:

Hello, world!

At first, some parts of this program will look mysterious. That is expected.

For now, focus on its structure.

5. The class

public class Hello {

Java programs are organized around entities called classes.

Classes will become one of the central ideas of this course when we study object-oriented programming.

For now, think of a class as a container that holds part of a Java program.

Here, the class is named:

Hello

Java is case-sensitive.

Therefore:

Hello
hello
HELLO

are three different names.

If the class is declared as:

public class Hello

the source file should normally be named:

Hello.java

Part III - The main method

6. Where execution begins

Consider:

public static void main(String[] args) {

When we run this Java application, execution begins in the main method.

For Week 1, treat this line as a required pattern.

Later in the course we will understand what each part means:

  • public
  • static
  • void
  • String[]
  • args

For now, remember:

public static void main(String[] args)

defines the starting point of a basic Java application.

7. Statements

Inside main, we have:

System.out.println("Hello, world!");

This is a Java statement.

A statement tells the computer to perform some action.

Here, the action is:

Display the text Hello, world!

Most Java statements end with a semicolon:

;

Forgetting the semicolon is a common beginning programming error.

Part IV - Compilation and execution

8. Source code

The Java code that we write is called source code.

For example:

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}

might be stored in:

Hello.java

The computer does not directly execute Java source code.

Instead, Java normally uses a two-stage process.

9. Compilation

The Java compiler translates source code into another representation called bytecode.

Conceptually:

Hello.java
    |
    | Java compiler
    v
Hello.class

The command-line Java compiler is called:

javac

For example:

javac Hello.java

If compilation succeeds, Java produces:

Hello.class

10. The Java virtual machine

The .class file contains Java bytecode.

The bytecode is executed by the Java Virtual Machine, or JVM.

Conceptually:

      v
   Compiler
      |
      v
   Bytecode
      |
      v
     JVM
      |
      v
Program execution

To run the program from a terminal, we might use:

java Hello

Notice that we write:

java Hello

not:

java Hello.java

when executing the compiled class in the traditional compile-then-run workflow.

Part V - Why Java uses a JVM

11. Portability

One of Java's historical design goals is portability.

The idea is approximately:

Compile Java source into a standard bytecode format, then run that bytecode using an appropriate JVM on each platform.

Therefore, Java bytecode can often run across operating systems without recompiling the source for each CPU architecture.

This idea is sometimes summarized by the phrase:

Write once, run anywhere.

In reality, platform differences still matter in some situations, but the JVM provides a useful level of abstraction between the Java program and the underlying machine.

Part VII - Variables

14. Programs need memory

Programs often need to remember information.

Suppose we want to calculate someone's age next year.

We need somewhere to store the current age.

Java provides variables for this purpose.

Example:

int age = 25;

This declares a variable named:

age

and gives it the value:

25

15. Variables as named storage

A useful first mental model is:

A variable is a named location in which a program stores a value.

For example:

int students = 20;
double temperature = 72.5;

We have two variables:

students
temperature

with corresponding values:

20
72.5

The variable names allow us to refer to those values later.

Part VIII - Variable declaration

16. Declaring a variable

In Java, variables have types.

The general form is:

type variableName;

For example:

int count;

This declares a variable named count capable of storing an integer.

We can later assign a value:

count = 10;

Or we can declare and initialize the variable at the same time:

int count = 10;

17. Assignment

Consider:

int x = 5;
x = 12;

After the first statement:

x contains 5

After the second statement:

x contains 12

The old value has been replaced.

Part IX - Assignment is not algebra

18. Understanding =

In mathematics:

x = 5

usually expresses an equality.

In Java:

x = 5;

means:

Evaluate the expression on the right and store the resulting value in the variable on the left.

This distinction becomes especially important when we write:

x = x + 1;

Mathematically,

x = x + 1

would be impossible.

In programming, however, it means:

  1. Read the current value of x.
  2. Add 1.
  3. Store the result back into x.

If:

x = 10

before the statement, then after:

x = x + 1;

we have:

x = 11

Part X - Primitive data types

19. Why types matter

A program works with different kinds of data.

Examples include:

  • whole numbers,
  • decimal numbers,
  • characters,
  • true/false values.

Java is a statically typed language.

This means that variables have declared types.

The compiler uses these types to determine what operations are valid.

20. int

The int type stores integers.

Examples:

int students = 24;
int temperature = -5;
int year = 2026;

Valid integer values include:

0
17
-92
5000

An int does not store fractional values.

This is invalid:

int price = 19.99;

21. double

The double type stores floating-point numbers.

Examples:

double price = 19.99;
double temperature = 72.5;
double pi = 3.14159;

A double can represent fractional quantities.

22. boolean

A boolean represents one of two logical values:

true
false

Example:

boolean enrolled = true;
boolean finished = false;

Booleans will become extremely important when we introduce decision-making in Week 2.

23. char

A char stores a single character.

Example:

char grade = 'A';

Notice the single quotation marks:

'A'

A character differs from a string.

Character:

'A'

String:

"A"

Part XI - Strings

24. Text data

Java represents sequences of characters using the String type.

Example:

String name = "Ada";

Another example:

String course = "CSC500";

Strictly speaking, String is not a primitive type.

It is a class.

We will understand the significance of that distinction later.

For now, it is fine to think of String as the standard Java type for text.

Part XII - Naming variables

25. Legal names

Java identifiers can include:

  • letters,
  • digits,
  • underscore _,
  • dollar sign $.

However, an identifier cannot begin with a digit.

Valid:

age
studentCount
exam2
total_score

Invalid:

2exam
student-count
class

The last example is invalid because class is a Java keyword.

26. Good names

Prefer meaningful variable names.

Poor:

double x;
double y;

Better:

double width;
double height;

Poor:

int a;

Better:

int studentCount;

Good variable names make programs easier to read, understand, test, and maintain.

27. Java naming convention

Java programmers normally use camelCase for variable names:

studentCount
maximumScore
monthlyPayment

The first word starts with a lowercase letter, while subsequent words begin with uppercase letters.

Class names normally begin with uppercase letters:

Student
BankAccount

Part XIII - Arithmetic expressions

28. Basic arithmetic operators

Java supports familiar arithmetic operators.

OperationJava
Addition+
Subtraction-
Multiplication*
Division/
Remainder%

Example:

29. Expression evaluation

Suppose:

int x = 5;
int y = 2;
int z = x + y * 3;

Java follows operator precedence.

Multiplication happens before addition:

y * 3
2 * 3
6

Then:

x + 6
5 + 6
11

Therefore:

z = 11

Parentheses can make the intended order explicit:

int z = (x + y) * 3;

Now:

(5 + 2) * 3
7 * 3
21

Part XIV - Integer division

30. An important Java rule

Consider:

int x = 5;
int y = 2;

System.out.println(x / y);

Many new programmers expect:

2.5

But Java prints:

2

Why?

Both operands are integers.

Therefore Java performs integer division.

The fractional part is discarded.

31. Producing floating-point division

If at least one operand is floating-point:

System.out.println(5.0 / 2);

the output is:

2.5

Similarly:

double result = 5.0 / 2.0;

produces:

2.5

This distinction will cause many bugs if students do not understand it.

Part XV - The remainder operator

32. %

The % operator computes the remainder after integer division.

For example:

int remainder = 10 % 3;

Since:

10 = 3 × 3 + 1

we get:

remainder = 1

Examples:

8 % 2 = 0
9 % 2 = 1
17 % 5 = 2

The remainder operator becomes useful for problems such as:

  • determining whether a number is even,
  • extracting digits,
  • cyclic calculations,
  • time calculations.

Part XXV - Errors

44. Programming errors

Programs can fail in several different ways.

It is useful to distinguish among:

  1. syntax errors,
  2. runtime errors,
  3. logic errors.

45. Syntax errors

A syntax error occurs when code violates the grammatical rules of Java.

Example:

System.out.println("Hello")

The semicolon is missing.

Another example:

int x = ;

The compiler cannot understand the statement.

Syntax errors are usually detected during compilation.

46. Runtime errors

A program may compile successfully but fail while it is executing.

Example:

int x = 10;
int y = 0;

System.out.println(x / y);

The program compiles.

But attempting integer division by zero causes an exception during execution.

This is a runtime error.

47. Logic errors

Logic errors are often more difficult.

The program runs, but produces an incorrect answer.

Example:

double width = 5;
double height = 3;

double area = width + height;

This program compiles.

It runs.

But the formula is wrong.

The programmer intended:

double area = width * height;

The computer faithfully executes what we wrote, not what we intended.

Part XXVI - Debugging

48. What is debugging?

Debugging is the process of identifying and correcting defects in a program.

Useful debugging habits include:

  • read compiler messages carefully,
  • reduce the problem to a small example,
  • print intermediate values,
  • trace code by hand,
  • test with simple inputs whose correct answers you already know,
  • change one thing at a time,
  • distinguish symptoms from causes.

A fundamental rule:

Do not randomly modify code until it works.

Instead, develop a hypothesis about what is wrong and test that hypothesis.

Part XXVII - comments

49. Comments for humans

Comments allow programmers to leave explanatory text in source code.

A single-line comment begins with:

//

Example:

// Compute the area of the rectangle
double area = width * height;

Java ignores the comment during execution.

50. Multi-line comments

Java also supports:

/*
This is a
multi-line comment.
*/

Comments should explain useful information, not restate obvious code.

Weak comment:

// Add x and y
sum = x + y;

More useful:

// Scores are weighted equally, so divide their sum by the number of exams.
average = total / examCount;

Part XXVIII - Code style

51. Readability matters

Compare:

int x=10;double y=20.5;System.out.println(x+y);

with:

int x = 10;
double y = 20.5;

System.out.println(x + y);

Both may compile.

The second is much easier to read.

Professional programming is not only about making code execute.

Code must also be understandable to humans.

52. Indentation

Use consistent indentation to show program structure.

Preferred:

    public static void main(String[] args) {

    }
}

Poor:

As programs become more complex, indentation becomes essential.

Part XXIX - Computational thinking

53. From problem to program

Suppose the problem is:

Given a temperature in Fahrenheit, calculate Celsius.

We should not immediately start typing Java.

First identify the relationship:

C = 5 / 9(F - 32)

Then identify inputs and outputs.

Input:

Fahrenheit temperature

Output:

Celsius temperature

Then form an algorithm:

  1. Read Fahrenheit temperature.
  2. Subtract 32.
  3. Multiply by 5.
  4. Divide by 9.
  5. Display Celsius temperature.

Then implement it.

54. Java implementation

import java.util.Scanner;

public class TemperatureConverter {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        System.out.print("Enter temperature in Fahrenheit: ");
        double fahrenheit = input.nextDouble();

        double celsius = (5.0 / 9.0) * (fahrenheit - 32);

        System.out.println("Celsius: " + celsius);
    }
}

Notice:

5.0 / 9.0

rather than:

5 / 9

Why?

Because:

5 / 9

uses integer division and evaluates to:

0

This would cause an incorrect result.

Part XXXII - Mental model of program execution

60. Programs execute sequentially

For now, programs execute approximately from top to bottom.

Consider:

int x = 5;
x = x + 1;
x = x * 2;

System.out.println(x);

Execution occurs in this order:

x = 5
x = 6
x = 12
print 12

Later, conditionals, loops, and method calls will make control flow more sophisticated.

But execution always follows defined rules.

Part XXXIII - memory and state

61. Program state

At any moment during execution, a program has a state.

The state includes the current values stored in variables.

Consider:

int balance = 100;
balance = balance - 25;
balance = balance + 50;

The state evolves:

balance = 100
balance = 75
balance = 125

Thinking about how program state changes over time is an important skill.

It becomes especially important when we later study:

  • loops,
  • objects,
  • arrays,
  • linked structures,
  • recursion,
  • algorithms.

Part XXXIV - Programming is about abstraction

62. Levels of detail

You do not need to understand how electrical signals move through a processor in order to write:

int x = 5;

Java provides abstractions that allow us to reason at a higher level.

For example, we say:

Store the integer 5 in the variable x.

The computer ultimately performs much lower-level operations.

A major theme throughout computer science is:

Managing complexity through abstraction.

Later examples include:

  • methods,
  • classes,
  • interfaces,
  • data structures,
  • libraries,
  • operating systems,
  • databases.

Part XXXVI - Common beginner mistakes

66. Missing semicolons

Incorrect:

int x = 5

Correct:

int x = 5;

67. Wrong capitalization

Incorrect:

system.out.println("Hello");

Correct:

System.out.println("Hello");

Java is case-sensitive.

68. Using a variable before declaring it

Incorrect:

x = 10;
int x;

Prefer:

int x = 10;

69. Confusing int and double

Potentially problematic:

int average = 7 / 2;

Result:

3

If the intended answer is 3.5:

double average = 7.0 / 2.0;

70. Forgetting quotation marks

Incorrect:

System.out.println(Hello);

Unless Hello is the name of a valid variable, this will not work.

Text literals require quotation marks:

System.out.println("Hello");

The first assignment should be relatively low stakes.

Students should submit several small programs demonstrating that they can:

  • create a Java source file,
  • compile it,
  • run it,
  • use variables,
  • perform arithmetic,
  • accept input,
  • display output.

Suggested tasks:

Problem 1 - Distance conversion

Read a distance in miles and convert it to kilometers.

Use:

1  mile = 1.60934  km

Problem 2 - Circle measurements

Read a radius and calculate:

area = π r2

and:

circumference = 2π r

Java provides:

Math.PI

Problem 3 - Time conversion

Read a number of seconds and calculate:

  • hours,
  • remaining minutes,
  • remaining seconds.

For example:

Input: 7384 seconds

Output:
2 hours
3 minutes
4 seconds

Problem 4 - Weighted grade

Read three scores:

  • homework,
  • midterm,
  • final.

Suppose the weights are:

Homework: 30%
Midterm: 30%
Final: 40%

Calculate the weighted course score.

Part XL - key ideas to remember

74. Week 1 summary

A program is a precise sequence of instructions executed by a computer.

An algorithm is a procedure for solving a problem.

Java source code is typically:

written
   ↓
compiled
   ↓
translated into bytecode
   ↓
executed by the JVM

Variables allow programs to maintain state.

Examples:

int students = 25;
double average = 92.4;
boolean enrolled = true;
String course = "CSC500";

Assignment changes program state:

x = x + 1;

Expressions compute values:

double area = width * height;

Input can be obtained using Scanner.

Output can be displayed using:

System.out.println(...)

Three important categories of errors are:

syntax errors
runtime errors
logic errors

Most importantly, programming requires learning to reason precisely about how instructions transform program state.

Looking ahead

In Week 1, our programs execute essentially from top to bottom.

That severely limits what they can do.

Suppose we want a program to behave differently depending on a student's grade:

If the score is at least 90:
    print "Excellent"

Otherwise:
    print "Keep working"

To do this, programs need the ability to make decisions.

That brings us to Week 2: Decisions, boolean logic, and conditional execution
