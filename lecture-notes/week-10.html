1. What is recursion?

A method is recursive if it calls itself, either directly or indirectly.

Consider the mathematical definition of factorial:

n! = n × (n-1) × (n-2) × ·s × 1

For example:

5! = 5 × 4 × 3 × 2 × 1 = 120

Factorial can also be defined recursively:

n! =
\begin{cases}
1 & if  n = 0 \\
n × (n-1)! & if  n > 0
\end{cases}

This definition says:

  • We already know the answer for 0!.
  • To find n!, we reduce the problem to a smaller version of the same problem.

That idea is the essence of recursion.

In Java:

public static int factorial(int n) {
    if (n == 0) {
        return 1;
    }

    return n * factorial(n - 1);
}

Calling:

factorial(4)

conceptually produces:

factorial(4)
= 4 * factorial(3)
= 4 * 3 * factorial(2)
= 4 * 3 * 2 * factorial(1)
= 4 * 3 * 2 * 1 * factorial(0)
= 4 * 3 * 2 * 1 * 1
= 24

2. The two essential parts of recursion

Almost every recursive algorithm needs two components.

2.1 base case

The base case is a condition for which the method can return an answer immediately without making another recursive call.

In factorial:

if (n == 0) {
    return 1;
}

Without a base case, recursion does not stop.

2.2 recursive case

The recursive case reduces the original problem to a smaller problem of the same form.

return n * factorial(n - 1);

The important idea is that:

factorial(n)

depends on:

factorial(n - 1)

and n - 1 is smaller than n.

A well-designed recursive method therefore has three properties:

  1. A base case exists.
  2. Each recursive call moves toward the base case.
  3. The recursive result is used to solve the current problem.

3. A first recursive example

Consider counting down from a positive number.

public static void countdown(int n) {
    if (n == 0) {
        System.out.println("Blastoff!");
        return;
    }

    System.out.println(n);
    countdown(n - 1);
}

Calling:

countdown(3);

prints:

3
2
1
Blastoff!

The sequence of method calls is:

countdown(3)
    countdown(2)
        countdown(1)
            countdown(0)

The final call does not recurse because it satisfies the base case.

4. The call stack

To understand recursion, you need to understand the call stack.

Whenever Java calls a method, information about that method call is placed on the stack.

This information includes things such as:

  • parameter values,
  • local variables,
  • where execution should return after the method finishes.

Consider:

public static int factorial(int n) {
    if (n == 0) {
        return 1;
    }

    return n * factorial(n - 1);
}

When we call:

factorial(3)

the stack grows approximately like this:

factorial(3)
factorial(2)
factorial(1)
factorial(0)

At the deepest point:

factorial(0)

returns 1.

Then the stack begins to unwind.

factorial(1) returns 1 * 1 = 1
factorial(2) returns 2 * 1 = 2
factorial(3) returns 3 * 2 = 6

There are therefore two conceptual stages of recursion:

Descending

The program repeatedly makes smaller recursive calls.

Unwinding

The recursive calls return in reverse order.

5. Recursion before and after the recursive call

The location of code relative to the recursive call matters.

Consider:

public static void example(int n) {
    if (n == 0) {
        return;
    }

    System.out.println(n);
    example(n - 1);
}

Calling:

example(3);

prints:

3
2
1

Now move the print statement:

public static void example(int n) {
    if (n == 0) {
        return;
    }

    example(n - 1);
    System.out.println(n);
}

The result becomes:

1
2
3

Why?

In the second version, printing happens while the recursive calls are returning.

Trace:

example(3)
    example(2)
        example(1)
            example(0)
        print 1
    print 2
print 3

This ability to perform operations during the unwinding stage is one of the most powerful aspects of recursion.

6. Recursive sum

Suppose we want to calculate:

1 + 2 + 3 + ·s + n

An iterative solution is straightforward:

public static int sum(int n) {
    int total = 0;

    for (int i = 1; i <= n; i++) {
        total += i;
    }

    return total;
}

We can also define the problem recursively:

sum(n) = n + sum(n-1)

with:

sum(0) = 0

Java implementation:

public static int sum(int n) {
    if (n == 0) {
        return 0;
    }

    return n + sum(n - 1);
}

For:

sum(4)

we get:

4 + sum(3)
4 + 3 + sum(2)
4 + 3 + 2 + sum(1)
4 + 3 + 2 + 1 + sum(0)
4 + 3 + 2 + 1 + 0
10

7. Recursive thinking

Writing recursive programs requires a slightly different mindset from writing loops.

When designing an iterative solution, you often ask:

How do I perform every step?

With recursion, a more useful question is:

If I could already solve a smaller version of this problem, how could I use that solution to solve the current problem?

For example, imagine we somehow already know how to compute:

factorial(4)

Then computing:

factorial(5)

is easy:

5 * factorial(4)

You do not need to mentally work through every deeper recursive call while writing the method.

You assume that the recursive call correctly solves the smaller problem.

This assumption is sometimes called the recursive leap of faith.

8. Recursion on strings

Recursion is not limited to arithmetic.

Suppose we want to print the characters of a string one at a time.

public static void printChars(String s) {
    if (s.length() == 0) {
        return;
    }

    System.out.println(s.charAt(0));
    printChars(s.substring(1));
}

Calling:

printChars("CAT");

produces:

C
A
T

The recursive calls are:

printChars("CAT")
printChars("AT")
printChars("T")
printChars("")

The problem gets smaller because the string becomes shorter with each call.

9. Reversing a string recursively

Consider:

public static String reverse(String s) {
    if (s.length() <= 1) {
        return s;
    }

    return reverse(s.substring(1)) + s.charAt(0);
}

Calling:

reverse("DOG")

works as follows:

reverse("DOG")
= reverse("OG") + "D"

reverse("OG")
= reverse("G") + "O"

reverse("G")
= "G"

Now the calls unwind:

reverse("G") = "G"

reverse("OG")
= "G" + "O"
= "GO"

reverse("DOG")
= "GO" + "D"
= "GOD"

Notice again that the important work happens while the recursive calls return.

10. Recursion with arrays

Arrays require a slightly different approach.

A recursive method usually needs an index to indicate which portion of the array remains to be processed.

Suppose we want to calculate the sum of an array.

public static int sumArray(int[] values, int index) {
    if (index == values.length) {
        return 0;
    }

    return values[index] + sumArray(values, index + 1);
}

Given:

int[] values = {5, 8, 2};

calling:

sumArray(values, 0)

produces:

5 + sumArray(values, 1)
5 + 8 + sumArray(values, 2)
5 + 8 + 2 + sumArray(values, 3)
5 + 8 + 2 + 0
15

The array itself never gets smaller.

Instead, the remaining portion of the problem becomes smaller because the index moves forward.

11. Finding the maximum recursively

Suppose we want to find the largest element in an array.

One recursive approach is:

public static int max(int[] values, int index) {
    if (index == values.length - 1) {
        return values[index];
    }

    int maxOfRest = max(values, index + 1);

    if (values[index] > maxOfRest) {
        return values[index];
    }

    return maxOfRest;
}

Think about the statement:

int maxOfRest = max(values, index + 1);

We are saying:

Assume that the recursive method can correctly find the maximum of everything after the current position.

Then we only need to compare that answer with the current element.

This is a good example of recursive problem decomposition.

12. Recursion and searching

One particularly important recursive algorithm is binary search.

Binary search works on a sorted collection.

Suppose we have:

[3, 7, 12, 18, 25, 31, 42]

and want to find 25.

Instead of examining every element, binary search examines the middle element.

Middle:

18

Since:

25 > 18

we can ignore the entire left half.

Now search only:

[25, 31, 42]

The problem gets approximately half as large after each step.

13. Recursive binary search

A recursive implementation might look like:

public static int binarySearch(
        int[] values,
        int target,
        int low,
        int high) {

    if (low > high) {
        return -1;
    }

    int mid = low + (high - low) / 2;

    if (values[mid] == target) {
        return mid;
    }

    if (target < values[mid]) {
        return binarySearch(values, target, low, mid - 1);
    }

    return binarySearch(values, target, mid + 1, high);
}

We might call it like this:

int index = binarySearch(values, 25, 0, values.length - 1);

There are two base-case outcomes:

Target found

if (values[mid] == target) {
    return mid;
}

Search range becomes empty

if (low > high) {
    return -1;
}

The recursive call always searches a smaller interval.

14. Why binary search matters

Compare linear search and binary search.

A linear search might examine:

1 element
2 elements
3 elements
...
n elements

In the worst case, it examines all n elements.

Binary search repeatedly cuts the problem approximately in half.

For 1,000 elements:

1000
500
250
125
62
31
15
7
3
1

Only about 10 reductions are necessary.

For 1,000,000 elements, only about 20 reductions are necessary.

We will formalize this comparison using Big-O notation next week.

For now, the key observation is:

Different algorithms can solve the same problem with dramatically different amounts of work.

This is the beginning of algorithm analysis.

15. Recursion versus iteration

Many problems can be solved using either loops or recursion.

Factorial with iteration:

public static int factorialIterative(int n) {
    int result = 1;

    for (int i = 2; i <= n; i++) {
        result *= i;
    }

    return result;
}

Factorial with recursion:

public static int factorialRecursive(int n) {
    if (n == 0) {
        return 1;
    }

    return n * factorialRecursive(n - 1);
}

Both compute the same result.

The important question is not:

Which one is always better?

Instead ask:

Which one expresses the structure of this particular problem more clearly?

16. Advantages of recursion

Recursion can make certain algorithms much easier to express.

It is especially natural when the problem itself has a recursive structure.

Examples include:

  • tree traversal,
  • directory traversal,
  • divide-and-conquer algorithms,
  • binary search,
  • searching mazes,
  • processing nested structures,
  • generating permutations,
  • exploring graphs,
  • parsing programming languages.

Later in computer science, recursion appears frequently.

17. Disadvantages of recursion

Recursion also has costs.

Every recursive call requires another stack frame.

Consider:

factorial(1000000)

This creates a huge number of nested method calls.

Eventually Java will run out of call-stack space.

The program may throw:

StackOverflowError

Iteration typically uses less stack memory.

For simple repetitive calculations, a loop may therefore be preferable.

18. Infinite recursion

One of the most common recursion errors is failing to move toward the base case.

Consider:

public static void countdown(int n) {
    if (n == 0) {
        return;
    }

    System.out.println(n);
    countdown(n);
}

The recursive call is:

countdown(n);

But n never changes.

If we call:

countdown(5)

the program repeatedly calls:

countdown(5)
countdown(5)
countdown(5)
...

Eventually it crashes with a StackOverflowError.

The correct call is:

countdown(n - 1);

19. A base case can exist and still be unreachable

Consider:

public static void countdown(int n) {
    if (n == 0) {
        return;
    }

    countdown(n + 1);
}

There is technically a base case.

However, if n starts at 5, the sequence becomes:

5
6
7
8
9
...

The calls move away from the base case.

The correct question is therefore not merely:

Does the method have a base case?

You must also ask:

Does every recursive call make progress toward it?

20. Input preconditions

Consider factorial again:

public static int factorial(int n) {
    if (n == 0) {
        return 1;
    }

    return n * factorial(n - 1);
}

What happens if we call:

factorial(-3);

The sequence becomes:

factorial(-3)
factorial(-4)
factorial(-5)
...

It never reaches zero.

One solution is to validate the input:

public static int factorial(int n) {
    if (n < 0) {
        throw new IllegalArgumentException(
            "Factorial requires a nonnegative integer.");
    }

    if (n == 0) {
        return 1;
    }

    return n * factorial(n - 1);
}

This connects recursion with ideas from previous weeks about defensive programming and exceptions.

21. A common mistake: trying to follow everything at once

Students often find recursion confusing because they mentally try to execute every recursive call simultaneously.

Consider:

return n * factorial(n - 1);

A better approach when writing recursive code is:

  1. Identify the base case.
  2. Assume the recursive call works correctly for a smaller input.
  3. Determine how to use the smaller answer to solve the current problem.

For factorial:

If factorial(n - 1) correctly gives me (n - 1)!, then multiplying it by n gives me n!.

This style of reasoning becomes extremely important in data structures.

22. Recursive definitions

Many structures in computer science are naturally recursive.

A list can be thought of as:

an item followed by another list

A directory can contain:

files and other directories

A tree contains:

a node and smaller subtrees

An arithmetic expression might contain:

numbers and smaller expressions

For example:

(3 + (4 * 5))

The expression contains another expression:

(4 * 5)

Recursive data structures naturally lead to recursive algorithms.

23. Example: palindrome checking

A palindrome reads the same forward and backward.

Examples:

racecar
level
madam

Think recursively.

A string is a palindrome if:

  1. It has zero or one characters, or
  2. Its first and last characters match, and the middle portion is also a palindrome.

Java:

public static boolean isPalindrome(String s) {
    if (s.length() <= 1) {
        return true;
    }

    if (s.charAt(0) != s.charAt(s.length() - 1)) {
        return false;
    }

    return isPalindrome(
        s.substring(1, s.length() - 1)
    );
}

For:

racecar

the recursive decomposition is:

racecar
 aceca
  cec
   e

Each smaller problem has exactly the same form as the original.

24. Example: count occurrences in an array

Suppose we want to count how many times target appears.

public static int count(
        int[] values,
        int target,
        int index) {

    if (index == values.length) {
        return 0;
    }

    int countInRest =
        count(values, target, index + 1);

    if (values[index] == target) {
        return 1 + countInRest;
    }

    return countInRest;
}

For:

int[] values = {4, 7, 4, 2, 4};

calling:

count(values, 4, 0)

returns:

3

25. Example: recursive power

We want to calculate:

baseexponent

For nonnegative exponents:

x0 = 1

and:

xn = x × xn-1

Java:

public static long power(long base, int exponent) {
    if (exponent < 0) {
        throw new IllegalArgumentException(
            "Exponent must be nonnegative.");
    }

    if (exponent == 0) {
        return 1;
    }

    return base * power(base, exponent - 1);
}

Example:

power(2, 4)

2 * power(2, 3)
2 * 2 * power(2, 2)
2 * 2 * 2 * power(2, 1)
2 * 2 * 2 * 2 * power(2, 0)
2 * 2 * 2 * 2 * 1

16

26. A more efficient recursive power

There is another way to compute powers.

Suppose:

28

Instead of calculating:

2 × 2 × 2 × 2 × 2 × 2 × 2 × 2

notice:

28 = 24 × 24

and:

24 = 22 × 22

This gives the idea:

public static long fastPower(long base, int exponent) {
    if (exponent == 0) {
        return 1;
    }

    long half = fastPower(base, exponent / 2);

    if (exponent % 2 == 0) {
        return half * half;
    }

    return base * half * half;
}

This example introduces an important algorithmic principle:

A problem does not always need to become smaller by only one unit.

Sometimes we can reduce it dramatically.

This idea will appear again in divide-and-conquer algorithms.

27. Fibonacci numbers

The Fibonacci sequence begins:

0, 1, 1, 2, 3, 5, 8, 13, 21, ...

It can be defined recursively:

F(0)=0
F(1)=1
F(n)=F(n-1)+F(n-2)

A direct Java implementation is:

public static long fibonacci(int n) {
    if (n == 0) {
        return 0;
    }

    if (n == 1) {
        return 1;
    }

    return fibonacci(n - 1) + fibonacci(n - 2);
}

This code closely matches the mathematical definition.

However, it has an important problem.

28. Not all recursive solutions are efficient

Consider:

fibonacci(5)

It calls:

fibonacci(4)
fibonacci(3)

But fibonacci(4) itself calls:

fibonacci(3)
fibonacci(2)

We calculate fibonacci(3) multiple times.

The call structure resembles:

                 fib(5)
               /        \
           fib(4)       fib(3)
          /     \       /    \
      fib(3)  fib(2) fib(2) fib(1)
      ...

The same subproblems are repeatedly recomputed.

This is a crucial lesson:

A recursive solution can be correct and still be a poor algorithm.

Correctness and efficiency are separate questions.

29. Iterative fibonacci

An iterative version avoids repeated work:

public static long fibonacciIterative(int n) {
    if (n == 0) {
        return 0;
    }

    long previous = 0;
    long current = 1;

    for (int i = 2; i <= n; i++) {
        long next = previous + current;
        previous = current;
        current = next;
    }

    return current;
}

The iterative version is far more efficient than the naive recursive version.

We will develop tools for formally describing this difference in Week 11.

For now:

Elegant code is not automatically efficient code.

30. Recursion as problem decomposition

Recursion is one example of a larger idea:

Problem decomposition

Take a difficult problem and express it using smaller versions of the same problem.

For example:

sum of 10 values

can become:

first value + sum of remaining 9 values

Binary search turns:

search 1000 values

into approximately:

search 500 values

A tree problem may become:

solve the left subtree
solve the right subtree
combine the answers

Thinking in terms of smaller subproblems is one of the central ideas of algorithms.

31. A general recursive template

Many recursive methods have this structure:

public static ReturnType recursiveMethod(Input input) {

    if (baseCaseCondition) {
        return baseCaseAnswer;
    }

    Input smallerInput = makeProblemSmaller(input);

    ReturnType smallerAnswer =
        recursiveMethod(smallerInput);

    return combine(input, smallerAnswer);
}

Not every recursive method fits this exact template, but it is a useful starting point.

A second common form involves multiple recursive calls:

ReturnType left =
    recursiveMethod(smallerProblem1);

ReturnType right =
    recursiveMethod(smallerProblem2);

return combine(left, right);

This structure becomes especially important for trees and divide-and-conquer algorithms.

32. How to design a recursive method

When solving a recursive problem, use the following process.

Step 1: define exactly what the method means

For example:

sumArray(values, index)

means:

Return the sum of all array elements from index through the end of the array.

A precise method definition makes recursion much easier.

Step 2: find the smallest problem

For sumArray, the smallest remaining portion is an empty portion.

if (index == values.length) {
    return 0;
}

Step 3: make the problem smaller

Move forward one element:

sumArray(values, index + 1)

Step 4: trust the recursive call

Assume:

sumArray(values, index + 1)

correctly computes the sum of everything after the current element.

Step 5: combine the answers

return values[index] +
       sumArray(values, index + 1);

33. Tracing recursive code

When a recursive program behaves unexpectedly, trace it systematically.

Consider:

public static int mystery(int n) {
    if (n == 0) {
        return 0;
    }

    return 2 + mystery(n - 1);
}

What does:

mystery(4)

return?

Trace:

mystery(4)
= 2 + mystery(3)

= 2 + 2 + mystery(2)

= 2 + 2 + 2 + mystery(1)

= 2 + 2 + 2 + 2 + mystery(0)

= 2 + 2 + 2 + 2 + 0

= 8

The method computes:

2 × n

Tracing is an excellent way to understand unfamiliar recursive programs.

34. Another tracing exercise

Consider:

public static void mystery(int n) {
    if (n <= 0) {
        return;
    }

    System.out.print(n + " ");
    mystery(n - 2);
    System.out.print(n + " ");
}

Calling:

mystery(5);

prints:

5 3 1 1 3 5

Why?

The first print statements happen while recursion moves downward.

The second print statements happen while recursion unwinds.

35. Stack overflow

Java provides limited memory for the call stack.

A recursive method that makes too many nested calls can cause:

java.lang.StackOverflowError

For example:

public static void forever() {
    forever();
}

This method has no base case.

But even correct recursion can overflow the stack if the recursion becomes excessively deep.

For example, recursively processing millions of array elements may be unsafe.

This is one reason recursion is not always appropriate.

36. Recursion and Java memory

Recall that each method call receives its own local variables.

Consider:

public static void test(int n) {
    int x = n * 10;

    if (n > 0) {
        test(n - 1);
    }

    System.out.println(x);
}

Calling:

test(3)

creates separate x values:

test(3): x = 30
test(2): x = 20
test(1): x = 10
test(0): x = 0

When calls unwind, the output is:

0
10
20
30

Each call has its own stack frame and therefore its own version of x.

37. Recursion and object-oriented programming

Recursive methods can also appear inside classes.

For example:

public class NumberUtils {

    public static int sumDigits(int n) {
        if (n < 10) {
            return n;
        }

        return n % 10 + sumDigits(n / 10);
    }
}

Calling:

NumberUtils.sumDigits(472)

computes:

2 + sumDigits(47)

2 + 7 + sumDigits(4)

2 + 7 + 4

13

The key observations are:

n % 10

gets the last digit, while:

n / 10

removes the last digit.

Each recursive call therefore receives a smaller number.

38. Recursion and problem representation

Often, finding the right recursive solution depends on finding the right representation of the problem.

Suppose we ask:

Find the sum of an array.

A method like this is difficult to recurse on:

sumArray(int[] values)

because the array never gets smaller.

Instead, redefine the problem:

sumArray(int[] values, int index)

Now the meaning becomes:

Find the sum beginning at this position.

The index allows the remaining problem to shrink.

This is an important algorithm-design technique:

Additional parameters can describe the part of the problem that remains.

Binary search similarly uses:

low
high

to identify the current search range.

39. Helper methods

Sometimes we do not want callers to supply the extra recursive parameters.

We can hide them using a helper method.

For example:

public static int sumArray(int[] values) {
    return sumArray(values, 0);
}

private static int sumArray(
        int[] values,
        int index) {

    if (index == values.length) {
        return 0;
    }

    return values[index] +
           sumArray(values, index + 1);
}

The caller writes:

sumArray(values);

instead of:

sumArray(values, 0);

The private recursive helper handles the implementation details.

This is also an example of encapsulation.

40. Recursive binary search with a helper

We can use the same pattern for binary search:

public static int binarySearch(
        int[] values,
        int target) {

    return binarySearch(
        values,
        target,
        0,
        values.length - 1
    );
}

private static int binarySearch(
        int[] values,
        int target,
        int low,
        int high) {

    if (low > high) {
        return -1;
    }

    int mid = low + (high - low) / 2;

    if (values[mid] == target) {
        return mid;
    }

    if (target < values[mid]) {
        return binarySearch(
            values,
            target,
            low,
            mid - 1
        );
    }

    return binarySearch(
        values,
        target,
        mid + 1,
        high
    );
}

The public method offers a simple interface.

The private method contains the recursive state.

41. Recursion checklist

Before considering a recursive method complete, ask:

Correctness

  • What exactly does this method promise to compute?
  • What is the base case?
  • Is the base-case answer correct?
  • Does every recursive call make the problem smaller?
  • Will every valid input eventually reach a base case?
  • Assuming the recursive call works, does the current method compute the correct answer?

Safety

  • What inputs are valid?
  • Could invalid input cause infinite recursion?
  • Could the recursion become extremely deep?

Efficiency

  • How many recursive calls are made?
  • Does the method repeatedly solve the same subproblem?
  • Would iteration be simpler?
  • Is recursion natural for the structure of the problem?

42. Common recursive patterns

There are several recurring patterns worth recognizing.

Pattern 1: reduce by one

solve(n)
    → solve(n - 1)

Examples:

  • factorial,
  • sum from 1 to n,
  • processing an array one element at a time.

Pattern 2: reduce the input size

solve(string)
    → solve(smaller substring)

Examples:

  • reversing a string,
  • palindrome checking.

Pattern 3: divide the problem

solve(n)
    → solve(n / 2)

Examples:

  • binary search,
  • fast exponentiation.

Pattern 4: multiple recursive subproblems

solve(problem)
    → solve(part1) + solve(part2)

Examples:

  • Fibonacci,
  • tree traversal,
  • merge sort,
  • divide-and-conquer algorithms.

These patterns will recur throughout computer science.

43. Recursion is not magic

A recursive call is still just a normal method call.

The computer does not "understand recursion" as a special concept.

It simply:

  1. calls a method,
  2. creates a stack frame,
  3. executes the method,
  4. possibly calls another method,
  5. waits for that call to return,
  6. continues execution.

Recursion is powerful because the method happens to call another instance of itself.

44. Algorithmic thinking

This week is not only about learning recursive syntax.

The larger objective is learning to think algorithmically.

When given a problem, ask:

  • What is the input?
  • What is the output?
  • What special cases exist?
  • Can I break the problem into smaller subproblems?
  • What information must I keep track of?
  • What guarantees that the algorithm eventually stops?
  • How much work does the algorithm perform?
  • Are there multiple ways to solve the problem?
  • What are the tradeoffs among those solutions?

These questions are central to computer science.

45. Worked example: sum of digits

Problem:

Write a recursive method that computes the sum of the digits of a nonnegative integer.

Example:

472 → 4 + 7 + 2 → 13

First observe:

472 % 10

is:

2

and:

472 / 10

is:

47

So:

sumDigits(472)

can be expressed as:

2 + sumDigits(47)

The base case occurs when the number has only one digit.

Solution:

public static int sumDigits(int n) {
    if (n < 10) {
        return n;
    }

    return n % 10 + sumDigits(n / 10);
}

Trace:

sumDigits(472)
= 2 + sumDigits(47)

= 2 + 7 + sumDigits(4)

= 2 + 7 + 4

= 13

46. Worked example: count a character

Problem:

Count how many times a particular character occurs in a string.

Example:

"banana", 'a'

should return:

3

Solution:

public static int countChar(
        String s,
        char target) {

    if (s.isEmpty()) {
        return 0;
    }

    int countInRest =
        countChar(s.substring(1), target);

    if (s.charAt(0) == target) {
        return 1 + countInRest;
    }

    return countInRest;
}

A more compact version is:

public static int countChar(
        String s,
        char target) {

    if (s.isEmpty()) {
        return 0;
    }

    int current =
        s.charAt(0) == target ? 1 : 0;

    return current +
           countChar(s.substring(1), target);
}

47. Worked example: is an array sorted?

Problem:

Determine recursively whether an array is sorted in nondecreasing order.

For example:

[2, 5, 5, 9, 12]

is sorted.

But:

[2, 8, 4, 10]

is not.

Recursive idea:

  • Compare the current element with the next one.
  • If they are out of order, return false.
  • Otherwise ask whether the remainder of the array is sorted.
public static boolean isSorted(
        int[] values,
        int index) {

    if (index >= values.length - 1) {
        return true;
    }

    if (values[index] > values[index + 1]) {
        return false;
    }

    return isSorted(values, index + 1);
}

48. Worked example: decimal to binary

Recursion can reveal structure in number systems.

Suppose we want to print the binary representation of a positive integer.

Repeated division by 2 gives:

13 / 2 = 6 remainder 1
6  / 2 = 3 remainder 0
3  / 2 = 1 remainder 1
1  / 2 = 0 remainder 1

The remainders appear in reverse order.

Recursion naturally handles this reversal.

public static void printBinary(int n) {
    if (n < 2) {
        System.out.print(n);
        return;
    }

    printBinary(n / 2);
    System.out.print(n % 2);
}

Calling:

printBinary(13);

prints:

1101

This is a good example of using the unwinding phase of recursion.

50. In-class design exercise

Write a recursive method:

public static int product(int[] values, int index)

that returns the product of all elements from index to the end.

For:

int[] values = {2, 3, 4};

calling:

product(values, 0)

should return:

24

Think about the base case carefully.

The correct identity value for multiplication is:

1

not:

0

One solution:

public static int product(
        int[] values,
        int index) {

    if (index == values.length) {
        return 1;
    }

    return values[index] *
           product(values, index + 1);
}

51. In-class design exercise: find a value

Write a recursive method that returns whether a target exists in an array.

public static boolean contains(
        int[] values,
        int target,
        int index)

One solution:

public static boolean contains(
        int[] values,
        int target,
        int index) {

    if (index == values.length) {
        return false;
    }

    if (values[index] == target) {
        return true;
    }

    return contains(
        values,
        target,
        index + 1
    );
}

Notice that this method can stop early as soon as it finds the target.

52. Recursion vs. loops: practical guidelines

Prefer a loop when:

  • the operation is naturally repetitive,
  • the data structure is linear,
  • recursion adds no conceptual clarity,
  • very deep recursion might occur.

Consider recursion when:

  • the problem is naturally defined in terms of smaller versions of itself,
  • the data structure is recursive,
  • the problem divides into subproblems,
  • the recursive formulation closely matches the conceptual solution.

Neither technique is inherently superior.

Good programmers know both.

53. Preview: why recursion matters for data structures

Next we will study algorithms and data structures in greater depth.

Recursion will become particularly useful for trees.

Imagine a binary tree:

        8
       / \
      3   10
     / \    \
    1   6    14

To process the entire tree, we can think recursively:

process current node
process left subtree
process right subtree

Each subtree is itself another tree.

That is why recursion is such a natural fit.

You do not need to understand trees yet. The important point is that recursive programming is preparation for the data structures that follow.

54. Summary

The central ideas from this week are:

Recursion

A recursive method calls itself on a smaller version of the problem.

Base case

The condition that stops recursion.

Recursive case

The part of the method that reduces the problem.

Progress

Every recursive call must move toward a base case.

Call stack

Each recursive call creates a separate method invocation that waits for deeper calls to return.

Unwinding

After the base case returns, pending recursive calls complete in reverse order.

Recursive thinking

Assume the smaller recursive problem can be solved correctly, then determine how its result helps solve the current problem.

Algorithmic thinking

Different correct solutions may require very different amounts of computational work.

60. Takeaway

The most important idea from recursion is not the syntax of calling a method from itself.

It is this:

A difficult problem can often be solved by reducing it to one or more smaller instances of the same problem.

That principle is one of the foundations of algorithms, data structures, and computer science.
