Part I - abstract data types

3. What is an abstract data type?

An Abstract Data Type (ADT) specifies:

  • what kind of data is stored,
  • what operations are supported,
  • and what those operations mean.

An ADT does not necessarily specify how those operations are implemented.

Consider a stack.

A stack supports operations such as:

push
pop
peek
isEmpty

This describes the behavior of a stack.

It does not tell us whether the stack is implemented using:

  • an array,
  • an ArrayList,
  • a linked list,
  • or some other representation.

That distinction is extremely important.

Adt versus implementation

For example:

Stack ADT
    |
    +-- Array implementation
    |
    +-- ArrayList implementation
    |
    +-- Linked-list implementation

All three implementations can behave like stacks.

The user of the stack does not necessarily need to know which implementation is being used.

This is another example of abstraction, a concept we have repeatedly encountered in object-oriented programming.

Part II - stacks

4. The stack adt

A stack is a collection in which elements are removed in the reverse order from which they were added.

This behavior is called:

Last In, First Out (LIFO)

Imagine a stack of plates.

If we place plates onto the top:

      C   <- top
      B
      A

the first plate we remove is C.

Then:

      B   <- top
      A

Then:

      A   <- top

The last item inserted is the first item removed.

5. Core stack operations

A stack typically provides the following operations.

Add an item to the top of the stack.

Return the top item without removing it.

peek()

If the stack contains:

peek()

returns:

C

isEmpty

Determines whether the stack contains any elements.

isEmpty()

7. Why are stacks useful?

Stacks occur naturally whenever the most recently created task must be handled first.

Examples include:

  • method calls,
  • recursion,
  • undo operations,
  • browser navigation,
  • expression evaluation,
  • syntax checking,
  • depth-first search,
  • backtracking algorithms.

8. The call stack

You have already been using stacks throughout this course.

Whenever Java calls a method, information about that method call is stored on the call stack.

Consider:

public static void main(String[] args) {
    methodA();
}

public static void methodA() {
    methodB();
}

public static void methodB() {
    System.out.println("Hello");
}

The call stack evolves approximately as follows.

First:

main

Then main calls methodA:

methodA
main

Then methodA calls methodB:

methodB
methodA
main

When methodB finishes:

methodA
main

Then methodA finishes:

main

Finally main finishes.

This is why recursion naturally works using a stack.

Each recursive call creates another stack frame.

9. Using a stack in Java

Java provides several ways of implementing stack behavior.

An older Java class called Stack exists:

Stack<Integer> stack = new Stack<>();

However, modern Java generally prefers using the Deque interface.

For example:

import java.util.ArrayDeque;
import java.util.Deque;

public class StackDemo {
    public static void main(String[] args) {

        Deque<Integer> stack = new ArrayDeque<>();

        stack.push(10);
        stack.push(20);
        stack.push(30);

        System.out.println(stack.pop());
        System.out.println(stack.peek());
    }
}

Output:

30
20

Notice the declaration:

Deque<Integer> stack = new ArrayDeque<>();

This uses an interface type for the variable and a concrete implementation for the object.

That is an example of programming to an abstraction.

10. Example: reverse a string using a stack

A stack naturally reverses order.

Suppose we want to reverse:

computer

Push every character:

c
o
m
p
u
t
e
r

Because the last character pushed is removed first, popping all characters produces:

retupmoc

Java implementation:

import java.util.ArrayDeque;
import java.util.Deque;

public class ReverseString {

    public static String reverse(String text) {

        Deque<Character> stack = new ArrayDeque<>();

        for (char c : text.toCharArray()) {
            stack.push(c);
        }

        StringBuilder result = new StringBuilder();

        while (!stack.isEmpty()) {
            result.append(stack.pop());
        }

        return result.toString();
    }

    public static void main(String[] args) {
        System.out.println(reverse("computer"));
    }
}

Output:

retupmoc

11. Example: matching parentheses

Stacks are useful for determining whether brackets are correctly nested.

Consider:

((a + b) * c)

This is valid.

But:

((a + b) * c

is not.

Consider something more complicated:

{ [ (a + b) * c ] + d }

To check the expression:

  1. When we encounter an opening symbol, push it.
  2. When we encounter a closing symbol, pop the corresponding opening symbol.
  3. If the symbols do not match, the expression is invalid.
  4. At the end, the stack should be empty.

For example:

Input:

{ [ ( ) ] }

Trace:

Read {    stack: {

Read [    stack: [
                   {

Read (    stack: (
                   [
                   {

Read )    pop (

Read ]    pop [

Read }    pop {

stack is empty

Therefore the brackets are balanced.

Part III - queues

12. The queue adt

A queue stores elements in the order in which they arrive.

A queue follows:

First In, First Out (FIFO)

Think about people waiting in line.

Suppose:

Alice arrives
Bob arrives
Carol arrives

The queue is:

Front                      Back
Alice   Bob   Carol

Alice is served first.

Then:

Front                Back
Bob   Carol

15. Queue applications

Queues appear whenever tasks should generally be handled in arrival order.

Examples include:

  • printer jobs,
  • customer-service requests,
  • web-server requests,
  • event processing,
  • operating-system scheduling,
  • breadth-first search,
  • simulations,

16. Using a queue in Java

The Java Collections Framework provides the Queue interface.

A common implementation is ArrayDeque.

import java.util.Queue;

        customers.offer("Alice");

        customers.offer("Carol");

Bob

Here:

adds an item.

poll()

removes the front item.

peek()

examines the front item.

Part IV - sets

18. The set adt

A set is a collection that does not contain duplicate elements.

Mathematically:

{1, 2, 3}

is a set.

Adding 2 again does not produce:

{1, 2, 2, 3}

The set remains:

{1, 2, 3}

19. Why use a set?

Suppose we are storing usernames that have visited a website:

alice
bob
alice
carol
bob
david

If we only care about unique visitors, the relevant collection is:

alice
bob
carol
david

A set naturally represents this concept.

20. Java HashSet

Java provides the Set interface.

A common implementation is:

HashSet

Example:

import java.util.HashSet;

    public static void main(String[] args) {

        names.add("Bob");

        names.add("Alice");

Although we inserted "Alice" twice, only one copy is stored.

22. Example: detecting duplicates

Suppose we want to determine whether an array contains duplicate values.

A simple nested-loop solution might take:

O(n²)

time.

Using a hash set, we can often solve the problem in expected:

O(n)

time.

import java.util.HashSet;
import java.util.Set;

public class DuplicateDetector {

    public static boolean containsDuplicate(int[] numbers) {

        Set<Integer> seen = new HashSet<>();

        for (int value : numbers) {

            if (seen.contains(value)) {
                return true;
            }

            seen.add(value);
        }

        return false;
    }
}

The key idea is:

Have I already seen this element?

A set answers exactly that question.

Part V - maps

24. The map adt

A map associates one value with another.

Each entry contains:

key -> value

For example:

student ID -> student name

or:

word -> frequency

or:

username -> password hash

or:

state -> capital

For example:

"Colorado" -> "Denver"
"Florida"  -> "Tallahassee"
"Texas"    -> "Austin"

25. Keys are unique

A map associates each key with at most one value.

Consider:

Alice -> 90
Bob   -> 85
Carol -> 95

If we later do:

Alice -> 100

the value associated with Alice changes.

We do not create another independent Alice entry.

95

28. Example: phone directory

A map is ideal when we want to look up information using some key.

Map<String, String> phoneBook = new HashMap<>();

phoneBook.put("Alice", "555-1234");
phoneBook.put("Bob", "555-9876");
phoneBook.put("Carol", "555-4321");

We can retrieve Alice's number with:

phoneBook.get("Alice");

There is no need to scan the entire collection manually.

29. Example: word frequency

Suppose we have:

the cat chased the dog

We want:

the     -> 2
cat     -> 1
chased  -> 1
dog     -> 1

A map is ideal.

import java.util.HashMap;
import java.util.Map;

public class WordFrequency {

    public static void main(String[] args) {

        String text = "the cat chased the dog";

        String[] words = text.split(" ");

        Map<String, Integer> counts = new HashMap<>();

        for (String word : words) {

            if (counts.containsKey(word)) {
                counts.put(word, counts.get(word) + 1);
            } else {
                counts.put(word, 1);
            }
        }

        System.out.println(counts);
    }
}

We can simplify this using:

getOrDefault()
for (String word : words) {
    counts.put(word, counts.getOrDefault(word, 0) + 1);
}

This pattern is extremely common.

30. Iterating through a map

Suppose:

Map<String, Integer> scores = new HashMap<>();

We can iterate through the keys:

for (String name : scores.keySet()) {
    System.out.println(name);
}

Or through both keys and values:

for (Map.Entry<String, Integer> entry : scores.entrySet()) {

    System.out.println(
        entry.getKey() + ": " + entry.getValue()
    );
}

Part VI - hashing

31. The lookup problem

Suppose we have 1,000,000 usernames.

We want to determine:

Does "alice42" exist?

If we store usernames in an ordinary list, we may have to search through many elements.

Linear search requires:

O(n)

time.

Can we do better?

Hash-based data structures attempt to make lookup approximately:

O(1)

on average.

34. Collisions

A complication occurs when two keys map to the same location.

Suppose:

hash("Alice") % 10 = 3

and:

hash("David") % 10 = 3

Both want position 3.

This is called a collision.

Hash tables therefore need a strategy for resolving collisions.

Common approaches include:

  • chaining,
  • open addressing.

We will not implement a full production-quality hash table in this course, but you should understand that collisions are normal and must be handled correctly.

35. Expected complexity of hash tables

For a well-designed hash table, operations such as:

put
get
contains
remove

are typically expected to take:

O(1)

time on average.

However, this is not a guarantee that every operation always requires constant time.

In pathological situations involving many collisions, operations may become slower.

For CSC500, remember:

HashSet membership: expected O(1)

HashMap lookup: expected O(1)

36. Why equals() and hashCode() matter

Java objects used as hash keys rely on two important methods:

equals()

and:

hashCode()

Conceptually:

  • hashCode() helps determine where an object should be stored.
  • equals() determines whether two keys should be considered equal.

An important Java rule is:

If two objects are equal according to equals(), they must produce the same hash code.

This becomes especially important when you create your own classes and use instances of those classes in a HashSet or as keys in a HashMap.

Part VII - choosing the right data structure

37. Data structure selection

An important programming skill is deciding which structure best fits a problem.

Do not simply choose whichever structure you remember first.

Ask:

What operations matter most?

Scenario 1

You need an undo system.

The most recent action should be undone first.

Use:

Stack

because the behavior is LIFO.

Scenario 2

Customers should be served in arrival order.

Use:

Queue

because the behavior is FIFO.

Scenario 3

You want to know whether a username has already appeared.

Use:

Set

because you care about membership and uniqueness.

Scenario 4

You want to look up a student's GPA using their student ID.

Use:

Map

because you want:

student ID -> GPA

Scenario 5

You need elements in index order and frequently access:

values.get(i)

Use:

ArrayList

rather than a set, queue, or stack.

Part VIII - worked problems

40. Problem: valid parentheses

Given a string containing:

(
)
[
]
{
}

determine whether the brackets are correctly balanced.

Examples:

([]{})

is valid.

([)]

is not valid.

Solution strategy

Use a stack.

Whenever we see:

(
[
{

push it.

Whenever we see:

)
]
}

check whether the top of the stack contains the matching opening symbol.

Java solution

import java.util.ArrayDeque;
import java.util.Deque;

public class BalancedBrackets {

    public static boolean isBalanced(String text) {

        Deque<Character> stack = new ArrayDeque<>();

        for (char c : text.toCharArray()) {

            if (c == '(' || c == '[' || c == '{') {

                stack.push(c);

            } else if (c == ')' || c == ']' || c == '}') {

                if (stack.isEmpty()) {
                    return false;
                }

                char opening = stack.pop();

                if (c == ')' && opening != '(') {
                    return false;
                }

                if (c == ']' && opening != '[') {
                    return false;
                }

                if (c == '}' && opening != '{') {
                    return false;
                }
            }
        }

        return stack.isEmpty();
    }
}

Part IX - deeper conceptual connections

44. Stack and recursion

Consider:

public static void countdown(int n) {

    if (n == 0) {
        return;
    }

    System.out.println(n);

    countdown(n - 1);
}

Calling:

countdown(3);

creates calls approximately like:

countdown(3)
countdown(2)
countdown(1)
countdown(0)

These are stacked on the call stack.

This means recursion and explicit stack-based algorithms are closely related.

Many recursive algorithms can be rewritten using an explicit stack.

45. Queues and breadth-first processing

Suppose tasks generate additional tasks.

A queue allows us to process them in discovery order.

This idea is the foundation of breadth-first search, an algorithm you will encounter again in data structures and algorithms courses.

Conceptually:

place starting item in queue

while queue not empty:
    remove next item
    process it
    add newly discovered items

Notice how the queue determines the order in which work happens.

46. Maps as indexes

A map can be thought of as an index.

Suppose we have:

class Student {
    private int id;
    private String name;
}

If students are stored in a list:

List<Student> students;

finding student 12345 might require scanning the list.

Instead we could maintain:

Map<Integer, Student> studentsById;

Then:

studentsById.get(12345);

directly expresses what we want.

This is a powerful general programming technique:

Organize data according to how you need to retrieve it.

Part X - common mistakes

47. Mistake: using a stack when you need a queue

Suppose jobs arrive:

A
B
C

If fairness requires processing:

A
B
C

then a stack is incorrect.

A stack would produce:

C
B
A

Always identify whether the problem requires:

LIFO

or:

FIFO

48. Mistake: assuming HashSet preserves insertion order

A HashSet does not promise that iteration will occur in insertion order.

This code:

Set<String> values = new HashSet<>();

values.add("A");
values.add("B");
values.add("C");

should not be interpreted as promising that iteration will always print:

A B C

If ordering matters, another data structure may be more appropriate.

49. Mistake: assuming HashMap keys are sorted

A HashMap does not keep its keys sorted.

If you need ordering, Java provides alternatives such as:

TreeMap

but our focus this week is HashMap.

50. Mistake: confusing containsKey() and containsValue()

Suppose:

Map<String, Integer> ages = new HashMap<>();

ages.put("Alice", 30);

Then:

ages.containsKey("Alice")

is:

true

while:

ages.containsValue(30)

is also:

true

These answer completely different questions.

51. Mistake: forgetting that get() may return null

Consider:

scores.get("David");

If "David" is not present, get() may return null.

Therefore you may need:

containsKey()

or:

getOrDefault()

depending on the problem.

Part XIV - summary

This week introduced four extremely important abstract data types.

Stack

A stack follows:

LIFO

Typical operations:

push
pop
peek

Common applications include:

  • recursion,
  • undo,
  • backtracking,
  • expression processing.

Queue

A queue follows:

FIFO

Typical operations:

offer
poll
peek

Common applications include:

  • scheduling,
  • request processing,
  • simulations,
  • breadth-first algorithms.

Set

A set stores unique elements.

Typical operations include:

add
remove
contains

A HashSet provides expected constant-time membership testing.

Map

A map stores:

key -> value

associations.

Typical operations include:

put
get
containsKey
remove

A HashMap provides expected constant-time lookup by key.

52. The most important idea

The most important idea from this week is not memorizing Java collection methods.

It is learning to ask:

What behavior does my program need from its data?

If you need:

most recent item first

think:

Stack

If you need:

oldest item first

think:

Queue

If you need:

Have I seen this before?

think:

Set

If you need:

Given this key, what value is associated with it?

think:

Map

Choosing the right data structure often turns a complicated program into a simple one.

Maintain:

Map<String, Set<Integer>>

where the value contains the line numbers where each word occurs.
