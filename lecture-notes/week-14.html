1. Why study trees?

Until now, most of the data structures we have studied have been linear.

Examples include:

  • Arrays
  • ArrayLists
  • Linked lists
  • Stacks
  • Queues

These structures organize data in a sequence.

For example:

10 → 20 → 30 → 40

Each item has a clear position before or after another item.

Many real-world problems, however, are not naturally linear.

Consider:

  • A computer file system
  • An organizational chart
  • A family tree
  • A university course prerequisite structure
  • The HTML elements in a web page
  • Categories and subcategories in an online store

These structures are naturally hierarchical.

A tree is a data structure designed to represent hierarchical relationships.

2. A first example of a tree

Consider the following structure:

          50
        /    \
      30      70
     /  \    /  \
   20   40  60   80

This structure contains seven values.

Unlike a linked list, one element may connect to multiple elements.

The value 50 is at the top.

Below it are 30 and 70.

Below 30 are 20 and 40.

Below 70 are 60 and 80.

This particular tree is called a binary tree because each node has at most two children.

3. Basic tree terminology

Trees have their own vocabulary.

Consider:

          A
        /   \
       B     C
      / \     \
     D   E     F

Node

Each element in the tree is called a node.

The nodes above are:

A, B, C, D, E, F

A node usually stores:

  1. Some data
  2. References to other nodes

Edge

A connection between two nodes is called an edge.

For example:

A → B
A → C
B → D
B → E
C → F

Root

The top node is called the root.

In this tree:

A

is the root.

A tree has exactly one root.

Parent

If one node directly connects downward to another node, the first node is the parent.

For example:

B

is the parent of:

D and E

Child

A node directly below another node is called a child.

For example:

B and C

are children of A.

Siblings

Nodes with the same parent are called siblings.

For example:

B and C

are siblings.

Similarly:

D and E

are siblings.

Leaf

A node with no children is called a leaf node.

In our example:

D
E
F

are leaves.

Internal node

A node that has at least one child is sometimes called an internal node.

In our example:

A
B
C

are internal nodes.

4. Subtrees

Every node in a tree can itself be considered the root of a smaller tree.

For example:

          A
        /   \
       B     C
      / \
     D   E

The tree rooted at B is:

      B
     / \
    D   E

This is called a subtree of the original tree.

This idea is extremely important.

A tree is naturally recursive:

A tree consists of a node whose children are themselves trees.

This is why recursion is so commonly used when working with trees.

5. Depth

The depth of a node is the number of edges between the root and that node.

Example:

          A
        /   \
       B     C
      /
     D

The depths are:

A: depth 0
B: depth 1
C: depth 1
D: depth 2

The root always has depth 0.

6. Height

The height of a tree is the length of the longest path from the root to a leaf.

For example:

          A
        /   \
       B     C
      /
     D
    /
   E

The longest root-to-leaf path is:

A → B → D → E

There are three edges.

Therefore:

height = 3

Height matters because the performance of many tree algorithms depends on it.

7. Binary trees

A binary tree is a tree in which every node has at most two children.

The children are usually called:

  • left child
  • right child

Example:

        10
       /  \
      5    20

A node might have:

  • zero children
  • one child
  • two children

All are valid in a binary tree.

8. Representing a binary tree in Java

A binary tree can be represented using objects.

A simple node class might look like this:

class TreeNode {
    int value;
    TreeNode left;
    TreeNode right;

    TreeNode(int value) {
        this.value = value;
        this.left = null;
        this.right = null;
    }
}

Each TreeNode contains:

int value;

which stores the data.

It also contains:

TreeNode left;
TreeNode right;

which are references to other nodes.

        50

10. Binary tree vs. binary search tree

These terms are related but not equivalent.

A binary tree only requires:

Each node has at most two children.

For example:

       50
      /  \
    100   12

This is a valid binary tree.

However, it is not a binary search tree.

11. Binary search trees

A binary search tree, or BST, is a binary tree with an additional ordering property.

For every node:

values in left subtree < node value
values in right subtree > node value

For example:

           50
         /    \
       30      70
      /  \    /  \
    20   40  60   80

This is a binary search tree.

For the root 50:

20, 30, 40 < 50

and:

60, 70, 80 > 50

The same property is true recursively for every node.

12. Why the bst property is useful

Suppose we want to find 60.

Start at:

50

Compare:

60 > 50

Therefore, we know that 60, if it exists, must be in the right subtree.

Move to:

70

Now:

60 < 70

Therefore move left.

We reach:

60

The value has been found.

Notice that we did not examine:

20
30
40
80

The ordering of the tree allowed us to eliminate entire portions of the data.

This is similar to the idea behind binary search on a sorted array.

13. Searching a binary search tree

A recursive search method can be written as:

public static boolean contains(TreeNode node, int target) {

    if (node == null) {
        return false;
    }

    if (target == node.value) {
        return true;
    }

    if (target < node.value) {
        return contains(node.left, target);
    } else {
        return contains(node.right, target);
    }
}

There are three main cases.

Case 1: the node is null

if (node == null) {
    return false;
}

This means we reached an empty part of the tree.

The target does not exist.

Case 2: we found the target

if (target == node.value) {
    return true;
}

Search is complete.

Case 3: decide which subtree to search

if (target < node.value) {
    return contains(node.left, target);
}

Otherwise:

return contains(node.right, target);

We search only one subtree.

14. Tracing bst search

Consider:

           50
         /    \
       30      70
      /  \    /  \
    20   40  60   80

Search for:

40

Step 1:

40 < 50

Go left.

Step 2:

40 > 30

Go right.

Step 3:

40 == 40

Found.

Only three nodes were examined.

15. Iterative search

Search can also be implemented without recursion.

public static boolean contains(TreeNode root, int target) {

    TreeNode current = root;

    while (current != null) {

        if (target == current.value) {
            return true;
        }

        if (target < current.value) {
            current = current.left;
        } else {
            current = current.right;
        }
    }

    return false;
}

Both recursive and iterative implementations are reasonable.

Tree algorithms are frequently written recursively because the recursive structure of the code matches the recursive structure of the tree.

16. Inserting into a binary search tree

Suppose we have:

          50
        /    \
      30      70

We want to insert:

40

Compare 40 with 50.

40 < 50

Go left.

Now compare with 30.

40 > 30

Go right.

The right child is empty.

Therefore insert 40 there.

Result:

          50
        /    \
      30      70
        \
         40

17. Recursive bst insertion

One implementation is:

public static TreeNode insert(TreeNode node, int value) {

    if (node == null) {
        return new TreeNode(value);
    }

    if (value < node.value) {
        node.left = insert(node.left, value);
    } else if (value > node.value) {
        node.right = insert(node.right, value);
    }

    return node;
}

Notice the base case:

if (node == null)

We have found the location where the new value belongs.

19. Balanced trees

Consider this BST:

           50
         /    \
       30      70
      /  \    /  \
    20   40  60   80

Its height is small relative to the number of nodes.

We informally call such a tree balanced.

Compare that with:

20
  \
   30
     \
      40
        \
         50
           \
            60

This tree is highly unbalanced.

Why does this matter?

Because tree height determines how many nodes we may need to visit.

20. Time complexity of bst search

Suppose a balanced BST contains approximately one million elements.

A well-balanced search tree might require only around:

log₂(1,000,000) ≈ 20

comparisons.

Thus, search is approximately:

O(log n)

when the tree is balanced.

21. Worst-case bst performance

If a BST becomes completely unbalanced:

10
  \
   20
     \
      30
        \
         40

searching could require visiting every node.

Worst-case complexity becomes:

O(n)

Therefore:

Balanced BST:
search ≈ O(log n)

Highly unbalanced BST:
search ≈ O(n)

The same general idea applies to insertion.

22. Tree traversal

Sometimes we do not want to search for one value.

Instead, we want to visit every node.

Visiting every node in a tree is called tree traversal.

Several traversal orders are common.

For binary trees, the three classic depth-first traversals are:

  1. Preorder
  2. Inorder
  3. Postorder

23. Inorder traversal

The inorder traversal visits nodes in this order:

LEFT
NODE
RIGHT

Consider:

           50
         /    \
       30      70
      /  \    /  \
    20   40  60   80

The inorder traversal is:

20 30 40 50 60 70 80

Notice something important:

Inorder traversal of a binary search tree visits values in sorted order.

24. Recursive inorder traversal

public static void inorder(TreeNode node) {

    if (node == null) {
        return;
    }

    inorder(node.left);

    System.out.println(node.value);

    inorder(node.right);
}

This code is remarkably short.

The recursive structure of the algorithm mirrors the structure of the tree.

Consider:

      30

Calling:

inorder(node);

26. Preorder traversal

Preorder traversal visits:

NODE
LEFT
RIGHT

For:

           50
         /    \
       30      70
      /  \    /  \
    20   40  60   80

the result is:

50 30 20 40 70 60 80

Implementation:

public static void preorder(TreeNode node) {

    if (node == null) {
        return;
    }

    System.out.println(node.value);

    preorder(node.left);
    preorder(node.right);
}

27. Postorder traversal

Postorder traversal visits:

LEFT
RIGHT
NODE

For the same tree:

           50
         /    \
       30      70
      /  \    /  \
    20   40  60   80

the result is:

20 40 30 60 80 70 50

Implementation:

public static void postorder(TreeNode node) {

    if (node == null) {
        return;
    }

    postorder(node.left);
    postorder(node.right);

    System.out.println(node.value);
}

28. Comparing traversals

A useful way to remember the three traversals is to ask:

When do we process the current node?

Preorder

NODE
left
right

The node is processed before its subtrees.

Inorder

left
NODE
right

The node is processed between its subtrees.

Postorder

left
right
NODE

The node is processed after its subtrees.

29. Why different traversals exist

Different traversal orders are useful for different problems.

Inorder

Useful for:

  • printing BST values in sorted order
  • processing values according to BST ordering

Preorder

Useful for:

  • copying tree structure
  • serializing certain tree representations
  • processing a parent before its children

Postorder

Useful for:

  • deleting a tree
  • computing properties from child nodes
  • processing children before their parent

30. Recursive tree problems

Many useful tree algorithms follow the same general pattern:

public static ReturnType solve(TreeNode node) {

    if (node == null) {
        return baseValue;
    }

    ReturnType leftResult = solve(node.left);
    ReturnType rightResult = solve(node.right);

    return combine(node, leftResult, rightResult);
}

This pattern appears repeatedly in computer science.

31. Counting nodes

Suppose we want to count the number of nodes in a tree.

Conceptually:

number of nodes =
1
+ number of nodes in left subtree
+ number of nodes in right subtree

Implementation:

public static int countNodes(TreeNode node) {

    if (node == null) {
        return 0;
    }

    return 1
        + countNodes(node.left)
        + countNodes(node.right);
}

32. Counting leaves

A leaf has:

node.left == null

and:

node.right == null

Implementation:

public static int countLeaves(TreeNode node) {

    if (node == null) {
        return 0;
    }

    if (node.left == null && node.right == null) {
        return 1;
    }

    return countLeaves(node.left)
        + countLeaves(node.right);
}

33. Finding the sum of all values

public static int sum(TreeNode node) {

    if (node == null) {
        return 0;
    }

    return node.value
        + sum(node.left)
        + sum(node.right);
}

Again:

sum of tree =
root value
+ sum of left subtree
+ sum of right subtree

34. Finding the height

We can define the height recursively.

One common definition is:

public static int height(TreeNode node) {

    if (node == null) {
        return -1;
    }

    int leftHeight = height(node.left);
    int rightHeight = height(node.right);

    return 1 + Math.max(leftHeight, rightHeight);
}

Why -1 for an empty tree?

Because then a leaf has height:

1 + max(-1, -1)
= 0

which matches the definition that a leaf has height zero.

Some textbooks use slightly different height conventions.

The important thing is to be consistent.

35. Finding minimum and maximum in a bst

Because of the BST ordering property:

The smallest value is the leftmost node.

For example:

           50
         /    \
       30      70
      /
    20

Minimum:

20

Implementation:

public static int findMin(TreeNode root) {

    if (root == null) {
        throw new IllegalArgumentException("Tree is empty");
    }

    TreeNode current = root;

    while (current.left != null) {
        current = current.left;
    }

    return current.value;
}

Similarly:

The maximum value is the rightmost node.

36. Removing values from a bst

Deletion from a BST is more complicated than insertion.

There are three cases.

Suppose we want to remove a node.

Case 1: the node is a leaf

Example:

    30
   /
 20

Removing 20 is easy.

Simply remove the reference.

Case 2: the node has one child

Example:

    30
      \
       40

If we remove 30, its child 40 can take its place.

Case 3: the node has two children

Example:

      30
     /  \
   20    40

This is more complicated.

We typically replace the node with either:

  • the largest value in its left subtree, or
  • the smallest value in its right subtree

These are called the:

inorder predecessor

and:

inorder successor

respectively.

For CSC500, understanding the three cases is more important than memorizing the full deletion implementation.

37. A more complete bst class

Instead of exposing raw TreeNode objects to users of our code, we can create a class representing the entire data structure.

public class BinarySearchTree {

    private TreeNode root;

    public BinarySearchTree() {
        root = null;
    }

    public void add(int value) {
        root = insert(root, value);
    }

    private TreeNode insert(TreeNode node, int value) {

        if (node == null) {
            return new TreeNode(value);
        }

        if (value < node.value) {
            node.left = insert(node.left, value);
        } else if (value > node.value) {
            node.right = insert(node.right, value);
        }

        return node;
    }

    public boolean contains(int value) {
        return contains(root, value);
    }

    private boolean contains(TreeNode node, int value) {

        if (node == null) {
            return false;
        }

        if (value == node.value) {
            return true;
        }

        if (value < node.value) {
            return contains(node.left, value);
        }

        return contains(node.right, value);
    }
}

This demonstrates an important object-oriented design principle:

Hide implementation details behind a public interface.

Users of BinarySearchTree do not need to manipulate nodes directly.

They simply call:

BinarySearchTree tree = new BinarySearchTree();

tree.add(50);
tree.add(30);
tree.add(70);

System.out.println(tree.contains(30));

38. Abstract data types revisited

Recall the distinction between an abstract data type and an implementation.

An abstract data type describes:

What operations are available?

An implementation describes:

How are those operations carried out?

For example, a Set might provide:

remove
contains

A set could potentially be implemented using:

  • a list
  • a hash table
  • a binary search tree

The user does not necessarily need to know which implementation is being used.

40. Treeset vs. HashSet

We previously encountered:

HashSet

Now consider:

TreeSet

Both implement the general Set abstraction.

But they make different tradeoffs.

HashSet

Typical:

add:      O(1)
contains: O(1)
remove:   O(1)

Elements are not maintained in sorted order.

Treeset

Typical:

add:      O(log n)
contains: O(log n)
remove:   O(log n)

Elements are maintained in sorted order.

Therefore:

There is rarely one "best" data structure.

The correct structure depends on what operations the program needs.

41. Treemap vs. HashMap

HashMap

and:

A TreeMap is useful when keys must remain sorted.

42. Another important tree: the heap

A heap is another type of binary tree.

However, it follows a different rule than a binary search tree.

A common type is a min-heap.

In a min-heap:

Every parent is less than or equal to its children.

Example:

          10
        /    \
      20      15
     /  \    /
   40   30  25

Notice:

10 < 20
10 < 15

20 < 40
20 < 30

15 < 25

However, this is not a BST.

For example, 15 appears on the right of 10, which is fine, but the entire tree does not follow BST ordering between arbitrary subtrees.

43. Min-heaps

A min-heap provides very quick access to the smallest element.

The smallest element is always at the root.

          5
        /   \
      10     8
     / \
   20   15

Minimum:

5

A max-heap works in the opposite direction.

The largest value appears at the root.

44. Priority queues

A heap is commonly used to implement a priority queue.

A normal queue follows:

first in, first out

A priority queue instead removes the element with the highest priority.

Example:

Suppose an emergency room contains patients with priorities:

Patient A: priority 4
Patient B: priority 1
Patient C: priority 3
Patient D: priority 2

The patients would not necessarily be processed according to arrival order.

They would be processed according to priority.

45. Java priorityqueue

Java provides:

PriorityQueue

Example:

import java.util.PriorityQueue;

PriorityQueue<Integer> pq = new PriorityQueue<>();

pq.add(40);
pq.add(10);
pq.add(30);
pq.add(20);

System.out.println(pq.remove());
System.out.println(pq.remove());
System.out.println(pq.remove());
System.out.println(pq.remove());

Output:

10
20
30
40

By default, Java's PriorityQueue behaves like a min-priority queue.

46. Priority queue complexity

A typical heap-based priority queue provides:

peek minimum: O(1)

insert:       O(log n)

remove min:   O(log n)

This makes heaps particularly useful when we repeatedly need to determine the smallest or largest item.

47. Bst vs. heap

Students sometimes confuse BSTs and heaps because both can be represented as binary trees.

They solve different problems.

Binary search tree

Designed primarily for:

searching for arbitrary values
maintaining sorted ordering

Typical balanced complexity:

search: O(log n)
insert: O(log n)

Heap

Designed primarily for:

quickly finding the smallest or largest element

Typical:

find min: O(1)
insert: O(log n)
remove min: O(log n)

Searching a heap for an arbitrary value is generally not efficient.

50. The importance of operations

When selecting a data structure, identify which operations matter.

Possible operations include:

insert
delete
search
access by index
find minimum
find maximum
iterate in sorted order
process oldest item
process newest item

Different data structures optimize different operations.

This idea is fundamental to computer science.

51. Common misconception: trees are always faster

Trees are not automatically faster than arrays or lists.

For example, suppose you have only five values.

The difference between:

O(n)

and:

O(log n)

may be irrelevant.

Tree structures also involve:

  • extra object references
  • more complex code
  • additional memory
  • potentially poor cache behavior

Data structures involve tradeoffs.

52. Common misconception: every binary tree is a bst

False.

This is a binary tree:

      10
     /  \
   100   3

But it is not a binary search tree.

A BST must satisfy the ordering property.

53. Common misconception: a bst is always o(log n)

False.

A balanced BST gives approximately:

O(log n)

search.

But an unbalanced tree can become:

O(n)

Example:

 \
  20

54. Common misconception: tree traversals are sorting algorithms

Inorder traversal of a BST produces values in sorted order.

However, the traversal itself did not sort the values.

The ordering was already established when the BST was constructed.

The traversal simply visits nodes according to that ordering.

64. Week 14 programming example

Below is a small complete BST implementation.

public class BinarySearchTree {

    private static class TreeNode {

        int value;
        TreeNode left;
        TreeNode right;

        TreeNode(int value) {
            this.value = value;
        }
    }

    private TreeNode root;

    public void add(int value) {
        root = add(root, value);
    }

    private TreeNode add(TreeNode node, int value) {

        if (node == null) {
            return new TreeNode(value);
        }

        if (value < node.value) {
            node.left = add(node.left, value);
        } else if (value > node.value) {
            node.right = add(node.right, value);
        }

        return node;
    }

    public boolean contains(int value) {
        return contains(root, value);
    }

    private boolean contains(TreeNode node, int value) {

        if (node == null) {
            return false;
        }

        if (value == node.value) {
            return true;
        }

        if (value < node.value) {
            return contains(node.left, value);
        }

        return contains(node.right, value);
    }

    public void printInOrder() {
        printInOrder(root);
    }

    private void printInOrder(TreeNode node) {

        if (node == null) {
            return;
        }

        printInOrder(node.left);

        System.out.println(node.value);

        printInOrder(node.right);
    }
}

Example usage:

public class Main {

    public static void main(String[] args) {

        BinarySearchTree tree =
            new BinarySearchTree();

        tree.add(50);
        tree.add(30);
        tree.add(70);
        tree.add(20);
        tree.add(40);
        tree.add(60);
        tree.add(80);

        System.out.println(
            tree.contains(60)
        );

        tree.printInOrder();
    }
}

67. Discussion question

Suppose you need to store student records indexed by student ID.

Which would you choose?

HashMap

There is not necessarily one universally correct answer.

You should know the following approximate complexities.

Structure / OperationTypical Complexity

HashSet membershipO(1) average
Balanced BST searchO(log n)
Balanced BST insertionO(log n)

Heap find minimumO(1)

69. Key takeaways

By the end of this week, you should understand the following ideas.

Trees represent hierarchical data.

Unlike lists, trees are not linear.

Binary trees have at most two children per node.

The children are conventionally called left and right.

Binary search trees add an ordering rule.

left < node < right

This rule enables efficient searching.

Recursive algorithms are natural for trees.

A tree contains smaller trees inside itself.

Traversals visit all nodes systematically.

Know:

preorder
inorder
postorder

Inorder traversal of a bst produces sorted values.

This follows from the BST ordering property.

Tree performance depends on tree height.

Balanced:

O(log n)

Potentially unbalanced:

O(n)

Heaps solve a different problem from bsts.

Heaps are particularly useful for priority queues.

Data structures are about tradeoffs.

The best structure depends on the operations your program needs.
