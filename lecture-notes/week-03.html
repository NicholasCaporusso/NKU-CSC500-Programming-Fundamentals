1. From selection to iteration

So far, we have studied two important forms of control flow.

Sequence

Statements normally execute one after another:

int x = 5;
int y = 10;
int sum = x + y;
System.out.println(sum);

Selection

An if statement allows the program to choose whether a statement should execute:

if (temperature < 32) {
    System.out.println("Freezing");
}

An if-else statement chooses between alternatives:

if (score >= 60) {
    System.out.println("Pass");
} else {
    System.out.println("Fail");
}

This week introduces the third major control structure:

Iteration — repeating instructions.

Iteration is implemented using loops.

2. Why programs need loops

Suppose we want to print the integers from 1 through 5.

We could write:

System.out.println(1);
System.out.println(2);
System.out.println(3);
System.out.println(4);
System.out.println(5);

This works, but it does not scale.

What if the requirement changes to:

Print the integers from 1 through 10,000.

Writing 10,000 separate println statements would be unreasonable.

Instead, we can describe the pattern:

Start at 1.

Print the current number.

Increase the number by 1.

Repeat until 5 has been printed.

In Java:

int number = 1;

while (number <= 5) {
    System.out.println(number);
    number++;
}

Output:

1
2
3
4
5

The program is short because the code itself is not being duplicated. The same statements execute repeatedly.

This is one of the central powers of programming:

A small amount of code can describe a potentially very large amount of computation.

3. Where repetition appears

Loops are used throughout programming.

Examples include:

  • Processing every student in a class.
  • Reading many values from a user.
  • Adding a collection of numbers.
  • Calculating an average.
  • Counting how many values satisfy a condition.
  • Finding the largest or smallest value.
  • Searching for a particular value.
  • Repeating a menu until the user selects "Quit."
  • Asking for input until the user enters something valid.
  • Simulating a die roll thousands of times.
  • Generating tables.
  • Producing text patterns.
  • Processing digits in an integer.
  • Repeating a game until it ends.

Later in the course, loops will also be essential for processing arrays, lists, searching, sorting, and many data structures.

For now, the central question is:

What computation needs to repeat, and what determines when repetition stops?

4. Vocabulary of loops

Several terms will appear repeatedly.

Iteration

One execution of a loop body is called an iteration.

For example:

for (int i = 1; i <= 3; i++) {
    System.out.println(i);
}

The loop performs three iterations.

Loop body

The statements that repeat are the loop body:

{
    System.out.println(i);
}

Loop condition

A Boolean expression that determines whether repetition should continue:

i <= 3

A loop condition must evaluate to either:

true

or:

false

Loop control variable

A variable whose value helps determine whether the loop continues.

Example:

int i = 1;

while (i <= 5) {
    System.out.println(i);
    i++;
}

Here, i is the loop control variable.

Termination

Termination means the loop eventually stops.

One of the most important questions about any loop is:

Why will this loop eventually terminate?

5. The three main Java loop structures

Java provides three basic loop structures.

while

while (condition) {
    // repeated statements
}

The condition is checked before each iteration.

A while loop can therefore execute zero times.

for

for (initialization; condition; update) {
    // repeated statements
}

A for loop is particularly convenient when the repetition is naturally controlled by a counter.

do-while

do {
    // repeated statements
} while (condition);

The condition is checked after the loop body.

A do-while loop therefore executes at least once.

6. A useful model for designing loops

Before writing Java syntax, answer four questions.

Question 1: What needs to repeat?

Identify the operation.

Example:

Read a score and add it to a total.

Question 2: When should repetition continue or stop?

Example:

Continue while fewer than five scores have been entered.

or:

Continue until the user enters -1.

Question 3: What state controls the repetition?

Possibilities include:

  • A counter
  • Current user input
  • A Boolean condition
  • A remaining amount
  • A current number
  • A menu choice

Question 4: What changes during each iteration?

Something generally needs to make progress toward termination.

For example:

count++;

or:

number = input.nextInt();

A strong loop design can usually answer:

What changes each iteration, and why will the condition eventually become false?

7. The while loop

The syntax of a while loop is:

while (condition) {
    statements;
}

Execution follows this pattern:

  1. Evaluate the condition.
  2. If it is false, skip the body and leave the loop.
  3. If it is true, execute the loop body.
  4. Return to the condition.
  5. Repeat.

Conceptually:

          +-----------------------+
          |                       |
          v                       |
    check condition               |
        /      \                  |
     false      true              |
       |           |              |
       |      execute body         |
       |           |              |
       |      change state --------+
       |
       v
   leave loop

8. First while example

int number = 1;

while (number <= 5) {
    System.out.println(number);
    number++;
}

Output:

1
2
3
4
5

Let's trace the program.

Initially:

number = 1

The condition is:

number <= 5

First iteration

1 <= 5 → true

Print:

1

Then:

number++;

makes:

number = 2

Second iteration

2 <= 5 → true

Print 2, then change number to 3.

This continues until:

number = 6

Now:

6 <= 5 → false

The loop stops.

9. Three essential parts of a typical loop

Many loops contain three important pieces.

9.1 Initialization

Establish the starting state.

int number = 1;

9.2 Condition

Decide whether another iteration should execute.

number <= 5

9.3 Update

Change the loop control state.

number++;

Putting them together:

int number = 1;                  // initialization

while (number <= 5) {            // condition
    System.out.println(number);
    number++;                    // update
}

When examining a loop, get into the habit of locating all three.

10. A while loop may execute zero times

Consider:

int x = 10;

while (x < 5) {
    System.out.println(x);
}

The first thing Java does is check:

10 < 5

which is false.

Therefore, the body executes zero times.

Nothing is printed.

This behavior is sometimes exactly what we want.

The while loop says:

Execute this body only if the condition is currently true.

11. Increment, decrement, and compound assignment

Loops frequently update numeric variables.

Instead of:

x = x + 1;

Java allows:

x++;

Similarly:

x--;

means:

x = x - 1;

Compound assignment operators are also common:

x += 2;
x -= 5;
x *= 3;
x /= 4;

For example:

x += 2;

means:

x = x + 2;

12. Counting by different amounts

A loop does not need to increase by 1.

Even numbers

int number = 0;

while (number <= 10) {
    System.out.println(number);
    number += 2;
}

Output:

0
2
4
6
8
10

Multiples of 5

int number = 5;

while (number <= 50) {
    System.out.println(number);
    number += 5;
}

13. Counting backward

A loop may also count downward.

int count = 10;

while (count >= 1) {
    System.out.println(count);
    count--;
}

System.out.println("Blast off!");

Output:

10
9

4
3
2
1
Blast off!

Notice that the three parts agree:

initial value: 10
condition:     count >= 1
update:        count--

The update moves the value toward making the condition false.

14. Infinite loops

An infinite loop is a loop that does not terminate as intended.

Consider:

int x = 1;

while (x <= 5) {
    System.out.println(x);
}

The program repeatedly prints:

1
1
1
1
1
...

Why?

Because x is never changed.

The condition remains:

1 <= 5

forever.

The intended version is:

int x = 1;

while (x <= 5) {
    System.out.println(x);
    x++;
}

15. Updating in the wrong direction

An update can exist and still be wrong.

int x = 1;

while (x <= 5) {
    System.out.println(x);
    x--;
}

The values become:

1
0
-1
-2
-3
...

The condition is:

x <= 5

As x decreases, the condition continues to be true.

The update is moving the state in the wrong direction.

A useful debugging question is:

Is the update moving the control variable toward termination or away from it?

16. How to debug an infinite loop

If a loop does not appear to stop, inspect it systematically.

Ask:

  1. What is the loop condition?
  2. Which variables appear in that condition?
  3. What are their initial values?
  4. Which of those variables change?
  5. Where are they changed?
  6. Are they changing in the correct direction?
  7. Can the condition eventually become false?
  8. Is input supposed to change but never being reread?
  9. Is a continue statement skipping an important update?
  10. Is there an accidental semicolon after the loop header?

Do not debug loops by staring at them indefinitely.

Trace the values.

18. What should you track in a trace table?

You generally do not need every variable in the program.

Track variables that:

  • Appear in the loop condition.
  • Change during the loop.
  • Affect an if condition inside the loop.
  • Store a running result.
  • Count events.
  • Control nested loops.

19. Counters

A counter records how many times something happens.

Counters usually start at zero:

int count = 0;

Why zero?

Because before anything has been counted, the correct count is zero.

Suppose we want to determine how many integers from 1 through 100 are divisible by 7.

int number = 1;
int count = 0;

while (number <= 100) {

    if (number % 7 == 0) {
        count++;
    }

    number++;
}

System.out.println("Count = " + count);

number and count have different purposes.

  • number controls which value is currently being examined.
  • count records how many qualifying values have been found.

Do not confuse the loop variable with the counter of interesting events.

20. Counters and conditions

A counter is often updated only when some condition is satisfied.

General pattern:

int count = 0;

while (someCondition) {

    if (somethingInterestingHappened) {
        count++;
    }

    // update loop state
}

Example: count the even numbers from 1 through 20.

int number = 1;
int evenCount = 0;

while (number <= 20) {

    if (number % 2 == 0) {
        evenCount++;
    }

    number++;
}

System.out.println("Even numbers: " + evenCount);

Result:

Even numbers: 10

21. Accumulators

An accumulator gradually combines values across iterations.

The most familiar accumulator is a running sum.

int total = 0;

total += value;

Suppose we want:

1 + 2 + 3 + 4 + 5

We can write:

int total = 0;
int number = 1;

while (number <= 5) {
    total += number;
    number++;
}

System.out.println(total);

Output:

15

Trace:

22. Why a sum accumulator starts at zero

For addition:

int total = 0;

is natural because zero does not change a sum.

For example:

0 + 5 = 5

Mathematically, zero is the identity value for addition.

If you accidentally start with:

int total = 1;

and process:

5, 10, 20

you obtain:

1 + 5 + 10 + 20 = 36

instead of:

35

23. Products use a different initial value

Suppose we want:

1 × 2 × 3 × 4 × 5

We should not write:

int product = 0;

because:

0 × anything = 0

Instead:

int product = 1;

for (int i = 1; i <= 5; i++) {
    product *= i;
}

System.out.println(product);

Output:

120

For multiplication, the identity value is 1.

24. Computing an average

To calculate an average of repeated values, we need:

  1. A sum accumulator
  2. A count

Example with five scores:

Scanner input = new Scanner(System.in);

double total = 0.0;
int count = 0;

while (count < 5) {

    System.out.print("Enter score: ");
    double score = input.nextDouble();

    total += score;
    count++;
}

double average = total / count;

System.out.println("Average = " + average);

The pattern is:

initialize total
initialize count

repeat:
    obtain value
    add value to total
    increase count

calculate total / count

This pattern will appear repeatedly throughout programming.

25. Be careful with integer division

Consider:

int total = 7;
int count = 2;

double average = total / count;

You might expect:

3.5

But Java first evaluates:

total / count

as integer division because both operands are int.

The result is:

3

Then Java converts it to double:

3.0

One correction is:

double average = (double) total / count;

Now the calculation becomes:

7.0 / 2 = 3.5

Using a double accumulator also avoids this problem:

double total = 7.0;
int count = 2;

double average = total / count;

26. Counter-controlled loops

A loop is counter-controlled when we know how many repetitions should occur.

Example:

Ask the user for exactly ten numbers.

int count = 0;

while (count < 10) {

    System.out.print("Enter number: ");
    int number = input.nextInt();

    count++;
}

The number of iterations is known:

10

This type of problem is often a good candidate for a for loop.

27. The for loop

The syntax is:

for (initialization; condition; update) {
    statements;
}

Example:

for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}

Output:

1
2
3
4
5

The three loop-control components appear together:

for (int i = 1; i <= 5; i++)

We can read this as:

Initialize i to 1.

Continue while i <= 5.

After each iteration, increase i by 1.

28. Execution order of a for loop

Consider:

for (int i = 1; i <= 3; i++) {
    System.out.println(i);
}

The execution order is:

initialization

condition
body
update

condition
body
update

condition
body
update

condition → false
stop

More precisely:

int i = 1            executes once

i <= 3               true
print 1
i++

i <= 3               true
print 2
i++

i <= 3               true
print 3
i++

i <= 3               false
stop

The initialization executes only once.

The condition executes before every potential iteration.

The update executes after every completed iteration.

29. for and while are closely related

This:

for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}

can be rewritten as:

int i = 1;

while (i <= 5) {
    System.out.println(i);
    i++;
}

Both produce:

1
2
3
4
5

The for loop packages initialization, condition, and update into one location.

This is convenient for count-controlled repetition.

30. Common for loop patterns

From 0 through 9

for (int i = 0; i < 10; i++) {
    System.out.println(i);
}

From 1 through 10

for (int i = 1; i <= 10; i++) {
    System.out.println(i);
}

Even numbers from 0 through 20

for (int i = 0; i <= 20; i += 2) {
    System.out.println(i);
}

Multiples of 5

for (int i = 5; i <= 100; i += 5) {
    System.out.println(i);
}

Counting backward

for (int i = 10; i >= 1; i--) {
    System.out.println(i);
}

31. The important 0 to n - 1 pattern

A very common pattern is:

for (int i = 0; i < n; i++) {
    // ...
}

If n is positive, this executes exactly n times.

For:

for (int i = 0; i < 5; i++) {
    System.out.println(i);
}

the values are:

0
1
2
3
4

There are five values.

Notice:

first value = 0
last value  = 4

The value 5 is the first value for which:

i < 5

is false.

This pattern will become especially important when we later work with indexed collections.

32. Off-by-one errors

One of the most common loop mistakes is an off-by-one error.

An off-by-one error means the loop executes one time too many or one time too few.

Suppose the requirement is:

Print 1 through 10.

Incorrect:

for (int i = 1; i < 10; i++) {
    System.out.println(i);
}

Output:

1
2
3
4
5
6
7
8
9

The value 10 is missing.

Correct:

for (int i = 1; i <= 10; i++) {
    System.out.println(i);
}

33. < Versus <=

These two loops are not equivalent:

for (int i = 0; i < 5; i++)

Values:

0 1 2 3 4

Five iterations.

But:

for (int i = 0; i <= 5; i++)

Values:

0 1 2 3 4 5

Six iterations.

When designing a counting loop, ask:

  1. What is the first value?
  2. What is the last value?
  3. Should the last value be included?
  4. Should the condition use < or <=?
  5. Exactly how many iterations should occur?

A useful debugging technique is to write down the expected values explicitly.

34. Variable scope in a for loop

Consider:

for (int i = 0; i < 5; i++) {
    System.out.println(i);
}

The variable i is declared inside the for header.

Its scope is limited to the loop.

Therefore:

for (int i = 0; i < 5; i++) {
    System.out.println(i);
}

System.out.println(i);   // compilation error

does not compile.

If i must remain available afterward:

int i;

for (i = 0; i < 5; i++) {
    System.out.println(i);
}

System.out.println(i);

After the loop, i is 5.

35. while versus for

Both can often solve the same problem.

A useful guideline is:

SituationUsually clearer
Repeat exactly 10 timesfor
Process integers 1 through 100for
Count from 0 to n - 1for
Continue until sentinel inputwhile
Continue until valid inputwhile
Repeat while some state remains truewhile
Menu that must display at least oncedo-while

This is a guideline, not a rigid law.

The goal is not:

Which loop requires the fewest characters?

The better question is:

Which loop most clearly communicates what controls the repetition?

36. Condition-controlled repetition

Sometimes the number of repetitions is unknown.

Example:

Continue accepting scores until the user says there are no more scores.

You do not know whether the user will enter:

3 scores

or:

30 scores

or:

300 scores

This is not naturally described as:

Repeat exactly N times.

Instead, repetition depends on a condition.

Such problems often use a while loop.

37. Sentinel-controlled loops

A sentinel value is a special value that signals the end of input.

Suppose valid exam scores are from 0 through 100.

We might choose:

-1

to mean:

Stop entering scores.

Because -1 is not a valid exam score, it can serve as a sentinel.

Example:

Scanner input = new Scanner(System.in);

System.out.print("Enter a score (-1 to stop): ");
int score = input.nextInt();

while (score != -1) {

    System.out.println("Processing " + score);

    System.out.print("Enter a score (-1 to stop): ");
    score = input.nextInt();
}

38. The priming read

Notice that the previous example reads input twice in the source code:

int score = input.nextInt();

before the loop and:

score = input.nextInt();

inside the loop.

This is called the priming-read pattern.

Conceptually:

read first value

while value is not sentinel:
    process value
    read next value

Why is the first input needed before the loop?

Because the loop condition needs a value to test.

Why is another input needed inside the loop?

Because the program must obtain the next value before checking the condition again.

39. A common sentinel-loop bug

Incorrect:

int value = input.nextInt();

while (value != -1) {
    System.out.println(value);
}

Suppose the user initially enters:

5

Then:

value != -1

is true.

The program prints 5.

But value never changes.

It prints:

5
5
5
5
5
...

The loop needs:

value = input.nextInt();

inside the body.

Correct:

int value = input.nextInt();

while (value != -1) {
    System.out.println(value);
    value = input.nextInt();
}

40. Do not process the sentinel as data

Suppose -1 means stop.

Correct:

int total = 0;

int value = input.nextInt();

while (value != -1) {
    total += value;
    value = input.nextInt();
}

The sentinel is checked before it is added.

The value -1 is not data. It is a control signal.

A sentinel should therefore normally be excluded from:

  • Totals
  • Counts
  • Averages
  • Minimum calculations
  • Maximum calculations
  • Other data processing

41. Sentinel-controlled average

Suppose a professor enters an unknown number of scores.

Scanner input = new Scanner(System.in);

double total = 0.0;
int count = 0;

System.out.print("Enter score (-1 to finish): ");
double score = input.nextDouble();

while (score != -1) {

    total += score;
    count++;

    System.out.print("Enter score (-1 to finish): ");
    score = input.nextDouble();
}

if (count > 0) {
    double average = total / count;

    System.out.println("Number of scores: " + count);
    System.out.println("Average: " + average);
} else {
    System.out.println("No scores were entered.");
}

Why is this important?

if (count > 0)

Because the user could enter -1 immediately.

Then:

count = 0

and calculating:

total / count

would attempt to divide by zero.

Whenever you compute an average from repeated input, consider the possibility that no data values were processed.

42. Input validation with a loop

Loops are useful when input must satisfy a requirement.

Suppose a valid score must be between 0 and 100.

System.out.print("Enter score: ");
int score = input.nextInt();

while (score < 0 || score > 100) {

    System.out.println("Invalid score.");

    System.out.print("Enter score again: ");
    score = input.nextInt();
}

System.out.println("Accepted score: " + score);

The condition:

score < 0 || score > 100

means:

Continue while the score is invalid.

The program exits the loop only when:

0 <= score <= 100

43. Why validation conditions sometimes feel backward

Suppose you describe valid input as:

A score from 0 through 100.

The validity condition is:

score >= 0 && score <= 100

But a validation loop often asks:

Should I ask again?

That means it needs the invalidity condition:

score < 0 || score > 100

A helpful strategy is:

  1. State valid input in English.
  2. State invalid input in English.
  3. Write the condition matching what the loop is supposed to continue doing.

44. The do-while loop

Java's third loop structure is:

do {
    statements;
} while (condition);

Example:

int x = 1;

do {
    System.out.println(x);
    x++;
} while (x <= 5);

Output:

1
2
3
4
5

The important difference is the location of the condition.

With a while loop:

condition → body

With a do-while loop:

body → condition

45. while versus do-while

Consider:

int x = 10;

while (x < 5) {
    System.out.println(x);
}

The body executes zero times.

Now:

int x = 10;

do {
    System.out.println(x);
} while (x < 5);

Output:

10

The condition is false, but the body has already executed.

Therefore:

A do-while loop always executes at least once.

46. The semicolon in do-while

The syntax requires a semicolon:

do {
    // statements
} while (condition);

Notice:

while (condition);

The semicolon is part of the do-while syntax.

This differs from an ordinary while loop:

while (condition) {
    // statements
}

where placing a semicolon after the condition is usually a bug.

47. A natural use of do-while: Menus

A menu normally needs to appear at least once.

int choice;

do {
    System.out.println("1. Deposit");
    System.out.println("2. Withdraw");
    System.out.println("3. View balance");
    System.out.println("4. Quit");

    System.out.print("Choice: ");
    choice = input.nextInt();

    if (choice == 1) {
        System.out.println("Deposit selected.");
    } else if (choice == 2) {
        System.out.println("Withdraw selected.");
    } else if (choice == 3) {
        System.out.println("Balance selected.");
    } else if (choice != 4) {
        System.out.println("Invalid choice.");
    }

} while (choice != 4);

System.out.println("Goodbye.");

The menu appears first.

Only afterward does the program ask:

Should it appear again?

That makes do-while a natural fit.

48. Finding the largest value

Loops frequently maintain a "best so far" value.

Suppose the user will enter five integers.

System.out.print("Enter number 1: ");
int largest = input.nextInt();

for (int i = 2; i <= 5; i++) {

    System.out.print("Enter number " + i + ": ");
    int number = input.nextInt();

    if (number > largest) {
        largest = number;
    }
}

System.out.println("Largest = " + largest);

The key idea is:

if (number > largest) {
    largest = number;
}

At every stage:

largest stores the largest value seen so far.

49. Why not initialize largest to zero?

This can be incorrect:

int largest = 0;

Suppose the data is:

-12
-8
-20
-4
-17

No value is greater than zero.

The program might incorrectly report:

0

even though zero was never entered.

A safer pattern is:

Use the first actual data value as the initial largest value.

int largest = input.nextInt();

Then compare the remaining inputs to it.

The same idea applies to minimum values.

50. Finding both minimum and maximum

System.out.print("Enter number 1: ");
int number = input.nextInt();

int smallest = number;
int largest = number;

for (int i = 2; i <= 5; i++) {

    System.out.print("Enter number " + i + ": ");
    number = input.nextInt();

    if (number < smallest) {
        smallest = number;
    }

    if (number > largest) {
        largest = number;
    }
}

System.out.println("Smallest = " + smallest);
System.out.println("Largest = " + largest);

The variables maintain two invariants:

smallest = smallest value seen so far
largest  = largest value seen so far

51. Combining loops and decisions

Loops frequently contain if statements.

Example:

Print the even integers from 1 through 20.

for (int i = 1; i <= 20; i++) {

    if (i % 2 == 0) {
        System.out.println(i);
    }
}

The loop condition:

i <= 20

controls how long repetition continues.

The if condition:

i % 2 == 0

controls what happens during one iteration.

These are different responsibilities.

53. Worked example: Counting divisible values

Problem:

How many integers from 1 through 100 are divisible by both 3 and 5?

int count = 0;

for (int i = 1; i <= 100; i++) {

    if (i % 3 == 0 && i % 5 == 0) {
        count++;
    }
}

System.out.println("Count = " + count);

This illustrates a common pattern:

repeat over candidate values

    if current value has desired property
        increase count

54. Worked example: FizzBuzz

For integers 1 through 30:

  • Print "FizzBuzz" if divisible by both 3 and 5.
  • Print "Fizz" if divisible by 3.
  • Print "Buzz" if divisible by 5.
  • Otherwise print the number.
for (int i = 1; i <= 30; i++) {

    if (i % 3 == 0 && i % 5 == 0) {
        System.out.println("FizzBuzz");

    } else if (i % 3 == 0) {
        System.out.println("Fizz");

    } else if (i % 5 == 0) {
        System.out.println("Buzz");

    } else {
        System.out.println(i);
    }
}

Why check both first?

Consider:

i = 15

Both of these are true:

i % 3 == 0

and:

i % 5 == 0

If we checked divisibility by 3 first:

if (i % 3 == 0) {
    System.out.println("Fizz");
}

then 15 would enter that branch immediately.

The later "FizzBuzz" case would never be reached.

When using an if-else-if chain, ordering conditions matters.

55. break

The break statement immediately terminates the nearest enclosing loop.

Example:

for (int i = 1; i <= 10; i++) {

    if (i == 5) {
        break;
    }

    System.out.println(i);
}

Output:

1
2
3
4

When i becomes 5, Java executes:

break;

and leaves the loop.

56. Searching with break

Suppose we want to examine candidate values until a target is found.

int target = 7;

for (int i = 1; i <= 10; i++) {

    if (i == target) {
        System.out.println("Found " + target);
        break;
    }

    System.out.println("Checked " + i);
}

Once the target is found, there may be no reason to continue searching.

This is a meaningful use of break.

However, do not use break simply because designing a clear loop condition feels inconvenient.

A clear termination condition is often easier to understand.

57. while (true) and break

This is an intentionally unbounded loop:

while (true) {

    int value = input.nextInt();

    if (value == -1) {
        break;
    }

    System.out.println(value);
}

This can be valid.

But compare it with:

int value = input.nextInt();

while (value != -1) {

    System.out.println(value);

    value = input.nextInt();
}

For beginners, the second form often makes the termination condition easier to see:

value != -1

Use the structure that makes program logic clearest.

58. continue

continue skips the rest of the current iteration.

It does not end the entire loop.

Example:

for (int i = 1; i <= 5; i++) {

    if (i == 3) {
        continue;
    }

    System.out.println(i);
}

Output:

1
2
4
5

When i == 3, Java skips:

System.out.println(i);

and moves to the next iteration.

59. break versus continue

These statements do very different things.

break

break;

means:

Leave the loop entirely.

continue

continue;

means:

Skip the rest of this iteration and proceed with the next iteration.

Example:

for (int i = 1; i <= 10; i++) {

    if (i == 3) {
        continue;
    }

    if (i == 7) {
        break;
    }

    System.out.println(i);
}

Output:

1
2
4
5
6

3 is skipped.

When 7 is reached, the loop ends completely.

60. A dangerous continue bug

Consider:

int i = 0;

while (i < 10) {

    if (i == 5) {
        continue;
    }

    i++;
}

When i becomes 5:

i == 5

is true.

continue sends execution back to the loop condition.

But:

i++;

was skipped.

Therefore i remains 5.

The program repeats forever.

This is one reason continue should be used carefully in while loops.

61. Nested loops

A nested loop is a loop inside another loop.

Example:

for (int row = 1; row <= 3; row++) {

    for (int column = 1; column <= 4; column++) {
        System.out.print("*");
    }

    System.out.println();
}

Output:

****
****
****

The outer loop controls the number of rows.

The inner loop controls how much is printed within each row.

62. How nested loops execute

Consider:

for (int i = 1; i <= 3; i++) {

    for (int j = 1; j <= 2; j++) {
        System.out.println("i = " + i + ", j = " + j);
    }
}

Output:

i = 1, j = 1
i = 1, j = 2
i = 2, j = 1
i = 2, j = 2
i = 3, j = 1
i = 3, j = 2

The important rule is:

For each single iteration of the outer loop, the inner loop runs through all of its iterations.

63. Why the inner variable resets

Look again:

for (int i = 1; i <= 3; i++) {

    for (int j = 1; j <= 2; j++) {
        System.out.println(i + " " + j);
    }
}

When the outer loop moves from:

i = 1

to:

i = 2

Java encounters this again:

for (int j = 1; ...)

So a new j starts at 1.

That is why the sequence is:

1 1
1 2

2 1
2 2

3 1
3 2

rather than allowing j to continue increasing across all outer iterations.

64. Counting nested-loop executions

Suppose:

for (int i = 0; i < 3; i++) {

    for (int j = 0; j < 4; j++) {
        System.out.println(i + ", " + j);
    }
}

The outer loop executes:

3 times

For each outer iteration, the inner loop executes:

4 times

Therefore, the inner statement executes:

3 × 4 = 12 times

This multiplication rule works when the inner loop performs the same number of iterations for every outer-loop iteration.

This is also an early glimpse of reasoning about how much work a program performs.

65. Nested loops with descriptive variables

You will often see:

for (int i = 0; i < 5; i++) {
    for (int j = 0; j < 5; j++) {
        // ...
    }
}

For small mathematical loops, i and j are common names.

But when the variables have meaningful roles, descriptive names are clearer:

for (int row = 0; row < 5; row++) {

    for (int column = 0; column < 5; column++) {
        // ...
    }
}

Code should communicate intent.

66. Rectangle pattern

67. Triangle pattern

for (int row = 1; row <= 5; row++) {

Why does the number of stars grow?

Because the inner condition is:

When:

When:

When:

it executes five times.

The number of inner-loop iterations depends on the outer-loop variable.

68. Number triangle

69. Multiplication table

for (int row = 1; row <= 10; row++) {

    for (int column = 1; column <= 10; column++) {

Conceptually:

70. Simple simulation with loops

Loops are useful when we want to repeat an experiment many times.

For example, a six-sided die roll can be simulated using:

int roll = (int)(Math.random() * 6) + 1;

Math.random() produces a double satisfying approximately:

0.0 <= value < 1.0

Multiplying by 6 gives:

0.0 <= value < 6.0

Casting to int produces:

0, 1, 2, 3, 4, or 5

Adding 1 produces:

1, 2, 3, 4, 5, or 6

To roll ten times:

for (int i = 0; i < 10; i++) {

    int roll = (int)(Math.random() * 6) + 1;

    System.out.println(roll);
}

71. Simulation with counting

Suppose we want to roll a die 10,000 times and count the number of sixes.

int sixCount = 0;

for (int i = 0; i < 10000; i++) {

    int roll = (int)(Math.random() * 6) + 1;

    if (roll == 6) {
        sixCount++;
    }
}

System.out.println("Number of sixes = " + sixCount);

This combines:

  • A fixed-repetition for loop
  • Random simulation
  • An if statement
  • A counter

Real programs frequently combine multiple basic programming constructs this way.

72. Simulation with two dice

int sevenCount = 0;

for (int trial = 0; trial < 10000; trial++) {

    int die1 = (int)(Math.random() * 6) + 1;
    int die2 = (int)(Math.random() * 6) + 1;

    int sum = die1 + die2;

    if (sum == 7) {
        sevenCount++;
    }
}

System.out.println("Number of sums equal to 7: " + sevenCount);

The loop says:

Repeat the experiment 10,000 times.

Inside each iteration:

  1. Roll the first die.
  2. Roll the second die.
  3. Calculate their sum.
  4. Test whether the sum is 7.
  5. Update the counter if appropriate.

Thinking in these steps makes larger loop bodies easier to understand.

73. Processing the digits of an integer

Loops can also repeatedly transform a number.

Suppose:

number = 5729

The expression:

number % 10

gives the final digit:

9

Integer division:

number / 10

removes that final digit:

This suggests a repeated process.

int number = 5729;

while (number > 0) {

    int digit = number % 10;

77. Factorial as repeated multiplication

For a positive integer n:

n! = n × (n - 1) × ... × 2 × 1

For example:

5! = 5 × 4 × 3 × 2 × 1 = 120

Using a loop:

int n = 5;
long factorial = 1;

for (int i = 1; i <= n; i++) {
    factorial *= i;
}

System.out.println(factorial);

Remember:

factorial = 1;

not zero.

A multiplicative accumulator must usually begin at 1.

78. Determining whether an integer is prime

A positive integer greater than 1 is prime if its only positive divisors are 1 and itself.

A straightforward introductory approach is to test possible divisors.

int number = 17;
boolean isPrime = true;

if (number <= 1) {
    isPrime = false;
} else {

    for (int divisor = 2; divisor < number; divisor++) {

        if (number % divisor == 0) {
            isPrime = false;
            break;
        }
    }
}

if (isPrime) {
    System.out.println(number + " is prime.");
} else {
    System.out.println(number + " is not prime.");
}

For 17, none of:

2, 3, 4, ..., 16

divides evenly into 17.

For 18, when:

divisor = 2

we obtain:

18 % 2 = 0

so the number is not prime.

This example combines:

  • Repetition
  • Selection
  • A Boolean flag
  • Remainder
  • Early termination with break

79. Common loop error: Accidental semicolon

Consider:

for (int i = 0; i < 10; i++); {
    System.out.println("Hello");
}

Notice:

i++);

The semicolon forms an empty loop body.

Java interprets the code roughly as:

for (int i = 0; i < 10; i++) {
    // nothing
}

{
    System.out.println("Hello");
}

Therefore "Hello" prints only once.

Correct:

for (int i = 0; i < 10; i++) {
    System.out.println("Hello");
}

80. A more dangerous semicolon error with while

Consider:

int i = 0;

while (i < 5);

{
    System.out.println(i);
    i++;
}

The actual loop is:

while (i < 5);

Its body is empty.

Because i never changes inside that empty loop:

i = 0

forever.

So the program gets stuck before reaching the following block.

81. Omitting braces

Java permits:

for (int i = 0; i < 5; i++)
    System.out.println(i);

because exactly one statement belongs to the loop.

But consider:

for (int i = 0; i < 5; i++)
    System.out.println(i);
    System.out.println("Done");

Java interprets this as:

for (int i = 0; i < 5; i++) {
    System.out.println(i);
}

System.out.println("Done");

Only the first statement belongs to the loop.

Using braces consistently is strongly recommended:

for (int i = 0; i < 5; i++) {
    System.out.println(i);
}

System.out.println("Done");

Braces make the program structure visually explicit.

82. Common loop error: Uninitialized accumulator

Incorrect:

int total;

for (int i = 1; i <= 10; i++) {
    total += i;
}

Java rejects this because total does not have a defined starting value.

Correct:

int total = 0;

for (int i = 1; i <= 10; i++) {
    total += i;
}

Before accumulating, establish the correct initial value.

83. Common loop error: Resetting the accumulator

Incorrect:

for (int i = 1; i <= 5; i++) {

    int total = 0;

    total += i;
}

Every iteration creates a new total initialized to zero.

The running history is lost.

Correct:

int total = 0;

for (int i = 1; i <= 5; i++) {
    total += i;
}

Ask yourself:

Does this variable need to remember information from previous iterations?

If yes, it normally must be initialized before the loop.

84. Common loop error: Incorrect counter initialization

Suppose we want to count positive values.

Correct:

int positiveCount = 0;

Then:

if (value > 0) {
    positiveCount++;
}

If you mistakenly begin:

int positiveCount = 1;

the result will normally be one too large.

Initialization matters because it establishes the meaning of the variable before any iteration occurs.

85. Common loop error: Changing the for variable in the body

Avoid unnecessarily modifying the loop control variable inside the body.

Example:

for (int i = 0; i < 10; i++) {

    System.out.println(i);

    i++;
}

Here i is updated twice:

  1. Inside the body
  2. By the for loop update

Values printed are:

0
2
4
6
8

This may be intentional, but it is easy to misread.

If the intent is to count by two, write it clearly:

for (int i = 0; i < 10; i += 2) {
    System.out.println(i);
}

86. Common loop error: Wrong comparison direction

Suppose we intend to count downward.

Incorrect:

for (int i = 10; i <= 1; i--) {
    System.out.println(i);
}

The first condition is:

10 <= 1

which is false.

The loop executes zero times.

Correct:

for (int i = 10; i >= 1; i--) {
    System.out.println(i);
}

The condition and update must agree with the intended direction.

87. Common loop error: Wrong update direction

Incorrect:

for (int i = 10; i >= 1; i++) {
    System.out.println(i);
}

The loop begins at 10.

The condition requires:

i >= 1

But the update:

i++

makes i larger.

So the loop does not move toward the lower boundary.

A correct countdown uses:

i--

88. Common loop error: Dividing by zero after a loop

Suppose:

double total = 0;
int count = 0;

No data values are processed.

Then:

double average = total / count;

attempts to divide by zero.

When input quantity is unknown, protect the calculation:

if (count > 0) {
    double average = total / count;
    System.out.println(average);
} else {
    System.out.println("No values entered.");
}

89. A systematic loop-writing strategy

When solving a loop problem, resist the temptation to immediately type:

for (...)

or:

while (...)

Instead use this process.

Step 1: Describe the repeated action

Example:

Read one score and add it to the total.

Step 2: Decide what controls termination

Example:

Stop after five scores.

or:

Stop when the user enters -1.

Step 3: Identify the variables

Perhaps:

score
total
count

Step 4: Decide their initial values

double total = 0.0;
int count = 0;

Step 5: Decide how state changes

total += score;
count++;

Step 6: Choose the loop structure

Fixed count:

for

Unknown quantity controlled by input:

while

Must execute at least once:

do-while

Step 7: Trace a small example

Do this before assuming the code is correct.

98. Debugging loops with temporary output

Suppose a loop gives the wrong answer.

Temporary diagnostic output can help.

System.out.println(
    "DEBUG: i=" + i +
    ", count=" + count +
    ", total=" + total
);

For example:

int total = 0;

for (int i = 1; i <= 5; i++) {

    total += i;

    System.out.println(
        "DEBUG: i=" + i +
        ", total=" + total
    );
}

Output:

DEBUG: i=1, total=1
DEBUG: i=2, total=3
DEBUG: i=3, total=6
DEBUG: i=4, total=10
DEBUG: i=5, total=15

This effectively lets the running program produce a trace table.

Remove debugging output when you no longer need it.

99. A better debugging procedure

If a loop behaves incorrectly:

  1. Choose a very small test input.
  2. Determine the expected answer by hand.
  3. Record the initial values.
  4. Evaluate the first condition manually.
  5. Trace the first iteration.
  6. Record all important variables.
  7. Trace the second iteration.
  8. Pay special attention to the final intended iteration.
  9. Evaluate the condition one more time after the expected final iteration.
  10. Compare the trace with the program's actual behavior.

Especially inspect:

first iteration
last iteration

Many loop errors appear at boundaries.

100. Common questions and misconceptions

Q1. Does a loop condition mean "stop when this is true"?

Usually no.

For a standard while or for loop, the condition normally means:

Continue while this is true.

Example:

while (number <= 10)

means:

Continue while number is less than or equal to 10.

The loop stops when that expression becomes false.

Q2. Does while execute at least once?

No.

int x = 100;

while (x < 10) {
    System.out.println(x);
}

executes zero times.

Q3. Does do-while execute at least once?

Yes.

The condition is checked only after the first body execution.

Q4. Why does this stop at 4?

for (int i = 0; i < 5; i++)

Because i < 5 is true for:

0, 1, 2, 3, 4

but false for:

5

Q5. Why does this execute 11 times?

for (int i = 0; i <= 10; i++)

Because the values are:

0 through 10

inclusive.

That is 11 values.

Q6. Is i++ the only possible update?

No.

Examples:

i--;
i += 2;
i += 5;
i -= 3;

The update depends on the problem.

Q7. Does every loop need a counter?

No.

For example:

while (score != -1) {
    // ...
}

may be controlled by user input instead of a counter.

Q8. What is the difference between a counter and an accumulator?

A counter records how many.

count++;

An accumulator combines values.

total += value;

Q9. Can one loop use both?

Yes, and averages commonly do:

total += score;
count++;

Q10. Why do sum accumulators start at zero?

Because zero does not alter addition.

0 + x = x

Q11. Why do product accumulators start at one?

Because:

1 × x = x

Starting at zero would make every product zero.

Q12. Why does sentinel input appear twice in the code?

In the priming-read pattern, one read obtains the first value before the condition is tested, and another obtains each following value.

Q13. Can the sentinel be included in the average?

No.

The sentinel is a control signal, not a data value.

Q14. Is while (true) always wrong?

No.

It creates an intentionally unbounded loop and may be paired with break.

However, an explicit loop condition is often easier to reason about.

Q15. What does break affect in nested loops?

break terminates the nearest enclosing loop.

For example:

for (int i = 0; i < 5; i++) {

    for (int j = 0; j < 5; j++) {

        if (j == 2) {
            break;
        }

        System.out.println(i + " " + j);
    }
}

The break terminates the inner j loop, not the outer i loop.

Q16. Does continue end a loop?

No.

It skips the remainder of the current iteration.

Q17. Why can continue be dangerous in a while loop?

Because it can skip the update that would eventually terminate the loop.

Q18. Why does the inner loop variable reset?

Because each outer iteration reaches the inner loop declaration again.

Q19. Can I use the same control variable for both nested loops?

Use separate variables.

Prefer:

for (int row = 0; row < 5; row++) {
    for (int column = 0; column < 5; column++) {
        // ...
    }
}

This keeps the two loop states distinct.

Q20. How do I know whether a loop terminates?

Identify the state in the condition and determine whether each iteration moves that state toward making the condition false.

101. Core loop patterns to recognize

Rather than memorizing dozens of complete programs, recognize reusable patterns.

Pattern 1: Fixed repetition

for (int i = 0; i < n; i++) {
    // repeat n times
}

Pattern 2: Count events

int count = 0;

for (...) {

    if (...) {
        count++;
    }
}

Pattern 3: Accumulate a sum

int total = 0;

for (...) {
    total += value;
}

Pattern 4: Accumulate a product

long product = 1;

for (...) {
    product *= value;
}

Pattern 5: Unknown amount of sentinel-controlled input

int value = input.nextInt();

while (value != sentinel) {

    // process value

    value = input.nextInt();
}

Pattern 6: Input validation

int value = input.nextInt();

while (valueIsInvalid) {
    value = input.nextInt();
}

Pattern 7: Maximum value

int largest = firstValue;

while (...) {

    if (value > largest) {
        largest = value;
    }
}

Pattern 8: Minimum value

int smallest = firstValue;

while (...) {

    if (value < smallest) {
        smallest = value;
    }
}

Pattern 9: Process digits

while (number > 0) {

    int digit = number % 10;

    // process digit

    number /= 10;
}

Pattern 10: Nested rows and columns

for (int row = 0; row < rows; row++) {

    for (int column = 0; column < columns; column++) {
        // process one position
    }
}

108. Week 3 vocabulary

Accumulator

A variable that maintains a running combined result, such as a sum.

Body

The statements repeatedly executed by a loop.

break

A statement that immediately terminates the nearest enclosing loop.

Condition

A Boolean expression that determines whether repetition continues.

Condition-controlled loop

A loop whose number of iterations depends on a condition rather than a predetermined count.

continue

A statement that skips the remainder of the current iteration.

Counter

A variable used to count repetitions or events.

Counter-controlled loop

A loop whose repetition is governed by a counter.

do-while loop

A post-test loop whose body executes before its condition is checked.

Infinite loop

A loop that fails to terminate as intended.

Initialization

The establishment of a loop's starting state.

Iteration

One execution of a loop body; more generally, repeated computation.

Loop

A programming structure that repeats statements.

Loop control variable

A variable whose value helps determine whether a loop continues.

Nested loop

A loop contained inside another loop.

Off-by-one error

A boundary error that causes a loop to execute one too many or one too few times.

Priming read

An input operation performed before a sentinel-controlled loop so the first condition can be evaluated.

Sentinel

A special value indicating that input or processing should stop.

Termination

The point at which a loop stops executing.

Update

A change to loop state, often designed to move the loop toward termination.

while loop

A pre-test loop that continues while its condition evaluates to true.

109. Week 3 summary

Iteration allows a small set of instructions to perform repeated computation.

Java provides three major loop constructs:

while
for

and:

do-while

A while loop tests its condition before each iteration and is particularly useful when the number of repetitions is not known in advance.

A for loop places initialization, condition, and update together and is particularly convenient for counter-controlled repetition.

A do-while loop checks its condition after executing the body, guaranteeing at least one execution.

Important loop patterns include:

  • Counting
  • Accumulating
  • Computing averages
  • Finding minimum and maximum values
  • Processing sentinel-controlled input
  • Validating input
  • Processing numeric ranges
  • Processing digits
  • Simulating repeated events
  • Nested iteration

The most important skill is not memorizing loop syntax.

For every loop, you should be able to answer:

  1. What is the initial state?
  2. What condition controls repetition?
  3. What happens during one iteration?
  4. What state changes?
  5. How does that change move the program toward termination?
  6. When does the loop stop?
  7. How many iterations occur?
  8. What is the final result?

When a loop does not behave as expected, do not rely only on visual inspection.

Trace it.

A programmer who can accurately trace a loop can usually explain it, debug it, and eventually design it.
