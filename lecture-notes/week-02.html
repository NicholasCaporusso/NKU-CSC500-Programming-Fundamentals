Week 2: Decisions and Boolean logic in Java

Course index

1. Overview

In Week 1, our programs mostly followed a straight-line sequence:

  1. read or create some data,
  2. perform calculations,
  3. display results.

For example:

int width = 10;
int height = 5;
int area = width * height;

System.out.println(area);

Every statement executes in order.

Real programs, however, frequently need to behave differently depending on the data they receive.

A banking program might need to ask:

Does the customer have enough money for this withdrawal?

A university registration system might ask:

Has the student completed the prerequisite?

A login program might ask:

Is the password correct?

A grading program might ask:

Is the score at least 90?

A program that reads user input might ask:

Is this value within the permitted range?

This ability to choose among different actions is called decision-making, selection, or branching.

Decision-making is one of the fundamental ideas of programming.

In Java, decisions are primarily built from:

  • Boolean values: true and false
  • Boolean expressions
  • relational operators
  • logical operators
  • if
  • else
  • else if
  • nested conditionals
  • input validation

The important skill this week is not simply learning the syntax of if.

The deeper goal is learning to express rules precisely enough that a computer can evaluate them.

3. Sequential execution and branching

Consider the following code:

int x = 4;
int y = 6;

int sum = x + y;

System.out.println(sum);
System.out.println("Finished");

The statements execute sequentially:

x = 4
  ↓
y = 6
  ↓
sum = x + y
  ↓
print sum
  ↓
print "Finished"

There is only one path through the program.

Now consider:

int score = 75;

if (score >= 60) {
    System.out.println("Pass");
}

The program now contains a decision.

Conceptually:

        score >= 60?
          /     \
       true     false
        |          |
        v          |
   print Pass      |
        \          /
         \        /
           continue

There are now multiple possible paths through the program.

That idea—different possible execution paths—is central to programming.

4. Boolean values

A decision requires a condition.

Ultimately, a condition must evaluate to one of two values:

true

or:

false

Java has a primitive data type specifically for these values:

boolean

Examples:

boolean isRaining = true;
boolean isLoggedIn = false;
boolean hasPermission = true;

Boolean variable names are often written so that they sound like questions.

Good examples include:

boolean isValid;
boolean hasTicket;
boolean canRegister;
boolean shouldContinue;
boolean isAdult;
boolean hasPermission;

This makes code easier to read.

For example:

if (hasTicket) {
    System.out.println("Entry allowed.");
}

reads almost like English:

If the person has a ticket, allow entry.

5. Boolean expressions

Most Boolean values are not manually written as true or false.

Instead, they are produced by Boolean expressions.

A Boolean expression is any expression whose result is either:

true

or:

false

Example:

int age = 25;

boolean isAdult = age >= 18;

Evaluate the right side:

age >= 18

Substitute the current value of age:

25 >= 18

That statement is true, so Java stores:

true

in isAdult.

Therefore:

System.out.println(isAdult);

prints:

true

Other Boolean expressions include:

temperature < 32
score == 100
x != y
balance >= withdrawal
name.equals("Alice")

Every one of these expressions evaluates to either true or false.

6. Relational operators

Relational operators compare values.

Example:

int x = 15;

System.out.println(x > 10);   // true
System.out.println(x < 10);   // false
System.out.println(x == 15);  // true
System.out.println(x != 20);  // true
System.out.println(x >= 15);  // true

Notice that each comparison produces a Boolean result.

7. Understanding boundary vocabulary

Programming requirements frequently use phrases such as:

  • at least
  • at most
  • greater than
  • more than
  • less than
  • fewer than
  • no more than
  • no less than
  • inclusive
  • exclusive

These words must be translated precisely.

Example: "at least 18"

The phrase:

age must be at least 18

means:

age >= 18

It does not mean:

age > 18

Someone who is exactly 18 satisfies "at least 18."

8. Assignment = versus equality ==

One of the most important beginner distinctions is:

=

versus:

==

They have completely different meanings.

8.1 Assignment

A single equals sign means assignment.

x = 5;

means:

Store the value 5 in x.

Assignment changes the value stored in a variable.

8.2 Equality comparison

A double equals sign means comparison.

x == 5

means:

Is the value currently stored in x equal to 5?

It produces a Boolean result.

For example:

int x = 5;

System.out.println(x == 5);

prints:

true

A helpful mental model is:

=   → store something
==  → ask whether two values are equal

9. The basic if statement

The simplest decision structure is an if statement.

Syntax:

if (condition) {
    statements;
}

The code inside the braces executes only when the condition is true.

Example:

int temperature = 30;

if (temperature < 32) {
    System.out.println("Freezing warning.");
}

Java evaluates:

temperature < 32

Substitute:

30 < 32

The result is:

true

Therefore the message executes.

If instead:

int temperature = 45;

the condition becomes:

45 < 32

which is false.

The body is skipped.

10. Statements before and after an if

Consider:

int age = 20;

System.out.println("Starting");

if (age >= 18) {
    System.out.println("Adult");
}

System.out.println("Ending");

Execution proceeds:

  1. print "Starting";
  2. evaluate age >= 18;
  3. execute "Adult" if the condition is true;
  4. continue after the if;
  5. print "Ending".

Since age is 20:

Starting
Adult
Ending

If age were 15:

Starting
Ending

The statement after the if executes in either case.

11. Blocks and braces

Curly braces define a block:

{
    // statements
}

Example:

if (score >= 90) {
    System.out.println("Excellent.");
    System.out.println("You earned an A.");
    System.out.println("Great work!");
}

All three statements belong to the if.

Java technically allows braces to be omitted when an if controls exactly one statement:

if (score >= 90)
    System.out.println("Excellent.");

For this course, prefer:

if (score >= 90) {
    System.out.println("Excellent.");
}

Using braces consistently:

  • makes the structure obvious;
  • reduces mistakes;
  • makes later modifications safer;
  • makes nested conditions easier to understand.

12. Why indentation alone is not enough

Consider:

if (score >= 60)
    System.out.println("Pass");
    System.out.println("Congratulations");

A human might visually interpret both println statements as belonging to the if.

Java does not.

Without braces, only the first statement belongs to the if.

Java effectively interprets the program as:

if (score >= 60) {
    System.out.println("Pass");
}

System.out.println("Congratulations");

Therefore "Congratulations" prints regardless of the score.

Important distinction:

Indentation communicates structure to humans. Braces establish structure for Java.

Use both correctly.

13. A semicolon after if

Consider this incorrect code:

if (x > 0); {
    System.out.println("Positive");
}

The semicolon immediately after the condition is a complete empty statement.

Conceptually, Java sees something like:

if (x > 0) {
    // do nothing
}

{
    System.out.println("Positive");
}

Therefore "Positive" executes regardless of whether x > 0.

Correct:

if (x > 0) {
    System.out.println("Positive");
}

14. The if-else statement

Sometimes a program must choose exactly one of two alternatives.

Syntax:

if (condition) {
    statementsIfTrue;
} else {
    statementsIfFalse;
}

Example:

int score = 75;

if (score >= 60) {
    System.out.println("Pass");
} else {
    System.out.println("Fail");
}

Because:

75 >= 60

is true, Java executes:

Pass

The else block is skipped.

If score were 50, Java would execute:

Fail

Exactly one branch executes.

15. Conditionals can assign values

Conditional statements are not only for printing messages.

They can determine values.

Example:

int a = 17;
int b = 42;

int maximum;

if (a > b) {
    maximum = a;
} else {
    maximum = b;
}

System.out.println("Maximum: " + maximum);

Since 42 is larger than 17:

Maximum: 42

The decision determines what value is stored in maximum.

16. Tracing an if-else

Consider:

int balance = 500;
int withdrawal = 700;

if (withdrawal <= balance) {
    balance = balance - withdrawal;
    System.out.println("Withdrawal approved.");
} else {
    System.out.println("Insufficient funds.");
}

Start with the variable values:

balance = 500
withdrawal = 700

Evaluate:

withdrawal <= balance

Substitute:

700 <= 500

Result:

false

Therefore Java skips the first branch and executes:

Insufficient funds.

Because the subtraction never executes, the final value of balance remains:

500

This is an important tracing principle:

Statements in a branch that is not selected do not execute and therefore cannot change variables.

17. Multiple alternatives with else if

Many decisions involve more than two possibilities.

For example:

90–100    A
80–89     B
70–79     C
60–69     D
below 60  F

A Java implementation is:

if (score >= 90) {
    System.out.println("A");
} else if (score >= 80) {
    System.out.println("B");
} else if (score >= 70) {
    System.out.println("C");
} else if (score >= 60) {
    System.out.println("D");
} else {
    System.out.println("F");
}

Java evaluates the branches from top to bottom.

The first condition that evaluates to true wins.

All remaining branches are skipped.

18. Tracing an else-if chain

Suppose:

int score = 83;

Trace:

First condition

score >= 90

becomes:

83 >= 90 → false

Continue.

Second condition

score >= 80

becomes:

83 >= 80 → true

Java executes:

System.out.println("B");

Then the rest of the chain is skipped.

Java does not evaluate:

score >= 70

or:

score >= 60

once a branch has already been selected.

19. Why else-if order matters

Consider:

int score = 95;

if (score >= 60) {
    System.out.println("D");
} else if (score >= 70) {
    System.out.println("C");
} else if (score >= 80) {
    System.out.println("B");
} else if (score >= 90) {
    System.out.println("A");
}

You might expect "A".

But Java starts at the top.

The first test is:

95 >= 60 → true

Therefore Java prints:

D

and skips everything else.

The problem is that the conditions overlap.

A score of 95 satisfies all of these:

score >= 60
score >= 70
score >= 80
score >= 90

The most restrictive condition should be tested first:

if (score >= 90) {
    System.out.println("A");
} else if (score >= 80) {
    System.out.println("B");
} else if (score >= 70) {
    System.out.println("C");
} else if (score >= 60) {
    System.out.println("D");
} else {
    System.out.println("F");
}

20. Taking advantage of what previous branches tell us

Consider:

if (temperature < 32) {
    System.out.println("Freezing");
} else if (temperature < 60) {
    System.out.println("Cold");
} else if (temperature < 80) {
    System.out.println("Mild");
} else {
    System.out.println("Hot");
}

Why doesn't the second test need to say:

temperature >= 32 && temperature < 60

Because if Java reaches the second condition, we already know that:

temperature < 32

was false.

Therefore we already know:

temperature >= 32

The earlier branch has established part of the range for us.

This is a powerful reasoning technique:

At each else if, ask what must already be known because all earlier conditions were false.

21. Independent if statements versus an else-if chain

These two structures are not equivalent.

21.1 Independent if statements

if (condition1) {
    ...
}

if (condition2) {
    ...
}

Both conditions are evaluated.

Both bodies may execute.

21.2 if-else-if

if (condition1) {
    ...
} else if (condition2) {
    ...
}

Once one branch succeeds, later alternatives are skipped.

22. Example: Independent conditions

Suppose:

int temperature = 20;
int windSpeed = 50;
boolean snowing = true;

We want to issue every relevant warning:

if (temperature < 32) {
    System.out.println("Freezing warning.");
}

if (windSpeed > 40) {
    System.out.println("High wind warning.");
}

if (snowing) {
    System.out.println("Snow warning.");
}

Output:

Freezing warning.
High wind warning.
Snow warning.

All three conditions can legitimately apply.

Therefore independent if statements are appropriate.

23. Example: Mutually exclusive categories

Suppose a temperature should receive exactly one description:

if (temperature < 32) {
    System.out.println("Freezing");
} else if (temperature < 60) {
    System.out.println("Cold");
} else if (temperature < 80) {
    System.out.println("Mild");
} else {
    System.out.println("Hot");
}

A temperature should not simultaneously be classified as:

Freezing
Cold
Mild
Hot

Only one category should be selected.

Therefore an if-else-if chain is appropriate.

24. A common grade-classification bug

Incorrect:

char grade = '?';

if (score >= 90) {
    grade = 'A';
}

if (score >= 80) {
    grade = 'B';
}

if (score >= 70) {
    grade = 'C';
}

Suppose:

score = 95;

Then:

score >= 90 → true → grade = 'A'
score >= 80 → true → grade = 'B'
score >= 70 → true → grade = 'C'

The final value is:

'C'

The correct structure is:

if (score >= 90) {
    grade = 'A';
} else if (score >= 80) {
    grade = 'B';
} else if (score >= 70) {
    grade = 'C';
} else {
    grade = 'F';
}

25. Logical operators

Relational operators let us create simple conditions.

Logical operators let us combine them into more complex rules.

Java's three major logical operators are:

OperatorNameMeaning
&&ANDboth operands must be true
``ORat least one operand must be true
!NOTreverses a Boolean value

26. Logical AND: &&

The expression:

A && B

is true only when both operands are true.

Truth table

ABA && B
falsefalsefalse
falsetruefalse
truefalsefalse
truetruetrue

Example:

int age = 25;
boolean hasTicket = true;

if (age >= 18 && hasTicket) {
    System.out.println("Entry allowed.");
}

Two requirements exist:

  1. age must be at least 18;
  2. the person must have a ticket.

Both must be satisfied.

27. Logical OR: ||

The expression:

A || B

is true if at least one operand is true.

Truth table:

AB`AB`
falsefalsefalse
falsetruetrue
truefalsetrue
truetruetrue

Example:

boolean isWeekend = false;
boolean isHoliday = true;

if (isWeekend || isHoliday) {
    System.out.println("Office is closed.");
}

The office is closed because at least one condition is true.

Important:

Java's || means "one or both," not "exactly one."

28. Logical NOT: !

The NOT operator reverses a Boolean value.

!true  → false
!false → true

Example:

boolean loggedIn = false;

if (!loggedIn) {
    System.out.println("Please log in.");
}

Read:

!loggedIn

as:

not logged in

Because loggedIn is false:

!false → true

so the message is displayed.

29. Choosing AND versus OR

Consider:

A student may register only if the prerequisite is complete and there is no registration hold.

if (completedPrerequisite && !hasHold) {
    System.out.println("Registration allowed.");
}

Both requirements must hold.

Now consider:

A discount applies if the customer is under 18 or at least 65.

if (age < 18 || age >= 65) {
    System.out.println("Discount applies.");
}

Either condition is sufficient.

A useful starting translation is:

and → &&
or  → ||
not → !

But do not mechanically replace words.

First understand the actual rule.

30. Conditions representing ranges

Suppose we want:

x is between 1 and 10 inclusive.

Mathematically, you might write:

1 <= x <= 10

Java does not support that chained comparison syntax.

This is invalid:

if (1 <= x <= 10) {
    ...
}

Instead:

if (x >= 1 && x <= 10) {
    System.out.println("x is between 1 and 10.");
}

Why AND?

Because both statements must be true:

x >= 1
AND
x <= 10

31. Inside a range: Use AND

General pattern:

value >= minimum && value <= maximum

Example:

if (score >= 0 && score <= 100) {
    System.out.println("Valid score.");
}

For the score to be valid, it must satisfy both boundaries.

32. Outside a range: Use OR

Suppose valid values are from 1 through 10.

A value is invalid if:

  • it is less than 1, or
  • it is greater than 10.

Therefore:

if (x < 1 || x > 10) {
    System.out.println("Invalid value.");
}

General pattern:

inside a range  → AND
outside a range → OR

33. Common range error: OR when AND is needed

Suppose the requirement is:

Age must be between 18 and 65 inclusive.

Incorrect:

if (age >= 18 || age <= 65) {
    ...
}

Try:

age = 10

Then:

age >= 18 → false
age <= 65 → true

false || true → true

So 10 incorrectly passes.

Try:

age = 90

Then:

age >= 18 → true

so the entire OR expression is already true.

The correct expression is:

if (age >= 18 && age <= 65) {
    ...
}

34. Impossible conditions

Consider:

if (age < 18 && age > 65) {
    ...
}

Can this ever be true?

No.

A number cannot simultaneously be:

less than 18

and:

greater than 65

If the intended requirement is "outside 18 through 65," use:

if (age < 18 || age > 65) {
    ...
}

36. Combining several requirements

Suppose registration requires all three conditions:

  • age is at least 18;
  • the account is active;
  • the user accepted the terms.

Write:

if (age >= 18 && accountActive && acceptedTerms) {
    System.out.println("Registration allowed.");
}

Now suppose access is allowed if:

  • the person is an administrator,

or

  • the person is an employee and completed training.

Write:

if (isAdmin || (isEmployee && completedTraining)) {
    System.out.println("Access granted.");
}

The parentheses communicate the grouping:

administrator
OR
(employee AND completed training)

37. Operator precedence

Operators are not all evaluated with equal priority.

A useful simplified precedence ordering for the operators used this week is:

  1. parentheses: ()
  2. arithmetic operations such as *, /, %, +, -
  3. relational comparisons: <, <=, >, >=
  4. equality comparisons: ==, !=
  5. logical NOT: ! as applicable to Boolean operands
  6. logical AND: &&
  7. logical OR: ||

For example:

age >= 18 && score >= 70

is understood as:

(age >= 18) && (score >= 70)

And:

isAdmin || isEmployee && trained

evaluates the AND portion first:

isAdmin || (isEmployee && trained)

However, readable programming should not depend on a reader memorizing every precedence rule.

Prefer parentheses when they make intent clearer:

if (isAdmin || (isEmployee && trained)) {
    ...
}

38. Use parentheses to communicate meaning

Compare:

if (age >= 18 && citizen || hasVisa) {
    ...
}

with:

if ((age >= 18 && citizen) || hasVisa) {
    ...
}

The second version makes the intended grouping much easier to see.

Parentheses are not merely mathematical decoration.

They communicate structure.

39. Boolean variables can improve readability

Consider:

if (age >= 18 &&
    age <= 65 &&
    hasLicense &&
    !licenseSuspended) {

    System.out.println("Eligible");
}

This is valid, but a more descriptive version may be easier to understand:

boolean validAge =
        age >= 18 && age <= 65;

boolean validLicense =
        hasLicense && !licenseSuspended;

boolean eligible =
        validAge && validLicense;

if (eligible) {
    System.out.println("Eligible");
}

Meaningful Boolean variable names turn complicated logic into readable concepts.

40. Do not write == true unnecessarily

Suppose:

boolean eligible = age >= 18;

This is legal:

if (eligible == true) {
    ...
}

but unnecessarily verbose.

Prefer:

if (eligible) {
    ...
}

Similarly, instead of:

if (eligible == false) {
    ...
}

prefer:

if (!eligible) {
    ...
}

This is standard Java style.

41. De Morgan's laws

De Morgan's laws describe how NOT interacts with AND and OR.

They are:

!(A && B)  ≡  !A || !B

and:

!(A || B)  ≡  !A && !B

The important idea is:

Negating a compound expression reverses each component and changes AND to OR, or OR to AND.

Example:

!(age >= 18 && age <= 65)

means:

It is not true that the age is between 18 and 65.

Equivalent:

age < 18 || age > 65

This is exactly the relationship between being inside and outside a range.

42. Negating comparisons

Useful opposites include:

OriginalNegation
x == yx != y
x != yx == y
x < yx >= y
x <= yx > y
x > yx <= y
x >= yx < y

For example, the opposite of:

score >= 60

is:

score < 60

It is not:

score <= 60

Why?

Because 60 satisfies the original expression:

60 >= 60 → true

Therefore it must not also satisfy its logical opposite.

43. Short-circuit evaluation

Java uses short-circuit evaluation for && and ||.

This means Java may stop evaluating a Boolean expression once the final result is already known.

43.1 Short-circuit AND

Consider:

A && B

If A is false, the entire expression must be false.

There is no reason to evaluate B.

Example:

int denominator = 0;

if (denominator != 0 && 100 / denominator > 5) {
    System.out.println("Condition satisfied.");
}

Java first checks:

denominator != 0

which becomes:

0 != 0 → false

Because:

false && anything → false

Java stops.

It does not evaluate:

100 / denominator

Therefore no division-by-zero calculation is attempted.

The order matters.

This safer expression:

denominator != 0 && 100 / denominator > 5

should not be carelessly reversed to:

100 / denominator > 5 && denominator != 0

because the dangerous division would be attempted first.

44. Short-circuit OR

Consider:

A || B

If A is true, the entire expression must be true.

Therefore Java does not need to evaluate B.

For example:

boolean isAdmin = true;
boolean specialPermission = false;

if (isAdmin || specialPermission) {
    System.out.println("Access granted.");
}

Once isAdmin is found to be true, Java already knows that the entire OR expression is true.

Short-circuit evaluation is:

  • an efficiency feature;
  • part of Java's evaluation rules;
  • sometimes a useful safety technique.

45. Nested if statements

An if statement can appear inside another if.

Example:

int age = 25;
boolean hasTicket = true;

if (age >= 18) {
    if (hasTicket) {
        System.out.println("Entry allowed.");
    }
}

The inner condition:

hasTicket

is evaluated only if:

age >= 18

is true.

This is called a nested conditional.

46. Nested conditions versus combined conditions

This:

if (age >= 18) {
    if (hasTicket) {
        System.out.println("Entry allowed.");
    }
}

can be written as:

if (age >= 18 && hasTicket) {
    System.out.println("Entry allowed.");
}

For this simple case, the combined form is usually cleaner.

However, nesting becomes useful when different actions are needed inside a branch.

Example:

if (age >= 18) {
    if (hasTicket) {
        System.out.println("Entry allowed.");
    } else {
        System.out.println("You need a ticket.");
    }
} else {
    System.out.println("You must be at least 18.");
}

Now the nested structure communicates additional information about why entry was denied.

47. Nested if versus else if

These structures solve different problems.

else if

Use else if when choosing one option from several alternatives:

if (temperature >= 90) {
    System.out.println("Hot");
} else if (temperature >= 60) {
    System.out.println("Warm");
} else {
    System.out.println("Cold");
}

Nested if

Use nesting when one decision conceptually depends on another:

if (usernameCorrect) {
    if (passwordCorrect) {
        System.out.println("Login successful.");
    }
}

The second question is considered only after the first requirement has been satisfied.

48. The dangling else

Without braces, nested conditionals can become confusing:

if (x > 0)
    if (y > 0)
        System.out.println("Both positive");
    else
        System.out.println("Which if owns this else?");

Java associates an else with the nearest preceding unmatched if.

Therefore the else belongs to:

if (y > 0)

not:

if (x > 0)

Use braces:

if (x > 0) {
    if (y > 0) {
        System.out.println("Both positive");
    } else {
        System.out.println("x is positive, but y is not.");
    }
}

Consistent braces remove ambiguity.

49. Comparing primitive values

Primitive types include values such as:

int
double
char
boolean

For primitive values, == compares values.

Example:

int a = 5;
int b = 5;

if (a == b) {
    System.out.println("Equal");
}

Output:

Equal

50. Comparing char values

A char is a primitive type.

Therefore:

char grade = 'A';

if (grade == 'A') {
    System.out.println("Excellent");
}

is correct.

Remember the distinction:

'A'

is a char.

But:

"A"

is a String.

Single quotes are used for a character.

Double quotes are used for a string.

51. Comparing strings

String comparison requires special care.

Do not normally use:

==

to ask whether two strings contain the same text.

Incorrect beginner-style comparison:

String answer = "yes";

if (answer == "yes") {
    ...
}

Instead, use:

.equals()

Correct:

String answer = "yes";

if (answer.equals("yes")) {
    System.out.println("Accepted.");
}

Why?

For primitive values, == compares the primitive values themselves.

For objects such as String, == asks whether the references refer to the same object.

The full meaning of object references will be studied later.

For Week 2, remember:

int x = 5;

if (x == 5) {
    ...
}

but:

String name = "Alice";

if (name.equals("Alice")) {
    ...
}

52. Case-insensitive string comparison

Sometimes capitalization should not matter.

Use:

.equalsIgnoreCase()

Example:

String answer = "YES";

if (answer.equalsIgnoreCase("yes")) {
    System.out.println("You answered yes.");
}

The comparison succeeds for values such as:

yes
YES
Yes
yEs

This is especially useful for simple command-style user input.

53. Example: Login decision

String correctPassword = "secret123";

  • known username but incorrect password;
  • successful login.

54. Floating-point comparisons

Be cautious when comparing double values with ==.

Consider:

double result = 0.1 + 0.2;

System.out.println(result);

Many decimal fractions cannot be represented exactly in binary floating-point form.

Therefore a condition such as:

if (result == 0.3) {
    ...
}

may not behave as expected.

A common approach is to compare whether the values are sufficiently close:

double tolerance = 0.000001;

if (Math.abs(result - 0.3) < tolerance) {
    System.out.println("Approximately equal.");
}

For this course, the main lesson is:

Exact equality is usually straightforward for integers, but calculated floating-point values often require more care.

55. Input validation

Programs should not blindly assume that user input is meaningful.

Input validation means checking whether input satisfies the program's requirements before using it.

Suppose a percentage must be between 0 and 100.

import java.util.Scanner;

public class PercentageValidator {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        System.out.print("Enter percentage: ");
        double percentage = input.nextDouble();

        if (percentage >= 0 && percentage <= 100) {
            System.out.println("Valid percentage.");
        } else {
            System.out.println("Invalid percentage.");
        }

        input.close();
    }
}

The valid interval is:

0 ≤ percentage ≤ 100

Therefore:

percentage >= 0 && percentage <= 100

56. Testing invalidity instead

The same validation can be expressed from the opposite direction.

Valid:

percentage >= 0 && percentage <= 100

Invalid:

percentage < 0 || percentage > 100

Example:

if (percentage < 0 || percentage > 100) {
    System.out.println("Invalid percentage.");
} else {
    System.out.println("Valid percentage.");
}

Both forms are logically correct.

Choose the version that best communicates the program's intent.

57. Why validate input?

Invalid input can cause:

  • meaningless calculations;
  • incorrect classifications;
  • impossible program states;
  • misleading output;
  • unsafe operations;
  • runtime errors in some situations.

Suppose the program calculates:

double average = total / numberOfItems;

If:

numberOfItems == 0

the operation may be invalid or meaningless.

A condition can protect the calculation:

if (numberOfItems != 0) {
    double average = total / numberOfItems;
    System.out.println(average);
} else {
    System.out.println("Cannot compute an average with zero items.");
}

58. Validation before calculation

A good design pattern is:

read input
   ↓
validate input
   ↓
if invalid:
    report problem
else:
    perform calculation

Example:

double height = -1.75;

if (height <= 0) {
    System.out.println("Invalid height.");
} else {
    double value = 100 / height;
    System.out.println(value);
}

The calculation happens only after the input has passed validation.

59. Example: Age validation and classification

int age = 16;

if (age < 0) {
    System.out.println("Invalid age.");
} else if (age < 13) {
    System.out.println("Child");
} else if (age < 20) {
    System.out.println("Teenager");
} else {
    System.out.println("Adult");
}

Notice the accumulated knowledge.

If Java reaches:

else if (age < 13)

we already know:

age >= 0

because otherwise the first branch would have executed.

If Java reaches:

else if (age < 20)

we already know:

age >= 13

because the previous test failed.

This is why carefully ordered conditions can be both shorter and easier to read.

60. Boundary cases

A boundary case is a value at or very near the edge of a condition.

Suppose valid ages are:

18 through 65 inclusive

Condition:

age >= 18 && age <= 65

Important test values include:

17
18
19
64
65
66

Why?

Because errors frequently occur exactly at boundaries.

For example:

age > 18

incorrectly rejects 18.

And:

age < 65

incorrectly rejects 65.

61. Off-by-one errors

An off-by-one error occurs when a boundary differs from the intended condition by one step.

Requirement:

A person must be at least 18.

Correct:

age >= 18

Incorrect:

age > 18

The incorrect expression excludes someone who is exactly 18.

Requirement:

Valid scores range from 0 through 100 inclusive.

Correct:

score >= 0 && score <= 100

Incorrect:

score > 0 && score < 100

The second expression incorrectly excludes:

0
100

Whenever writing <, >, <=, or >=, ask:

Should the boundary itself count?

62. Testing conditions systematically

Do not test a conditional using only one "normal" value.

For:

if (age >= 18) {
    ...
}

use values such as:

10
17
18
19
40

For:

score >= 0 && score <= 100

test:

-1
0
1
50
99
100
101

A good testing pattern is:

  1. clearly below the valid region;
  2. immediately below a boundary;
  3. exactly on the boundary;
  4. immediately above the boundary;
  5. clearly inside the region;
  6. exactly on the upper boundary;
  7. immediately above it.

  1. identify the individual facts;
  2. express each fact as a Boolean condition;
  3. decide how those facts relate;
  4. combine them;
  5. test representative examples.

69. Writing readable conditions

A Boolean expression can be logically correct while still being difficult to understand.

For example:

if ((age >= 18 && hasID && !isSuspended) ||
    (isEmployee && managerApproved) ||
    isAdministrator) {
    ...
}

A more readable version might use intermediate Boolean variables:

boolean normalAccess =
        age >= 18 &&
        hasID &&
        !isSuspended;

boolean employeeAccess =
        isEmployee &&
        managerApproved;

boolean accessAllowed =
        normalAccess ||
        employeeAccess ||
        isAdministrator;

if (accessAllowed) {
    System.out.println("Access granted.");
}

The goal is not to write the shortest possible code.

The goal is to make the logic understandable.

70. Prefer positive, direct conditions

Compare:

if (!(age < 18)) {
    ...
}

with:

if (age >= 18) {
    ...
}

The second is usually easier to read.

Similarly, instead of:

if (loggedIn == true) {
    ...
}

prefer:

if (loggedIn) {
    ...
}

Instead of:

if (loggedIn == false) {
    ...
}

prefer:

if (!loggedIn) {
    ...
}

Readable logic reduces mistakes.

71. The conditional operator ?:

Java also provides a compact conditional operator:

condition ? valueIfTrue : valueIfFalse

Example:

String result =
        score >= 60 ? "Pass" : "Fail";

Equivalent if-else:

String result;

if (score >= 60) {
    result = "Pass";
} else {
    result = "Fail";
}

It is often called the ternary operator because it has three operands:

  1. the condition;
  2. the value used when true;
  3. the value used when false.

Use it for simple value selection.

Avoid complicated nested ternary expressions in beginner code.

72. Worked example: Shipping cost

Suppose:

Order under $25       → $7.99 shipping
$25 through $49.99    → $4.99 shipping
$50 or more           → free shipping

Implementation:

double orderTotal = 42.50;
double shipping;

if (orderTotal >= 50) {
    shipping = 0.0;
} else if (orderTotal >= 25) {
    shipping = 4.99;
} else {
    shipping = 7.99;
}

System.out.println("Shipping: $" + shipping);

For:

orderTotal = 42.50

Trace:

42.50 >= 25 → true

Therefore:

shipping = 4.99

Notice that the second test does not need:

orderTotal >= 25 && orderTotal < 50

If Java reaches the second test, we already know the total is below 50.

73. Worked example: Leap year logic

A leap year follows this rule:

  • divisible by 400, or
  • divisible by 4 but not divisible by 100.

A number is divisible by another number when the remainder is zero.

For example:

year % 4 == 0

means the year is divisible by 4.

The complete Boolean expression is:

boolean leapYear =
        year % 400 == 0 ||
        (year % 4 == 0 && year % 100 != 0);

Then:

if (leapYear) {
    System.out.println("Leap year");
} else {
    System.out.println("Not a leap year");
}

This is a good example of why parentheses and intermediate Boolean variables improve readability.

74. Worked example: Triangle validation

Suppose a, b, and c represent side lengths.

For three positive lengths to form a triangle:

a + b > c
a + c > b
b + c > a

All conditions must hold.

boolean validTriangle =
        a > 0 &&
        b > 0 &&
        c > 0 &&
        a + b > c &&
        a + c > b &&
        b + c > a;

if (validTriangle) {
    System.out.println("Valid triangle");
} else {
    System.out.println("Invalid triangle");
}

This demonstrates a general programming skill:

Translate a mathematical or domain definition directly into Boolean conditions.

77. Complete program: BMI classification

import java.util.Scanner;

public class BMIClassifier {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        System.out.print("Enter weight in kilograms: ");
        double weight = input.nextDouble();

        System.out.print("Enter height in meters: ");
        double height = input.nextDouble();

        if (weight <= 0 || height <= 0) {

            System.out.println("Invalid input.");

        } else {

            double bmi = weight / (height * height);

            System.out.printf("BMI: %.1f%n", bmi);

            if (bmi < 18.5) {
                System.out.println("Underweight");
            } else if (bmi < 25.0) {
                System.out.println("Normal range");
            } else if (bmi < 30.0) {
                System.out.println("Overweight");
            } else {
                System.out.println("Obesity range");
            }
        }

        input.close();
    }
}

Important observations:

  1. invalid values are checked before the BMI calculation;
  2. the BMI calculation runs only after the input is validated;
  3. nested branching separates validation from classification;
  4. category boundaries are ordered;
  5. each later category takes advantage of information established by earlier failed tests.

79. Code tracing

You should be able to predict the behavior of conditional code without running it.

Consider:

int x = 8;
int y = 3;

    y = y + 2;
}

if (y > 4) {
    x = x - 3;
} else {
    x = x + 3;
}

System.out.println(x);
System.out.println(y);

Do not jump to the output.

Trace systematically.

Step 1: Initial values

x = 8
y = 3

Step 2: First condition

x > 5

Substitute:

Execute:

y = y + 2;

So:

y = 5

Current state:

x = 8
y = 5

Step 3: Second condition

y > 4

Substitute the current value:

5 > 4 → true

Therefore:

x = x - 3;

So:

x = 5

Step 4: Final output

5
5

A key tracing principle is:

Always use the variable's current value, not necessarily its original value.

81. A systematic debugging process

When a conditional program behaves incorrectly, do not randomly change operators.

Use a systematic process.

Step 1: Identify the exact rule

Suppose your condition is:

age >= 18 && hasPermission

Ask what the requirement actually says.

Step 2: Inspect the variable values

System.out.println("age = " + age);
System.out.println(
        "hasPermission = " + hasPermission);

Step 3: Evaluate individual pieces

System.out.println(age >= 18);
System.out.println(hasPermission);

Step 4: Evaluate the combined condition

System.out.println(
        age >= 18 && hasPermission);

Step 5: Check boundaries

Test:

17
18
19

Step 6: Translate the code back into English

age >= 18 && hasPermission

means:

Age is at least 18 AND permission is present.

If that does not match the original requirement, the condition is wrong.

82. Debugging checklist

When a decision behaves incorrectly, ask:

  1. What values do the variables currently contain?
  2. What exact condition is being evaluated?
  3. What does each individual comparison evaluate to?
  4. Did I accidentally use = instead of ==?
  5. Should this use && or ||?
  6. Should a boundary be inclusive or exclusive?
  7. Are overlapping conditions ordered correctly?
  8. Should these be independent if statements?
  9. Or should they form an if-else-if chain?
  10. Are braces placed correctly?
  11. Is there an accidental semicolon after if (...)?
  12. Am I comparing strings with .equals()?
  13. Have I used meaningful Boolean variable names?
  14. Have I tested the true case?
  15. Have I tested the false case?
  16. Have I tested the boundary cases?

Mistake 1: Assignment instead of comparison

Incorrect:

x = 5

when the intent is to ask whether x equals 5.

Correct comparison:

x == 5

Mistake 2: Comparing strings using ==

Avoid:

name == "Alice"

Use:

name.equals("Alice")

Mistake 3: Using OR for an inside range

Incorrect:

age >= 18 || age <= 65

Correct:

age >= 18 && age <= 65

Mistake 4: Using AND for an outside range

Incorrect:

age < 18 && age > 65

Correct:

age < 18 || age > 65

Mistake 5: Incorrect else-if ordering

Incorrect:

    ...
} else if (score >= 90) {
    ...
}

The first branch captures scores of 90 and above.

Mistake 6: Confusing independent decisions with alternatives

Independent:

    ...
}

    ...
}

Mutually exclusive alternatives:

if (condition1) {
    ...
} else if (condition2) {
    ...

    ...
}

Avoid:

    statement1;

Incorrect:

    ...

Mistake 9: Comparing a Boolean to true

84. How to approach a multi-rule programming problem

Before writing Java syntax, answer the following questions.

Question 1

What decision is the program making?

Question 2

What individual facts determine that decision?

Question 3

Which facts must all be true?

Use AND.

Question 4

Which facts are alternatives?

Use OR.

Question 5

Is some fact required to be false?

Use NOT or write the direct opposite comparison.

Question 6

Are there exactly two outcomes or several categories?

This helps determine whether you need:

if
if-else

or:

if-else-if

Question 7

Can several conditions independently apply?

If yes, consider separate if statements.

Question 8

Are there invalid inputs?

Validate them.

Question 9

What are the boundaries?

Identify values immediately below, on, and above each boundary.

Question 10

Can you explain the condition clearly in plain English?

If you cannot, the logic probably needs more work before coding.

    ...
}
if (score >= 0 && score <= 100) {
    ...
}

The expression must evaluate to true or false.

Q2. Can I put an integer directly in an if?

Not like this:

if (5) {
    ...
}

Java requires a Boolean condition.

Use something such as:

if (x == 5) {
    ...
}

Q3. Do I need else after every if?

No.

This is valid:

if (temperature < 32) {
    System.out.println("Freezing warning.");
}

Use else only when you need an alternative action.

Q4. Does every if-else-if chain need a final else?

No.

Example:

if (score >= 90) {
    System.out.println("Excellent");
} else if (score >= 80) {
    System.out.println("Very good");
}

If neither condition matches, nothing in the chain executes.

A final else is useful when there is a default case.

Q5. Can two separate if statements both execute?

Yes.

if (x > 0) {
    System.out.println("Positive");
}

if (x % 2 == 0) {
    System.out.println("Even");
}

If x is positive and even, both messages print.

Q6. Can two branches of the same if-else-if chain execute?

No.

Only the first matching branch executes.

Q7. Why doesn't Java allow 1 <= x <= 10?

Because Java evaluates comparisons as individual Boolean expressions.

Write:

x >= 1 && x <= 10

Q8. How do I remember AND versus OR for ranges?

For a value to be inside a range, it must satisfy both boundaries:

x >= min && x <= max

To be outside a range, it must violate either boundary:

x < min || x > max

So:

inside  → AND
outside → OR

Q9. Why is age >= 18 || age <= 65 almost always true?

Because nearly any number satisfies at least one half.

A young age satisfies:

age <= 65

A very large age satisfies:

age >= 18

If you mean "between 18 and 65," use AND.

Q10. When should I use nested if statements?

When one decision logically occurs inside another decision, especially when you need different actions or messages at each stage.

Q11. When should I combine nested conditions with &&?

When the nested structure does nothing except require both conditions.

Instead of:

if (adult) {
    if (hasTicket) {
        enter();
    }
}

conceptually prefer:

if (adult && hasTicket) {
    ...
}

when that representation is clearer.

Q12. Why use .equals() for strings?

Because String values are objects.

For text content comparison:

name.equals("Alice")

is the appropriate form.

Q13. When can I use ==?

== works naturally for primitive values such as:

int
char
boolean

For example:

x == 5
grade == 'A'

Be cautious with calculated double values and use .equals() for string contents.

Q14. Should I write if (flag == true)?

Usually no.

Prefer:

if (flag) {
    ...
}

And instead of:

if (flag == false) {
    ...
}

use:

if (!flag) {
    ...
}

Q15. Why are braces recommended when Java sometimes allows them to be omitted?

Because braces:

  • make the controlled block explicit;
  • prevent accidental bugs;
  • reduce dangling-else confusion;
  • make later modifications safer.

Q16. What is short-circuit evaluation?

For:

A && B

if A is false, Java does not evaluate B.

For:

A || B

if A is true, Java does not evaluate B.

Q17. What is the best way to debug a Boolean expression?

Break it into parts.

Instead of staring at:

age >= 18 &&
score >= 70 &&
hasPermission

print or trace:

age >= 18
score >= 70
hasPermission

separately.

Then combine the results.

Q18. What should I test first?

Boundary values.

If the condition is:

age >= 18

test:

17
18
19

If the valid range is:

score >= 0 && score <= 100

test:

-1
0
1
99
100
101

Q19. Do we repeatedly ask for input until it is valid this week?

This week focuses on detecting and responding to invalid input with conditional logic.

Repeatedly asking until input becomes valid requires iteration. Loops are introduced in Week 3, where this validation logic will naturally be combined with repetition.

Before submitting a conditional program, verify:

  • [ ] Every if condition evaluates to a Boolean.
  • [ ] I used == for primitive equality comparison.
  • [ ] I did not confuse = and ==.
  • [ ] I used .equals() for String contents.
  • [ ] I chose && when all requirements must hold.
  • [ ] I chose || when either requirement is sufficient.
  • [ ] I used AND for the inside of a range.
  • [ ] I used OR for the outside of a range.
  • [ ] My inclusive and exclusive boundaries are correct.
  • [ ] My else-if branches are in a sensible order.

  • [ ] I tested each possible branch.

92. Key takeaways

The most important ideas from Week 2 are:

  1. Programs make decisions by evaluating Boolean conditions.
  1. A Boolean expression evaluates to either true or false.
  1. Relational operators compare values.
   <  >  <=  >=  ==  !=
  1. Logical operators combine or negate conditions.
   &&  ||  !
  1. if executes code conditionally.
  1. if-else chooses between two alternatives.
  1. if-else-if chooses among several mutually exclusive alternatives.
  1. Separate if statements can all execute independently.
  1. Order matters when else-if conditions overlap.
  1. Inside a numeric range usually requires AND.
    x >= min && x <= max
  1. Outside a range usually requires OR.
    x < min || x > max
  1. Boundary values deserve special attention.
  1. Strings should normally be compared using .equals().
  1. Short-circuit evaluation can prevent unnecessary or unsafe evaluation.
  1. Nested decisions are useful when one decision depends on another.
  1. Input should be validated before the program relies on it.
  1. Readable Boolean logic is better than clever Boolean logic.
  1. Tracing code by hand is one of the best ways to learn how conditionals work.
  1. Testing should include true cases, false cases, and boundary cases.
  1. Conditional logic is fundamentally about translating real-world rules into precise computational rules.

93. Why this week matters

Conditional logic may initially appear to be a small Java syntax topic.

It is much more important than that.

Algorithms repeatedly ask questions such as:

Is this value the one I am looking for?

Is this value larger than the previous value?

Is this input valid?

Should this operation continue?

Which category does this value belong to?

Does this object satisfy a requirement?

Those questions become Boolean expressions.

Those Boolean expressions control what programs do.

As the course progresses, the same ability to reason precisely about conditions will appear in loops, methods, arrays, object-oriented programs, searching and sorting algorithms, linked data structures, trees, and many other areas of computer science.

The central skill to develop this week is therefore:

Given a rule stated in ordinary language, express that rule precisely as Boolean logic, verify that the logic is correct, and use it to control program execution.
