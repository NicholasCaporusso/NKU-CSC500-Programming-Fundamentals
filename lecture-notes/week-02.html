1. Programs need to make decisions

So far, the programs we have written execute statements sequentially.

For example:

int x = 10;
int y = 20;
int sum = x + y;
System.out.println(sum);

Every statement executes in order.

Real programs are usually more interesting because they behave differently depending on the situation.

For example:

  • If a student's grade is at least 60, display "Pass".
  • If the temperature is below freezing, display a warning.
  • If a password is incorrect, deny access.
  • If a bank account does not contain enough money, reject a withdrawal.
  • If a user is 18 or older, allow access to an adult-only feature.

This ability is called selection, branching, or decision-making.

A program evaluates a condition and chooses which code to execute.

Conceptually:

Is the condition true?

       yes
        |
        v
do something

       no
        |
        v
do something else

In Java, decisions are primarily expressed using the if statement.

2. Boolean values

A decision requires a condition.

A condition must ultimately evaluate to one of two values:

true

or

false

Java has a primitive data type specifically for these values:

boolean

For example:

boolean isRaining = true;
boolean isLoggedIn = false;

A Boolean variable can be used directly inside an if statement:

if (isRaining) {
    System.out.println("Take an umbrella.");
}

If isRaining is true, the message is printed.

If it is false, the body of the if statement is skipped.

3. Boolean expressions

Most Boolean values are not typed directly as true or false.

Instead, we create Boolean expressions.

For example:

int age = 25;

boolean adult = age >= 18;

The expression

age >= 18

evaluates to either true or false.

Because age is 25:

25 >= 18

is true.

Therefore:

adult

contains the value:

true

4. Relational operators

Java provides relational operators for comparing values.

Examples:

int x = 15;

System.out.println(x > 10);   // true
System.out.println(x < 10);   // false
System.out.println(x == 15);  // true
System.out.println(x != 20);  // true

5. A very important mistake: = vs ==

Beginning programmers frequently confuse:

=

and:

==

They mean completely different things.

The single equals sign:

=

means assignment.

Example:

x = 5;

This means:

Store the value 5 in variable x.

The double equals sign:

==

means comparison.

Example:

x == 5

This means:

Is the value stored in x equal to 5?

Consider:

int x = 10;

if (x == 10) {
    System.out.println("x is 10");
}

The expression:

x == 10

asks a question.

It does not change x.

6. The basic if statement

The syntax of an if statement is:

if (condition) {
    statements;
}

For example:

int temperature = 30;

if (temperature < 32) {
    System.out.println("Warning: freezing temperature.");
}

The program asks:

Is temperature < 32?

If the answer is true, the body executes.

If the answer is false, the body is skipped.

7. Understanding control flow

Consider:

int age = 20;

System.out.println("Starting program");

if (age >= 18) {
    System.out.println("Adult");
}

System.out.println("Ending program");

Execution proceeds as follows:

Starting program
        |
        v
Is age >= 18?
      /   \
    true  false
     |      |
  Adult     |
      \    /
       v
Ending program

Because age is 20, the output is:

Starting program
Adult
Ending program

If age were 15:

int age = 15;

the output would be:

Starting program
Ending program

8. Blocks and braces

The braces:

{
}

define a block of statements.

For example:

if (score >= 90) {
    System.out.println("Excellent");
    System.out.println("You earned an A.");
    System.out.println("Great work!");
}

All three statements belong to the if.

Although Java allows braces to be omitted when the body contains exactly one statement:

if (score >= 90)
    System.out.println("Excellent");

we will generally use braces.

Preferred style:

if (score >= 90) {
    System.out.println("Excellent");
}

This reduces bugs and makes code easier to modify.

9. The if-else statement

Sometimes we want exactly one of two alternatives.

Syntax:

if (condition) {
    statementsIfTrue;
} else {
    statementsIfFalse;
}

Example:

int score = 75;

if (score >= 60) {
    System.out.println("Pass");
} else {
    System.out.println("Fail");
}

Because:

75 >= 60

is true, the output is:

Pass

Exactly one branch executes.

10. Tracing an if-else

Consider:

int balance = 500;
int withdrawal = 700;

if (withdrawal <= balance) {
    balance = balance - withdrawal;
    System.out.println("Withdrawal approved.");
} else {
    System.out.println("Insufficient funds.");
}

Evaluate the condition:

withdrawal <= balance

Substitute the values:

700 <= 500

The expression is false.

Therefore Java skips the first branch and executes the else branch:

Insufficient funds.

The value of balance remains:

500

11. Multiple alternatives with else if

Many decisions involve more than two possibilities.

Consider letter grades:

90–100  A
80–89   B
70–79   C
60–69   D
below 60 F

We can write:

if (score >= 90) {
    System.out.println("A");
} else if (score >= 80) {
    System.out.println("B");
} else if (score >= 70) {
    System.out.println("C");
} else if (score >= 60) {
    System.out.println("D");
} else {
    System.out.println("F");
}

Java evaluates conditions from top to bottom.

As soon as one condition is true, its branch executes and the rest are skipped.

12. Why order matters

Suppose:

int score = 95;

Consider this incorrect code:

if (score >= 60) {
    System.out.println("D");
} else if (score >= 70) {
    System.out.println("C");
} else if (score >= 80) {
    System.out.println("B");
} else if (score >= 90) {
    System.out.println("A");
}

What happens?

The first condition is:

score >= 60

For a score of 95, that condition is true.

Therefore Java prints:

D

and skips the rest.

The correct ordering is:

if (score >= 90) {
    System.out.println("A");
} else if (score >= 80) {
    System.out.println("B");
} else if (score >= 70) {
    System.out.println("C");
} else if (score >= 60) {
    System.out.println("D");
} else {
    System.out.println("F");
}

When ranges overlap, order matters.

13. Conditions that represent ranges

Suppose we want to determine whether:

x is between 1 and 10

Mathematically we might write:

1 <= x <= 10

Java does not allow chained comparisons like this.

This is invalid:

if (1 <= x <= 10) {

Instead, we must write two comparisons and combine them:

if (x >= 1 && x <= 10) {
    System.out.println("x is between 1 and 10.");
}

This introduces logical operators.

14. Logical operators

Java has three major logical operators:

OperatorNameMeaning
&&ANDboth conditions must be true

15. Logical and: &&

The expression:

A && B

is true only when both A and B are true.

Truth table:

ABA && B
falsefalsefalse
falsetruefalse
truefalsefalse
truetruetrue

Example:

int age = 25;
boolean hasTicket = true;

if (age >= 18 && hasTicket) {
    System.out.println("Entry allowed.");
}

Both requirements must be satisfied.

16. Using and for ranges

Suppose:

int score = 85;

We want to determine whether the score is between 80 and 89 inclusive.

if (score >= 80 && score <= 89) {
    System.out.println("Grade B");
}

Another common version is:

if (score >= 80 && score < 90) {
    System.out.println("Grade B");
}

Both comparisons must be true.

17. Logical or: ||

The expression:

A || B

is true if at least one condition is true.

Truth table:

ABA \\B
falsefalsefalse
falsetruetrue
truefalsetrue
truetruetrue

Example:

boolean isWeekend = true;
boolean isHoliday = false;

if (isWeekend || isHoliday) {
    System.out.println("Office is closed.");
}

The office is closed if either condition is true.

18. And vs or

Suppose a student may register for a course only if:

  • the student completed the prerequisite, and
  • the student has no registration hold.

We need:

if (completedPrerequisite && !hasHold) {
    System.out.println("Registration allowed.");
}

Now suppose a student receives a discount if:

  • the student is under 18, or
  • the student is 65 or older.

We need:

if (age < 18 || age >= 65) {
    System.out.println("Discount applies.");
}

A useful translation rule is:

"and"  → &&
"or"   → ||
"not"  → !

But always think about the actual logic rather than mechanically replacing English words.

19. Logical not: !

The NOT operator reverses a Boolean value.

!true

becomes:

false

and:

!false

becomes:

true

Example:

boolean loggedIn = false;

if (!loggedIn) {
    System.out.println("Please log in.");
}

Read:

!loggedIn

as:

not logged in

20. Boolean variables make code easier to read

Instead of writing:

if (age >= 18 && age <= 65 && hasLicense && !licenseSuspended) {
    System.out.println("Eligible");
}

we can sometimes introduce meaningful variables:

boolean validAge = age >= 18 && age <= 65;
boolean validLicense = hasLicense && !licenseSuspended;

if (validAge && validLicense) {
    System.out.println("Eligible");
}

The second version can be easier to understand.

A good variable name can explain the meaning of a condition.

21. Operator precedence

Consider:

age >= 18 && citizen || hasVisa

Java applies operators according to precedence rules.

A simplified ordering for the operators we have seen is:

  1. Arithmetic operations
  2. Relational operators
  3. !
  4. &&
  5. ||

However, complicated Boolean expressions can become difficult to read.

Prefer parentheses when they clarify intent:

(age >= 18 && citizen) || hasVisa

Even if the parentheses are not technically required, they improve readability.

22. Short-circuit evaluation

Java uses short-circuit evaluation for && and ||.

This means Java may not evaluate the second part of a Boolean expression if the result is already known.

Consider AND:

A && B

If A is false, the entire expression must be false.

Java therefore does not need to evaluate B.

Example:

int denominator = 0;

if (denominator != 0 && 100 / denominator > 5) {
    System.out.println("Condition satisfied.");
}

Java first evaluates:

denominator != 0

This is false.

Since:

false AND anything

is false, Java stops.

It never evaluates:

100 / denominator

Therefore no divide-by-zero error occurs.

23. Short-circuit or

Consider:

A || B

If A is true, the entire expression must be true.

Java does not need to evaluate B.

Example:

if (isAdmin || hasPermission()) {
    ...
}

If isAdmin is already true, Java does not call:

hasPermission()

This behavior becomes especially important later when expressions include method calls.

24. Nested if statements

An if statement may contain another if statement.

Example:

int age = 25;
boolean hasTicket = true;

if (age >= 18) {
    if (hasTicket) {
        System.out.println("Entry allowed.");
    }
}

The inner condition is checked only if:

age >= 18

is true.

This is called a nested conditional.

25. Nested conditions vs combined conditions

The previous example:

if (age >= 18) {
    if (hasTicket) {
        System.out.println("Entry allowed.");
    }
}

can also be written as:

if (age >= 18 && hasTicket) {
    System.out.println("Entry allowed.");
}

These versions produce the same result.

When the logic is simple, the combined version is usually cleaner.

Nested conditions are useful when additional decisions occur only inside a particular branch.

26. Example: login system

Suppose a system checks both username and password.

String correctUsername = "alice";
String correctPassword = "secret123";

String username = "alice";
String password = "secret123";

if (username.equals(correctUsername)) {
    if (password.equals(correctPassword)) {
        System.out.println("Login successful.");
    } else {
        System.out.println("Incorrect password.");
    }
} else {
    System.out.println("Unknown username.");
}

The nested structure allows us to provide different messages depending on which check failed.

27. Comparing strings

This is an extremely important Java rule.

Do not normally compare strings using:

==

For example:

String name = "Alice";

if (name == "Alice") {

may appear to work in some cases, but it does not mean what beginning programmers usually think it means.

For strings, use:

.equals()

Correct:

if (name.equals("Alice")) {
    System.out.println("Hello Alice");
}

Why?

For primitive values such as:

int
double
char
boolean

== compares values.

For objects such as String, == compares object references.

We will explore references and objects in much greater detail when we study object-oriented programming.

For now, remember:

int x = 5;

if (x == 5) {

but:

String name = "Alice";

if (name.equals("Alice")) {

28. Case-insensitive string comparison

Sometimes capitalization should not matter.

For example:

String answer = "YES";

if (answer.equalsIgnoreCase("yes")) {
    System.out.println("You answered yes.");
}

This treats:

yes
YES
Yes
yEs

as equivalent.

29. Comparing char values

Characters are primitive values, so they can be compared with ==.

Example:

char grade = 'A';

if (grade == 'A') {
    System.out.println("Excellent.");
}

Remember:

'A'

is a char.

But:

"A"

is a String.

30. Floating-point comparisons

Be cautious when comparing double values with ==.

Consider:

double result = 0.1 + 0.2;

System.out.println(result);

Because computers represent many decimal values approximately, result may not be represented internally as exactly:

0.3

Therefore:

if (result == 0.3) {

can be unreliable.

Instead, compare using a small tolerance:

double tolerance = 0.000001;

if (Math.abs(result - 0.3) < tolerance) {
    System.out.println("Approximately equal.");
}

We will revisit numerical precision later.

31. Input validation

One important use of conditionals is checking whether user input is valid.

Suppose a percentage must be between 0 and 100.

Scanner input = new Scanner(System.in);

System.out.print("Enter percentage: ");
double percentage = input.nextDouble();

if (percentage >= 0 && percentage <= 100) {
    System.out.println("Valid percentage.");
} else {
    System.out.println("Invalid percentage.");
}

This is called validation.

Programs should not assume that every input is valid.

32. Example: age validation

System.out.print("Enter age: ");
int age = input.nextInt();

if (age < 0) {
    System.out.println("Invalid age.");
} else if (age < 13) {
    System.out.println("Child");
} else if (age < 20) {
    System.out.println("Teenager");
} else {
    System.out.println("Adult");
}

Notice that after checking:

age < 0

we do not need to repeat:

age >= 0

in the next condition.

If Java reaches:

else if (age < 13)

we already know that:

age >= 0

because otherwise the first branch would have executed.

Understanding what is already known at each branch is an important programming skill.

33. Mutually exclusive conditions

Consider:

if (score >= 90) {
    System.out.println("A");
}

if (score >= 80) {
    System.out.println("B");
}

If:

score = 95

both conditions are true.

The program prints:

A
B

This is because these are two independent if statements.

If we want exactly one grade, we need:

if (score >= 90) {
    System.out.println("A");
} else if (score >= 80) {
    System.out.println("B");
}

This distinction is important.

Use multiple independent if statements when multiple conditions may legitimately trigger.

Use an if-else-if chain when the alternatives are mutually exclusive.

34. Example: independent conditions

Suppose we examine weather conditions.

if (temperature < 32) {
    System.out.println("Freezing warning.");
}

if (windSpeed > 40) {
    System.out.println("High wind warning.");
}

if (snowing) {
    System.out.println("Snow warning.");
}

It is entirely possible that all three warnings should appear.

Therefore independent if statements are appropriate.

35. Example: mutually exclusive categories

Suppose we classify temperature:

if (temperature < 32) {
    System.out.println("Freezing");
} else if (temperature < 60) {
    System.out.println("Cold");
} else if (temperature < 80) {
    System.out.println("Mild");
} else {
    System.out.println("Hot");
}

Only one category should appear.

Therefore an if-else-if chain is appropriate.

36. Common error: incorrect range logic

Suppose we want:

age must be between 18 and 65.

Incorrect:

if (age >= 18 || age <= 65) {

Why is this incorrect?

Consider:

age = 10

The first condition:

age >= 18

is false.

But:

age <= 65

is true.

Therefore:

false || true

becomes true.

Now consider:

age = 90

The first condition:

age >= 18

is true.

Therefore the entire expression is true.

Almost every possible age passes the test.

Correct:

if (age >= 18 && age <= 65) {

Both boundaries must be satisfied simultaneously.

37. Common error: impossible conditions

Consider:

if (age < 18 && age > 65) {

Can this ever be true?

No.

A number cannot simultaneously be:

less than 18

and:

greater than 65

The programmer probably intended:

if (age < 18 || age > 65) {

This means the age lies outside the interval from 18 through 65.

38. Inside vs outside a range

Suppose we have:

18 <= age <= 65

Inside the range:

age >= 18 && age <= 65

Outside the range:

age < 18 || age > 65

This pattern occurs frequently.

General rule:

inside a range → AND
outside a range → OR

39. De morgan's laws

Logical expressions can often be rewritten.

Two important identities are:

!(A && B) = !A || !B

and:

!(A || B) = !A && !B

These are known as De Morgan's Laws.

For example:

!(age >= 18 && age <= 65)

means:

It is not true that age is between 18 and 65.

This is equivalent to:

age < 18 || age > 65

You do not need to memorize formal logic notation immediately, but these relationships become useful when designing and simplifying conditions.

40. The dangling else

Consider:

if (x > 0)
    if (y > 0)
        System.out.println("Both positive");
    else
        System.out.println("What does this else belong to?");

Without braces, this is difficult to read.

Java associates an else with the nearest unmatched if.

To remove ambiguity, use braces:

if (x > 0) {
    if (y > 0) {
        System.out.println("Both positive");
    } else {
        System.out.println("x is positive, but y is not.");
    }
}

Again, using braces consistently prevents many problems.

41. Indentation does not determine program structure

Consider:

if (score >= 60)
    System.out.println("Pass");
    System.out.println("Congratulations");

A human reader might think both statements belong to the if.

Java does not.

Without braces, only the first statement belongs to the if.

Java sees:

if (score >= 60) {
    System.out.println("Pass");
}

System.out.println("Congratulations");

Therefore "Congratulations" prints regardless of the score.

Indentation is for humans.

Braces determine program structure.

42. A complete example: shipping cost

Suppose shipping costs are:

Order under $25       → $7.99
$25 through $49.99    → $4.99
$50 or more           → free

Java:

double orderTotal = 42.50;
double shipping;

if (orderTotal >= 50) {
    shipping = 0.0;
} else if (orderTotal >= 25) {
    shipping = 4.99;
} else {
    shipping = 7.99;
}

System.out.println("Shipping: $" + shipping);

Notice that we do not need:

orderTotal >= 25 && orderTotal < 50

for the second condition.

Why?

If Java reaches the second condition, we already know:

orderTotal < 50

because otherwise the first branch would have executed.

43. Example: leap year

A leap year provides an excellent Boolean logic exercise.

A year is a leap year if:

  • it is divisible by 400, or
  • it is divisible by 4 but not divisible by 100.

We can express this as:

boolean leapYear =
        year % 400 == 0 ||
        (year % 4 == 0 && year % 100 != 0);

Then:

if (leapYear) {
    System.out.println("Leap year");
} else {
    System.out.println("Not a leap year");
}

This example demonstrates why parentheses and Boolean variables can make complex conditions easier to understand.

44. Example: triangle validation

Suppose three values represent the lengths of triangle sides.

For three positive lengths a, b, and c to form a triangle:

a + b > c
a + c > b
b + c > a

All three conditions must be true:

boolean validTriangle =
        a > 0 &&
        b > 0 &&
        c > 0 &&
        a + b > c &&
        a + c > b &&
        b + c > a;

if (validTriangle) {
    System.out.println("Valid triangle");
} else {
    System.out.println("Invalid triangle");
}

This is a useful example of translating a mathematical definition into code.

45. Example: maximum of two numbers

int a = 17;
int b = 42;

int maximum;

if (a > b) {
    maximum = a;
} else {
    maximum = b;
}

System.out.println("Maximum: " + maximum);

This demonstrates that conditionals can determine values, not just print messages.

46. Maximum of three numbers

One approach:

int a = 17;
int b = 42;
int c = 23;

int maximum = a;

if (b > maximum) {
    maximum = b;
}

if (c > maximum) {
    maximum = c;
}

System.out.println("Maximum: " + maximum);

Notice that we use two independent if statements.

Each asks whether the current candidate is larger than the maximum found so far.

This pattern will appear again when we study arrays and algorithms.

47. The conditional operator

Java also contains a compact conditional operator:

condition ? valueIfTrue : valueIfFalse

For example:

String result = score >= 60 ? "Pass" : "Fail";

This is equivalent to:

String result;

if (score >= 60) {
    result = "Pass";
} else {
    result = "Fail";
}

The conditional operator is sometimes called the ternary operator because it has three operands.

For now, use it only for simple situations.

Do not turn complicated decision logic into deeply nested ternary expressions.

48. Writing good conditions

Prefer conditions that are easy to read.

Instead of:

if (!(age < 18)) {

consider:

if (age >= 18) {

Instead of:

if (loggedIn == true) {

write:

if (loggedIn) {

Instead of:

if (loggedIn == false) {

write:

if (!loggedIn) {

Good programming is not just about making code work.

Code should also communicate its meaning clearly to other programmers.

49. Avoid comparing booleans with == true

Suppose:

boolean eligible = age >= 18;

This works:

if (eligible == true) {

But it is unnecessarily verbose.

Prefer:

if (eligible) {

Likewise:

if (eligible == false) {

is better written:

if (!eligible) {

50. Translating requirements into conditions

One of the most important programming skills is converting an English requirement into precise Boolean logic.

Example:

A customer gets free shipping if the order is at least $50.
orderTotal >= 50

Example:

A student may take the course if they completed CSC500 and have graduate standing.
completedCSC500 && graduateStanding

Example:

A person qualifies for the discount if they are younger than 18 or at least 65.
age < 18 || age >= 65

Example:

Access is allowed only when the password is correct and the account is not locked.
passwordCorrect && !accountLocked

Before writing an if statement, first make sure the condition itself correctly expresses the rule.

52. Tracing conditional code

You should be able to determine the output of code without running it.

Example:

int x = 8;
int y = 3;

if (x > 5) {
    y = y + 2;
}

if (y > 4) {
    x = x - 3;
} else {
    x = x + 3;
}

System.out.println(x);
System.out.println(y);

Trace:

Initial values:

x = 8
y = 3

First condition:

x > 5
8 > 5 → true

Therefore:

y = 5

Second condition:

y > 4
5 > 4 → true

Therefore:

x = 5

Final output:

5
5

Tracing code manually is one of the best ways to develop programming intuition.

53. Debugging conditional logic

When a conditional program behaves incorrectly, ask:

  1. What values do the variables actually contain?
  2. What condition is being evaluated?
  3. What does each comparison evaluate to?
  4. Is the correct operator being used?
  5. Should this be && or ||?
  6. Are the boundary values correct?
  7. Are conditions ordered properly?
  8. Are these supposed to be independent if statements or an if-else-if chain?
  9. Are braces placed correctly?
  10. Are strings being compared with .equals()?

Printing intermediate values can help.

Example:

System.out.println("age = " + age);
System.out.println("hasLicense = " + hasLicense);
System.out.println("condition = " + (age >= 18 && hasLicense));

This is a simple but effective debugging technique.

54. Boundary cases

Suppose admission requires:

age must be at least 18

Which operator should we use?

age > 18

or:

age >= 18

The phrase:

at least 18

means:

age >= 18

A person who is exactly 18 qualifies.

Boundary values frequently cause programming bugs.

Whenever you write a condition, test values:

  • just below the boundary,
  • exactly at the boundary,
  • just above the boundary.

For:

score >= 60

test:

59
60

55. Boundary vocabulary

56. Example program: bmi classification

import java.util.Scanner;

public class BMIClassifier {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        System.out.print("Enter weight in kilograms: ");
        double weight = input.nextDouble();

        System.out.print("Enter height in meters: ");
        double height = input.nextDouble();

        if (weight <= 0 || height <= 0) {
            System.out.println("Invalid input.");
        } else {
            double bmi = weight / (height * height);

            System.out.printf("BMI: %.1f%n", bmi);

            if (bmi < 18.5) {
                System.out.println("Underweight");
            } else if (bmi < 25.0) {
                System.out.println("Normal range");
            } else if (bmi < 30.0) {
                System.out.println("Overweight");
            } else {
                System.out.println("Obesity range");
            }
        }

        input.close();
    }
}

Important observations:

  • Invalid input is checked first.
  • The BMI is calculated only if the input is valid.
  • Categories are checked from smallest boundary upward.
  • We take advantage of what previous conditions have already established.

57. Example program: simple calculator

import java.util.Scanner;

public class Calculator {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        System.out.print("Enter first number: ");
        double x = input.nextDouble();

        System.out.print("Enter operator (+, -, *, /): ");
        String operator = input.next();

        System.out.print("Enter second number: ");
        double y = input.nextDouble();

        if (operator.equals("+")) {
            System.out.println(x + y);
        } else if (operator.equals("-")) {
            System.out.println(x - y);
        } else if (operator.equals("*")) {
            System.out.println(x * y);
        } else if (operator.equals("/")) {
            if (y != 0) {
                System.out.println(x / y);
            } else {
                System.out.println("Cannot divide by zero.");
            }
        } else {
            System.out.println("Unknown operator.");
        }

        input.close();
    }
}

This program demonstrates:

  • string comparison,
  • an if-else-if chain,
  • nested decisions,
  • input validation.

58. Example program: loan eligibility

Suppose a simplified lending system has the following rules:

A person qualifies if:

  • age is at least 18,
  • annual income is at least $30,000,
  • credit score is at least 650.
boolean eligible =
        age >= 18 &&
        income >= 30000 &&
        creditScore >= 650;

if (eligible) {
    System.out.println("Basic eligibility requirements satisfied.");
} else {
    System.out.println("Eligibility requirements not satisfied.");
}

Now suppose we want specific explanations:

if (age < 18) {
    System.out.println("Applicant must be at least 18.");
} else if (income < 30000) {
    System.out.println("Income requirement not satisfied.");
} else if (creditScore < 650) {
    System.out.println("Credit score requirement not satisfied.");
} else {
    System.out.println("Basic eligibility requirements satisfied.");
}

Both versions are valid.

Which one is better depends on what the program needs to accomplish.

59. Boolean logic is the foundation of algorithms

Conditional logic may initially look like a small syntax topic.

It is not.

Nearly every important algorithm depends on making decisions.

For example:

Searching:

if (currentValue == target) {

Sorting:

if (leftValue > rightValue) {

Binary search:

if (target < middleValue) {

Linked structures:

if (current == null) {

Trees:

if (key < node.key) {

Graph algorithms:

if (!visited[neighbor]) {

Object-oriented programs:

if (account.isActive()) {

Learning to construct and reason about conditions precisely is therefore a fundamental computer science skill.

60. Common mistakes summary

Mistake 1: using = instead of ==

Incorrect:

x = 5

when you intend comparison.

Correct:

x == 5

Mistake 2: comparing strings with ==

Incorrect:

name == "Alice"

Correct:

name.equals("Alice")

Mistake 3: using or for an inside range

Incorrect:

age >= 18 || age <= 65

Correct:

age >= 18 && age <= 65

Mistake 4: using and for an outside range

Incorrect:

age < 18 && age > 65

Correct:

age < 18 || age > 65

Mistake 5: incorrect ordering

Incorrect:

if (score >= 60) {
    ...
} else if (score >= 70) {
    ...
}

Higher thresholds should usually be tested first when using this style.

Mistake 6: missing braces

Avoid:

if (condition)
    statement1;
    statement2;

Prefer:

if (condition) {
    statement1;
    statement2;
}

Mistake 7: confusing independent decisions with alternatives

Independent:

if (...) {
}

if (...) {
}

Mutually exclusive:

if (...) {
} else if (...) {
} else {
}

63. In-class exercise: ticket pricing

A movie theater charges:

Under age 5       Free
Age 5–12          $8
Age 13–64         $12
Age 65 or older   $7

Write a Java program that asks for a customer's age and displays the ticket price.

Possible solution:

if (age < 0) {
    System.out.println("Invalid age.");
} else if (age < 5) {
    System.out.println("Free");
} else if (age <= 12) {
    System.out.println("$8");
} else if (age <= 64) {
    System.out.println("$12");
} else {
    System.out.println("$7");
}

Discussion question:

Why do we not need to write:

age >= 5 && age <= 12

for the second pricing category?

Because reaching that branch already tells us that age >= 5.

67. Mental model for conditionals

When reading an if statement, do not think:

Java somehow understands my intention.

Think mechanically.

For:

if (score >= 80 && attendance >= 75) {

Java performs approximately this reasoning:

1. Retrieve score.
2. Compare score with 80.
3. Produce true or false.
4. If necessary, retrieve attendance.
5. Compare attendance with 75.
6. Produce true or false.
7. Combine the Boolean values using AND.
8. If the final result is true, execute the block.
9. Otherwise skip the block.

Computers execute precise instructions.

They do not infer what a programmer intended to write.

68. Key takeaways

A Boolean expression evaluates to:

true

or:

false

The major comparison operators are:

==
!=
<
>
<=
>=

The major logical operators are:

&&
||
!

Use:

if

for a conditional action.

Use:

if / else

for two alternatives.

Use:

if / else if / else

for multiple mutually exclusive alternatives.

Use independent if statements when multiple conditions may all need to execute.

Use:

.equals()

rather than == to compare strings.

For ranges:

inside → &&
outside → ||

Test boundary values carefully.

Use braces consistently.

Most importantly, learn to translate requirements into precise Boolean expressions.

69. Suggested lab

Eligibility checker

Write a Java program that determines whether a student is eligible to register for a graduate course.

Ask the user for:

GPA
number of completed credits
whether prerequisite was completed
whether the student has an academic hold

The student is eligible if:

  • GPA is at least 3.0,
  • completed credits are at least 12,
  • the prerequisite has been completed,
  • and there is no academic hold.

The program should provide a useful explanation when the student is not eligible.

Example:

Enter GPA: 3.4
Enter completed credits: 15
Prerequisite completed? true
Academic hold? false

Student is eligible to register.

Another run:

Enter GPA: 2.7
Enter completed credits: 15
Prerequisite completed? true
Academic hold? false

Student is not eligible.
Reason: GPA must be at least 3.0.

Extension

Rather than stopping after the first failed requirement, display every failed requirement.

For example:

Student is not eligible.

Reasons:
- GPA must be at least 3.0.
- Prerequisite has not been completed.

This requires recognizing that the validation checks should be independent rather than one if-else-if chain.

71. Preparation for week 3

Next week we introduce loops.

Conditionals allow a program to ask:

Should this code execute?

Loops allow a program to ask:

Should this code execute again?

For example, instead of writing:

System.out.println("Hello");
System.out.println("Hello");
System.out.println("Hello");
System.out.println("Hello");
System.out.println("Hello");

we will be able to write:

for (...) {
    System.out.println("Hello");
}

Conditionals and loops together form the fundamental control structures from which most algorithms are built.
