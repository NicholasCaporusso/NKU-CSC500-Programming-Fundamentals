1. Motivation: programs are getting bigger

During the first few weeks of the course, most of our programs were relatively small.

A typical program might:

  1. read some input,
  2. perform some calculations,
  3. use a loop or conditional,
  4. print a result.

For example:

import java.util.Scanner;

public class GradeCalculator {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        System.out.print("Enter exam 1 score: ");
        double exam1 = input.nextDouble();

        System.out.print("Enter exam 2 score: ");
        double exam2 = input.nextDouble();

        System.out.print("Enter final exam score: ");
        double finalExam = input.nextDouble();

        double average =
                exam1 * 0.30 +
                exam2 * 0.30 +
                finalExam * 0.40;

        if (average >= 90) {
            System.out.println("Grade: A");
        } else if (average >= 80) {
            System.out.println("Grade: B");
        } else if (average >= 70) {
            System.out.println("Grade: C");
        } else if (average >= 60) {
            System.out.println("Grade: D");
        } else {
            System.out.println("Grade: F");
        }
    }
}

This program works.

But imagine that the program grows to 500, 5,000, or 50,000 lines.

Putting all of the logic inside main quickly becomes difficult to:

  • read,
  • understand,
  • debug,
  • test,
  • modify,
  • and reuse.

Programming therefore relies heavily on decomposition.

Program decomposition is the process of breaking a large problem into smaller, manageable pieces.

In Java, one of our primary tools for decomposition is the method.

2. What is a method?

A method is a named block of code that performs a particular task.

You have already used methods.

For example:

System.out.println("Hello");

println is a method.

Similarly:

Math.sqrt(25);

sqrt is a method.

And:

input.nextInt();

nextInt is a method.

Until now, we have mostly been calling methods written by other programmers.

This week, we begin writing our own.

3. A simple method

Consider the following program:

public class GreetingExample {

    public static void printGreeting() {
        System.out.println("Welcome to CSC500!");
        System.out.println("Let's learn Java.");
    }

    public static void main(String[] args) {
        printGreeting();
    }
}

The method is:

public static void printGreeting() {
    System.out.println("Welcome to CSC500!");
    System.out.println("Let's learn Java.");
}

The method is called using:

printGreeting();

When Java encounters the method call, it temporarily transfers execution to the method.

After the method finishes, execution returns to the point immediately following the method call.

4. Anatomy of a method

Consider:

public static void printGreeting() {
    System.out.println("Hello!");
}

The structure is:

public static void methodName(parameters) {
    statements
}

For now, we will concentrate on four pieces.

Method name

printGreeting

The method name identifies the method.

Java method names conventionally use camelCase.

Examples:

calculateAverage
printMenu
findMaximum
convertTemperature
isValidPassword

Good method names describe what the method does.

Avoid vague names such as:

doStuff
thing
process
method1

5. void methods

Some methods perform an action but do not produce a value.

These are called void methods.

Example:

public static void printSeparator() {
    System.out.println("--------------------");
}

The word:

void

means that the method does not return a value.

We can call it several times:

public static void main(String[] args) {
    printSeparator();
    System.out.println("CSC500");
    printSeparator();
}

Output:

--------------------
CSC500
--------------------

Methods allow us to avoid repeating code.

6. Why methods matter

Methods provide several important benefits.

6.1 readability

Compare:

double subtotal = price * quantity;
double tax = subtotal * 0.06;
double total = subtotal + tax;
System.out.printf("%.2f%n", total);

with:

double total = calculateTotal(price, quantity);
printTotal(total);

The second version expresses the intention of the program more clearly.

6.2 reuse

Instead of writing the same calculation several times, we can write it once.

public static double calculateTax(double amount) {
    return amount * 0.06;
}

Then:

double tax1 = calculateTax(100);
double tax2 = calculateTax(250);
double tax3 = calculateTax(37.50);

6.3 testing

It is easier to test a small method independently than to test an entire large program.

For example:

public static int square(int number) {
    return number * number;
}

We can test:

System.out.println(square(3));   // should be 9
System.out.println(square(0));   // should be 0
System.out.println(square(-4));  // should be 16

6.4 debugging

If a program consists of well-designed methods, we can often identify which method contains an error.

Instead of asking:

"Where is the bug in these 500 lines?"

we can ask:

"Is the bug in readInput, calculateAverage, or determineGrade?"

7. Parameters

Methods often need information from the caller.

That information is passed using parameters.

Consider:

public static void greet(String name) {
    System.out.println("Hello, " + name + "!");
}

Here:

String name

is a parameter.

We can call the method:

greet("Maria");

Output:

Hello, Maria!

Or:

greet("James");

Output:

Hello, James!

The same method can operate on different data.

8. Parameters vs. arguments

The words parameter and argument are closely related but have different meanings.

In the method definition:

public static void greet(String name)

name is a parameter.

In the method call:

greet("Maria");

"Maria" is an argument.

A useful distinction is:

A parameter is a variable in the method definition. An argument is the value supplied when the method is called.

9. Multiple parameters

Methods may have multiple parameters.

Example:

public static void printRectangle(int width, int height) {
    System.out.println("Width: " + width);
    System.out.println("Height: " + height);
}

Call:

printRectangle(10, 5);

The values correspond by position.

width  receives 10
height receives 5

Order matters.

Consider:

public static void printPerson(String name, int age) {
    System.out.println(name + " is " + age + " years old.");
}

Correct:

printPerson("Aisha", 28);

Incorrect:

printPerson(28, "Aisha");

The types and positions must match the method definition.

10. Methods that return values

Many methods calculate something and return the result.

Example:

public static int square(int number) {
    return number * number;
}

The method's return type is:

int

That means the method promises to produce an integer.

Calling:

square(5)

produces the value:

25

We can store that value:

int result = square(5);

Or print it:

System.out.println(square(5));

Or use it in another expression:

int total = square(3) + square(4);

which becomes:

9 + 16

and therefore:

25

11. Return type

Every method declares what kind of value it returns.

Examples:

public static int getAge()

returns an int.

public static double calculateAverage()

returns a double.

public static boolean isValid()

returns a boolean.

public static String getName()

returns a String.

A method that returns nothing uses:

void

12. The return statement

The return statement ends the method and sends a value back to the caller.

Example:

public static double calculateArea(double radius) {
    double area = Math.PI * radius * radius;
    return area;
}

Calling:

double result = calculateArea(5);

causes the following sequence:

radius = 5
area = π × 5 × 5
return area

The returned result is assigned to:

result

13. Returning expressions directly

A temporary variable is not always necessary.

Instead of:

public static double calculateArea(double radius) {
    double area = Math.PI * radius * radius;
    return area;
}

we can write:

public static double calculateArea(double radius) {
    return Math.PI * radius * radius;
}

Both are correct.

Choose whichever is clearer.

14. Example: maximum of two numbers

public static int max(int a, int b) {
    if (a > b) {
        return a;
    } else {
        return b;
    }
}

Call:

int larger = max(12, 7);

Result:

12

We can also write:

public static int max(int a, int b) {
    if (a > b) {
        return a;
    }

    return b;
}

Once Java executes a return, the method ends.

15. Boolean methods

Methods returning boolean are especially useful.

Example:

public static boolean isEven(int number) {
    return number % 2 == 0;
}

Usage:

if (isEven(10)) {
    System.out.println("The number is even.");
}

Boolean methods often have names beginning with words such as:

is
has
can
contains
should

Examples:

isValidAge()
hasPermission()
canRegister()
containsValue()

These names help make code read almost like English.

16. Example: eligibility method

Suppose a student may register for a graduate course if the student:

  • has completed CSC500, and
  • has a GPA of at least 3.0.

We could write:

public static boolean canRegister(boolean completedCSC500,
                                  double gpa) {
    return completedCSC500 && gpa >= 3.0;
}

Then:

if (canRegister(true, 3.4)) {
    System.out.println("Registration permitted.");
}

Notice how the method name communicates the meaning of the condition.

17. Methods calling other methods

Methods can call other methods.

Example:

public static double calculateSubtotal(double price, int quantity) {
    return price * quantity;
}

public static double calculateTax(double subtotal) {
    return subtotal * 0.06;
}

public static double calculateTotal(double price, int quantity) {
    double subtotal = calculateSubtotal(price, quantity);
    double tax = calculateTax(subtotal);

    return subtotal + tax;
}

This is one of the most important ideas in software development.

Complex operations can be constructed from simpler operations.

18. Program decomposition

Suppose we are asked to write a program that:

  1. reads three exam scores,
  2. calculates their average,
  3. determines the letter grade,
  4. prints the result.

A beginning programmer might put everything inside main.

Instead, we can identify smaller tasks.

main
 |
 +-- readScore
 |
 +-- calculateAverage
 |
 +-- determineGrade
 |
 +-- printResult

Now each method performs one focused task.

19. Example of decomposition

import java.util.Scanner;

public class GradeProgram {

    public static double readScore(Scanner input,
                                   String prompt) {
        System.out.print(prompt);
        return input.nextDouble();
    }

    public static double calculateAverage(
            double score1,
            double score2,
            double score3) {

        return (score1 + score2 + score3) / 3.0;
    }

    public static char determineGrade(double average) {
        if (average >= 90) {
            return 'A';
        } else if (average >= 80) {
            return 'B';
        } else if (average >= 70) {
            return 'C';
        } else if (average >= 60) {
            return 'D';
        } else {
            return 'F';
        }
    }

    public static void printResult(double average,
                                   char grade) {
        System.out.printf("Average: %.2f%n", average);
        System.out.println("Grade: " + grade);
    }

    public static void main(String[] args) {

        Scanner input = new Scanner(System.in);

        double exam1 =
                readScore(input, "Enter exam 1: ");

        double exam2 =
                readScore(input, "Enter exam 2: ");

        double exam3 =
                readScore(input, "Enter exam 3: ");

        double average =
                calculateAverage(exam1, exam2, exam3);

        char grade =
                determineGrade(average);

        printResult(average, grade);
    }
}

Notice that main now describes the overall algorithm.

It is almost readable as:

read the scores
calculate the average
determine the grade
print the result

This is good program design.

20. The role of main

At this stage of the course, students often think:

Everything happens inside main.

A better mental model is:

main coordinates the program.

Ideally, main should often describe the high-level workflow while other methods perform the details.

For example:

public static void main(String[] args) {
    displayWelcomeMessage();
    getUserInput();
    performCalculations();
    displayResults();
}

The exact design depends on the application, but large blocks of unrelated logic inside main are usually a sign that decomposition would help.

21. Variable scope

A variable is not necessarily accessible everywhere in a program.

The region in which a variable exists is called its scope.

Consider:

public static void printNumber() {
    int number = 10;

    System.out.println(number);
}

The variable:

number

exists only inside printNumber.

This would not work:

public static void main(String[] args) {
    printNumber();

    System.out.println(number);
}

Java would produce a compilation error because number does not exist inside main.

22. Local variables

Variables declared inside a method are called local variables.

Example:

public static double calculateArea(double radius) {
    double area = Math.PI * radius * radius;
    return area;
}

Both:

radius

and:

area

are local to this particular invocation of calculateArea.

Other methods cannot directly access them.

23. Different methods can use the same variable name

Because local variables belong to different scopes, this is legal:

public static void methodA() {
    int x = 10;
    System.out.println(x);
}

public static void methodB() {
    int x = 20;
    System.out.println(x);
}

The two variables named x are completely separate variables.

Calling:

methodA();
methodB();

prints:

10
20

24. Parameters are local variables

Parameters behave like local variables.

Consider:

public static int square(int number) {
    return number * number;
}

The parameter:

number

exists only during that invocation of square.

Consider:

square(5);
square(10);

Conceptually, Java creates a different number for each call.

First call:

number = 5

Second call:

number = 10

25. Java passes primitive values to methods

Consider:

public static void changeNumber(int number) {
    number = 100;
}

Now:

public static void main(String[] args) {
    int x = 5;

    changeNumber(x);

    System.out.println(x);
}

What prints?

5

Not:

100

Why?

The method receives a copy of the value stored in x.

Conceptually:

main:

x = 5

          copy
           |
           v

changeNumber:

number = 5

Then:

number = 100;

changes the local variable number.

It does not change x.

We will revisit Java's parameter passing more deeply when we study objects and references.

26. Execution flow

Consider:

public static void methodA() {
    System.out.println("A1");
    methodB();
    System.out.println("A2");
}

public static void methodB() {
    System.out.println("B");
}

public static void main(String[] args) {
    System.out.println("Start");
    methodA();
    System.out.println("End");
}

What is printed?

Trace carefully.

First:

Start

Then methodA begins:

A1

Then methodA calls methodB:

B

methodB finishes.

Execution returns to methodA:

A2

methodA finishes.

Execution returns to main:

End

Complete output:

Start
A1
B
A2
End

27. The call stack

Java must remember where to return after a method finishes.

It does this using a structure called the call stack.

Consider:

main calls methodA
methodA calls methodB
methodB calls methodC

At the deepest point, we can visualize the stack as:

+-----------+
| methodC   |
+-----------+
| methodB   |
+-----------+
| methodA   |
+-----------+
| main      |
+-----------+

When methodC finishes:

+-----------+
| methodB   |
+-----------+
| methodA   |
+-----------+
| main      |
+-----------+

Then methodB finishes:

+-----------+
| methodA   |
+-----------+
| main      |
+-----------+

Eventually execution returns to main.

The stack becomes especially important when we study recursion later in the course.

28. Method call tracing example

Consider:

public static int doubleNumber(int x) {
    return x * 2;
}

public static int addFive(int x) {
    return x + 5;
}

public static void main(String[] args) {
    int result = addFive(doubleNumber(4));

    System.out.println(result);
}

Evaluate from the inside outward.

First:

doubleNumber(4)

returns:

8

The expression becomes:

addFive(8)

which returns:

13

Therefore:

result = 13;

29. Designing good methods

A method should usually perform one clear conceptual task.

Good examples:

calculateAverage()
findMaximum()
printMenu()
readScore()
isValidPassword()
convertMilesToKilometers()

Less desirable:

readInputCalculateAverageDetermineGradeAndPrintResult()

That method is doing too many unrelated tasks.

A useful principle is:

One method, one responsibility.

This principle becomes increasingly important as programs become larger.

30. How large should a method be?

There is no universal maximum number of lines.

Instead, ask:

Does the method have one clear purpose?

If yes, the size may be appropriate.

If you find yourself describing the method as:

"This method reads data, calculates totals, checks eligibility, prints the results, and saves a file..."

the method probably has too many responsibilities.

Another useful clue is comments such as:

// read data

...

// calculate totals

...

// determine grade

...

// print result

Each comment may indicate an opportunity to create a separate method.

31. Top-down design

One useful design strategy is called top-down design.

Start with the high-level problem.

Suppose we need to create an ATM simulation.

At the highest level:

runATM

Break that into:

displayMenu
readChoice
processChoice

Then processChoice may break into:

deposit
withdraw
checkBalance

The hierarchy might look like:

main
 |
 +-- displayMenu
 |
 +-- readChoice
 |
 +-- processChoice
       |
       +-- deposit
       |
       +-- withdraw
       |
       +-- checkBalance

Rather than solving the entire problem at once, we repeatedly divide it into smaller problems.

32. Example: temperature conversion

Problem:

Create a program that converts Fahrenheit temperatures to Celsius.

Formula:

C = (F - 32) × 5/9

We can separate calculation from user interaction.

public static double fahrenheitToCelsius(double fahrenheit) {
    return (fahrenheit - 32) * 5.0 / 9.0;
}

Then:

public static void main(String[] args) {
    Scanner input = new Scanner(System.in);

    System.out.print("Enter temperature in Fahrenheit: ");
    double fahrenheit = input.nextDouble();

    double celsius =
            fahrenheitToCelsius(fahrenheit);

    System.out.printf("%.2f F = %.2f C%n",
                      fahrenheit,
                      celsius);
}

This separation provides an important benefit:

The conversion method does not know anything about keyboards, scanners, or printing.

It simply performs a calculation.

That makes the method easier to reuse and test.

33. Pure calculation methods

When possible, calculation methods should receive the information they need as parameters and return their result.

Prefer:

public static double calculateBMI(double weight,
                                  double height) {
    return weight / (height * height);
}

instead of having the method directly ask the user for input.

Why?

Because the first version can be reused in:

  • a console application,
  • a web application,
  • a mobile application,
  • automated tests,
  • another Java program.

The calculation itself is independent of how input is collected.

This separation is an early example of good software design.

34. Example: input validation method

We can move validation logic into its own method.

public static boolean isValidScore(double score) {
    return score >= 0 && score <= 100;
}

Then:

double score = input.nextDouble();

if (isValidScore(score)) {
    System.out.println("Valid score.");
} else {
    System.out.println("Invalid score.");
}

This is more readable than repeatedly writing:

score >= 0 && score <= 100

throughout the program.

35. Method signatures

Consider:

public static double calculateArea(double radius)

The method has:

  • a name: calculateArea
  • a parameter list: (double radius)
  • a return type: double

Methods are distinguished in part by their names and parameter types.

For example, Java can support:

public static int max(int a, int b)

and:

public static double max(double a, double b)

This concept is called method overloading.

We will only use it lightly for now, but students should recognize that methods may share a name if their parameter lists differ.

36. Common error: forgetting to return a value

Incorrect:

public static int square(int number) {
    int result = number * number;
}

Java expects the method to return an int.

The method promises:

int

but never returns one.

Correct:

public static int square(int number) {
    int result = number * number;
    return result;
}

37. Common error: returning the wrong type

Incorrect:

public static int getAverage(int a, int b) {
    return "hello";
}

The method promises an:

int

but attempts to return a:

String

The returned value must be compatible with the declared return type.

38. Common error: using a void method as a value

Suppose:

public static void printHello() {
    System.out.println("Hello");
}

This is incorrect:

String x = printHello();

printHello does not produce a value.

Its return type is:

void

39. Common error: printing instead of returning

Beginning programmers frequently confuse:

System.out.println(...)

with:

return

These are very different operations.

Consider:

public static void square(int number) {
    System.out.println(number * number);
}

This displays the square, but the caller cannot use the result.

For example, we cannot meaningfully write:

int result = square(5);

Instead:

public static int square(int number) {
    return number * number;
}

Now the caller decides what to do with the value.

int result = square(5);
System.out.println(result);

As a design principle:

If a method computes a value that other code may need, returning the value is usually more flexible than printing it directly.

40. Common error: incorrect argument count

Definition:

public static int add(int a, int b) {
    return a + b;
}

Correct:

add(5, 7);

Incorrect:

add(5);

Incorrect:

add(5, 7, 10);

The number of arguments must match the parameters.

41. Common error: incorrect argument types

Definition:

public static double calculateTax(double amount) {
    return amount * 0.06;
}

This is reasonable:

calculateTax(100.0);

This is not:

calculateTax("one hundred");

Java checks parameter types at compile time.

This is one benefit of a statically typed language.

42. Common error: scope confusion

Incorrect:

public static void calculate() {
    int result = 25;
}

public static void main(String[] args) {
    calculate();

    System.out.println(result);
}

result belongs to calculate, not to main.

One solution is to return the value.

public static int calculate() {
    return 25;
}

public static void main(String[] args) {
    int result = calculate();

    System.out.println(result);
}

43. Worked example: loan payment

Suppose we want to calculate a simple monthly payment.

For this example, assume:

monthly payment = loan amount / number of months

We could write:

public static double calculateMonthlyPayment(
        double loanAmount,
        int months) {

    return loanAmount / months;
}

Then:

public static void displayPayment(double payment) {
    System.out.printf("Monthly payment: $%.2f%n",
                      payment);
}

And:

public static void main(String[] args) {

    Scanner input = new Scanner(System.in);

    System.out.print("Loan amount: ");
    double amount = input.nextDouble();

    System.out.print("Number of months: ");
    int months = input.nextInt();

    double payment =
            calculateMonthlyPayment(amount, months);

    displayPayment(payment);
}

Notice the separation between:

input
calculation
output

This pattern appears constantly in software.

44. Worked example: number analysis

Suppose a program reads an integer and reports whether it is:

  • positive, negative, or zero,
  • and even or odd.

We could create:

public static boolean isPositive(int number) {
    return number > 0;
}

public static boolean isNegative(int number) {
    return number < 0;
}

public static boolean isEven(int number) {
    return number % 2 == 0;
}

Then:

public static void describeNumber(int number) {

    if (isPositive(number)) {
        System.out.println("Positive");
    } else if (isNegative(number)) {
        System.out.println("Negative");
    } else {
        System.out.println("Zero");
    }

    if (isEven(number)) {
        System.out.println("Even");
    } else {
        System.out.println("Odd");
    }
}

This example demonstrates that small methods can communicate concepts clearly.

45. Methods and loops

Methods can contain loops.

Example:

public static int sumFromOneTo(int n) {

    int sum = 0;

    for (int i = 1; i <= n; i++) {
        sum += i;
    }

    return sum;
}

Call:

int result = sumFromOneTo(5);

The method computes:

1 + 2 + 3 + 4 + 5

and returns:

15

46. Methods and conditionals

Methods can contain conditionals.

Example:

public static double absoluteValue(double number) {

    if (number < 0) {
        return -number;
    }

    return number;
}

Methods do not replace loops or conditionals.

Instead, methods allow us to organize programs containing those structures.

47. Nested method calls

Consider:

public static int square(int x) {
    return x * x;
}

public static int sumOfSquares(int a, int b) {
    return square(a) + square(b);
}

Calling:

sumOfSquares(3, 4)

becomes:

square(3) + square(4)

then:

9 + 16

then:

25

This idea-building larger abstractions from smaller ones-is fundamental to computer science.

48. Abstraction

When we call:

Math.sqrt(25)

we do not need to understand exactly how Java computes the square root.

We only need to know:

input: a number
output: its square root

This is an example of abstraction.

A method allows a programmer to hide implementation details behind a meaningful name.

For example:

double tax = calculateTax(amount);

The caller does not need to know the exact formula used inside calculateTax.

The method provides a useful abstraction.

This principle becomes central when we study objects and classes.

49. Method contracts

It is helpful to think of a method as having a contract.

For example:

public static double calculateArea(double radius)

The caller provides:

a radius

The method provides:

an area

We can describe this formally.

Method

calculateArea

Input

radius: double

Output

area: double

Assumption

radius >= 0

Behavior

returns π × radius²

Thinking about methods this way will become important later when designing larger software systems.

50. Choosing parameters

A method should receive the information necessary to perform its task.

Suppose:

public static double calculateTotal(
        double price,
        int quantity,
        double taxRate)

This is flexible because the required information is explicit.

Compare that with relying on hidden values elsewhere in the program.

Explicit parameters often make a method easier to:

  • understand,
  • test,
  • reuse,
  • and modify.

51. Avoid unnecessary parameters

Do not pass information the method does not need.

Suppose a method only calculates area:

public static double calculateRectangleArea(
        double width,
        double height) {

    return width * height;
}

There is no reason to also pass:

userName
programVersion
menuChoice

A clean method interface contains only relevant information.

52. Example of poor decomposition

Consider:

public static void doEverything() {
    Scanner input = new Scanner(System.in);

    System.out.print("Enter price: ");
    double price = input.nextDouble();

    System.out.print("Enter quantity: ");
    int quantity = input.nextInt();

    double subtotal = price * quantity;
    double tax = subtotal * 0.06;
    double total = subtotal + tax;

    if (total > 100) {
        total *= 0.95;
    }

    System.out.println(total);
}

This works, but several responsibilities have been combined.

Possible decomposition:

readPrice
readQuantity
calculateSubtotal
calculateTax
applyDiscount
printReceipt

The point is not to create methods mechanically.

The goal is to identify meaningful responsibilities.

53. Too many tiny methods

Decomposition can also go too far.

For example:

public static int addOne(int x) {
    return x + 1;
}

public static int addTwo(int x) {
    return addOne(addOne(x));
}

This may be useful in a particular context, but creating a separate method for every trivial operation can make code harder rather than easier to understand.

Good decomposition requires judgment.

Ask:

Does naming this operation make the program easier to understand, test, or reuse?

54. Incremental development

Methods work well with incremental development.

Instead of writing an entire program and testing at the end:

  1. write one method,
  2. test it,
  3. verify that it works,
  4. write another method,
  5. test again,
  6. gradually assemble the complete program.

For example, if implementing:

calculateAverage
determineGrade
printResult

first verify:

System.out.println(calculateAverage(90, 80, 70));

Then test:

System.out.println(determineGrade(95));
System.out.println(determineGrade(85));
System.out.println(determineGrade(75));

Only after those methods work should we integrate them into the complete application.

This greatly reduces debugging difficulty.

55. Debugging method-based programs

When debugging, ask:

Did the method receive the correct inputs?

Print temporary diagnostic information if necessary:

System.out.println("DEBUG: score = " + score);

Did the method return the expected result?

double average = calculateAverage(70, 80, 90);
System.out.println("DEBUG average = " + average);

Is the error inside the method or in the caller?

Test methods independently.

using:

Write a method that returns whether an integer represents a valid month.

public static boolean isValidMonth(int month)

63. In-class exercise: letter grade

Write:

public static char getLetterGrade(double score)

Assume:

90–100 A
80–89  B
70–79  C
60–69  D
below 60 F

Solution:

public static char getLetterGrade(double score) {

    if (score >= 90) {
        return 'A';
    } else if (score >= 80) {
        return 'B';
    } else if (score >= 70) {
        return 'C';
    } else if (score >= 60) {
        return 'D';
    }

    return 'F';

64. In-class exercise: sum of integers

Write:

public static int sumTo(int n)

that returns:

1 + 2 + ... + n

Example:

sumTo(4)

returns:

10

Solution:

public static int sumTo(int n) {

    int sum = 0;

    for (int i = 1; i <= n; i++) {
        sum += i;
    }

    return sum;
}

65. Larger decomposition exercise

Design a program that calculates the cost of movie tickets.

Rules:

Child ticket:   $8
Adult ticket:   $12
Senior ticket:  $9

Additionally, purchases of five or more tickets receive a 10% discount.

Do not begin by writing code.

First identify possible methods.

Possible design:

getTicketPrice
calculateSubtotal
applyDiscount
printReceipt

One possible method:

public static double getTicketPrice(int age) {

    if (age < 13) {
        return 8.0;
    } else if (age >= 65) {
        return 9.0;
    }

    return 12.0;
}

Another:

public static double applyDiscount(
        double subtotal,
        int quantity) {

    if (quantity >= 5) {
        return subtotal * 0.90;
    }

    return subtotal;
}

The important skill is not merely coding the methods.

The important skill is recognizing how a large problem can be divided into smaller responsibilities.

66. Method documentation

Methods should be understandable from their names, but documentation can provide additional information.

For example:

/**
 * Calculates the area of a circle.
 *
 * @param radius the radius of the circle
 * @return the area of the circle
 */
public static double calculateCircleArea(double radius) {
    return Math.PI * radius * radius;
}

This style is called Javadoc.

You do not need extensive documentation for every trivial method, but public methods in larger programs should have understandable contracts.

67. Naming conventions

Method names should generally be verbs or verb phrases.

Good:

calculateAverage
findMaximum
printMenu
readInput
validateScore

Boolean methods often work well as questions:

isEven
isValid
hasPermission
canRegister

Avoid names like:

stuff
abc
function1
work
data

Code is read much more often than it is written.

Names matter.

68. A useful design question

Whenever you encounter a piece of code, ask:

What does this code mean conceptually?

For example:

if (age >= 18 && hasID && !accountSuspended)

could become:

if (canAccessAccount(age, hasID, accountSuspended))

Methods can give names to ideas.

That is one of their greatest benefits.

69. Methods as building blocks

Think of programming as constructing increasingly powerful building blocks.

Java provides:

Math.sqrt
System.out.println
String.length

We create:

calculateAverage
isValidScore
determineGrade

Later, we will construct entire classes and objects that group related data and methods together.

Methods are therefore an important bridge from basic programming toward object-oriented programming.

70. Key distinctions

Make sure you understand these pairs.

Method definition vs. method call

Definition:

public static int square(int x) {
    return x * x;
}

Call:

square(5);

Parameter vs. argument

Parameter:

int x

Argument:

5

return vs. println

return:

return result;

sends data back to the caller.

println:

System.out.println(result);

sends text to the console.

Local variable vs. variable in another method

Variables inside different methods belong to different scopes.

Calculation vs. user interaction

Whenever practical, separate:

reading input
performing calculations
printing output

71. Week 4 programming style guidelines

For CSC500 programs from this point forward:

  1. Avoid placing the entire program in main.
  2. Use methods for meaningful subtasks.
  3. Give methods descriptive names.
  4. Prefer calculation methods that return values.
  5. Keep input/output separate from calculations when reasonable.
  6. Avoid unnecessary global state.
  7. Keep variables in the smallest reasonable scope.
  8. Test methods independently.
  9. Do not duplicate code that can reasonably be placed in a method.
  10. Make main communicate the overall structure of the program.

72. End-of-week example

Here is a complete program demonstrating several concepts from this week.

import java.util.Scanner;

public class FitnessCalculator {

    public static double calculateBMI(
            double weightKg,
            double heightMeters) {

        return weightKg /
                (heightMeters * heightMeters);
    }

    public static String classifyBMI(double bmi) {

        if (bmi < 18.5) {
            return "Underweight";
        } else if (bmi < 25) {
            return "Normal";
        } else if (bmi < 30) {
            return "Overweight";
        } else {
            return "Obese";
        }
    }

    public static void displayResult(
            double bmi,
            String category) {

        System.out.printf("BMI: %.1f%n", bmi);
        System.out.println("Category: " + category);
    }

    public static void main(String[] args) {

        Scanner input = new Scanner(System.in);

        System.out.print("Weight in kilograms: ");
        double weight = input.nextDouble();

        System.out.print("Height in meters: ");
        double height = input.nextDouble();

        double bmi =
                calculateBMI(weight, height);

        String category =
                classifyBMI(bmi);

        displayResult(bmi, category);
    }
}

Notice how the program has three conceptual operations:

calculate BMI
classify BMI
display result

Each operation is represented by a method.

main coordinates those operations.

73. Concept check questions

Students should be able to answer these questions by the end of the week.

1. What is a method?

A named block of code designed to perform a particular task.

2. Why do programmers use methods?

To improve decomposition, readability, reuse, testing, abstraction, and maintainability.

3. What is a parameter?

A variable declared in a method definition that receives information from the caller.

4. What is an argument?

A value supplied when calling a method.

5. What does void mean?

The method does not return a value.

6. What does return do?

It ends the method and sends a value back to the caller.

7. What is scope?

The part of a program in which a variable can be accessed.

8. What is a local variable?

A variable declared inside a method or block whose scope is limited to that region.

9. What happens when one method calls another?

Execution transfers to the called method. When it finishes, execution returns to the caller.

10. What is program decomposition?

Breaking a complex problem into smaller, manageable subproblems.

74. Exit ticket

Without running the program, determine its output.

public static int f(int x) {
    return x * 2;
}

public static int g(int x) {
    return f(x) + 1;
}

public static void main(String[] args) {

    int a = 3;
    int b = g(a);

    System.out.println(a);
    System.out.println(b);
}

Answer:

3
7

Reasoning:

g(3)
→ f(3) + 1
→ 6 + 1
→ 7

The variable a remains 3.

75. Week 4 summary

This week introduced one of the most important transitions in programming.

Until now, we mainly focused on individual statements:

variables
conditionals
loops

Methods allow us to organize those statements into larger conceptual units.

The central ideas are:

method = named computation

parameters = information going into a method

return value = information coming out of a method

scope = where a variable exists

decomposition = dividing a large problem into smaller problems

The most important habit to develop is this:

Do not think of a program as one long sequence of statements.

Instead, think of a program as a collection of smaller operations that cooperate to solve a larger problem.

That way of thinking prepares us for the next major topic in Java:

classes and objects.
